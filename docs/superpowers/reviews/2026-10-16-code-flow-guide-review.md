# 코드 동작 흐름 안내 화면 설계 리뷰 (2026-10-16)

대상은 `docs/superpowers/specs/2026-10-14-code-flow-guide-design.md` 의 이번 차수 변경분이다. 변경분은 사용자 설명서, 설명서의 0번 화면 둘러보기, 설명서와 원본 관리, 화면 항목 목록과 설명 대조, 절차 표와 JSON 형식 표와 결과물 위치 표의 새 줄이다. 메인 세션이 훅 밖에서 이 스킬을 열었고, 파일이 `docs/superpowers/specs` 아래에 있어 spec 으로 판정했다.

렌즈 원본은 같은 이름의 폴더에 있다(`lens-grounding-1.json`, `lens-consistency-1.json`, `lens-adversarial-1.json`, `lens-fit-1.json`). 렌즈를 한 번씩만 실행했다.

## 선행연구 렌즈

메인 세션은 선행연구 렌즈를 제안하지 않았다. 이번 변경은 시안으로 이미 해 본 일(설명서 화면, 코드에서 항목 뜻 추적)을 스킬 절차로 옮기는 정리이고, 되는지 자체가 미지수인 일이 아니라고 판정했다.

## 합친 지적

근거를 연 확인: grounding 의 블라인드 분기 지적은 메인 세션이 `useRiskGrade.ts:78-81` 을 열어 확인했다. 나머지 지적은 렌즈가 인용한 spec 줄이 실제 문장과 같은지만 확인했다.

| 지적 | 잡은 렌즈 |
|---|---|
| 산출물 공백: `manual_template.html` 과 항목 서브에이전트 지침 파일이 위치 절 파일 표에 없고, `render.py` 가 출력 두 개를 내는 방식이 정해지지 않았다 | consistency(둘) |
| 항목 `no` 를 필수로 두었는데 위치를 못 찾은 항목은 번호 없이 남기고, 번호를 누가 매기는지 없다. `target` 이 JSON 형식에 없다 | consistency, adversarial, grounding(notes) |
| 둘러보기 화면의 캡처 실패 표기가 장면(`screen.unavailable`)과 다르고 모호하다 | consistency |
| `areas` 원본이 항목 목록 전체라 표시 규칙은 대조 전부터 늘 0번에서 설명된 것이 되고, 개발자용은 여전히 표시 규칙을 설명하지 않는다 | consistency, adversarial |
| 「빠짐없이 나열」과 「근거 없는 항목은 내지 않음」이 충돌해 뜻을 못 정한 요소가 목록에서 사라진다 | consistency, adversarial |
| 알아 둘 점의 「눈에 보이는 상태 묘사는 싣지 않음」과 대조의 「표시 규칙을 핵심으로도 싣음」의 경계가 없고, 대조에서 넣은 핵심은 검토를 거치지 않는다 | consistency |
| 대조의 「장면 추가」에 필요한 동작 · 캡처 계획 · 가짜 데이터를 누가 만드는지 없다 | consistency, adversarial |
| 0번에 넣을 「주요 화면」의 기준과 그 화면에 닿는 동작 · 가짜 데이터의 출처가 없다. 표시 규칙은 가짜 데이터가 조건을 만족해야 그려진다 | consistency, adversarial(둘) |
| 첫 문단 · 목적 · 플러그인 설명이 「HTML 한 장」 · 바이브 코더 독자만 말한다 | consistency |
| 「안내 화면」이 두 결과물을 함께 가리키는지 절마다 다르고, 옛 절의 결함 표시 · 참고 접기가 설명서 예외를 적지 않는다 | consistency |
| 요약을 사용자 시각으로 쓰는 규칙과 결함을 사용자 시각 알아 둘 점으로 옮기는 규칙이 「화면과 문장 규칙」 표와 지침 파일 배정에 없다 | consistency |
| 제외 범위 · 템플릿 변경 절의 「개발자용 단계 화면」이 새 「개발자용 안내 화면」과 이름이 겹친다 | consistency, fit |
| 결과 보고에 `manual.html` 경로와 둘러보기 실패가 없다 | consistency |
| 용어 드리프트: 0번 묶음의 이름, 항목 · 요소, 버튼 · 단추, 템플릿 · 화면 틀, `screens` 와 `screens/` 폴더 | consistency, fit |
| 「RM 시험 결과물처럼 순서가 틀리고 핵심이 빠진다」가 같은 문서의 다른 원인(분석을 맡긴 순서)과 부딪힌다 | grounding |
| 「조회에 실패해도 G」는 일반 펀드만 맞고, 블라인드 펀드는 현재 종합등급으로 보인다 | grounding |
| 「빠짐없이」의 판정 기준과 반복 요소를 세는 단위가 없다 | adversarial |
| 위치 측정이 같은 글자가 여럿일 때 엉뚱한 요소를 성공으로 돌려준다 | adversarial |
| 번호 겹침 검사가 걸렸을 때의 처리가 없고, 포함 관계 항목은 본래 겹친다 | adversarial |
| 화면 코드가 다른 레포에 있는 경우(RM)의 레포 기록과 근거 경로 기준이 없다 | adversarial |
| `coverage.json` 은 읽는 곳이 없고 같은 정보가 답에 적힌다 | adversarial, fit |
| 항목 `evidence` 를 렌더가 쓰지 않는데 `flow.json` 필수다 | adversarial |
| 항목 단계가 기능 분석과 독립인데 순서대로 놓였고, 추적을 멈출 조건이 「닿은 데까지」뿐이다 | adversarial |
| 항목 뜻에 근거 줄과 문장을 맞춰 보는 대조가 없다 | adversarial |
| 결론이 절 첫 문장에 오지 않음, 네 문장 넘는 단락, 주체 생략, 관형절 중간 삽입, 쉼표 둘, 비유(무게 · 입구 · 얇은), 표 머리 「바꾸는 것」, 수사로 대상 가리키기, JSON 표 셀 말끝 | fit |
| 기준값(6초, 0.5~2배, 3 : 2)과 「독자는 접힌 내용을 열지 않기 쉽다」, 원본 관리 결정에 출처 · 날짜가 없다. 미래 별도 스킬 규칙은 요청 범위를 넘는다 | fit |

## 커버리지 공백

렌즈 넷이 모두 결과를 돌려주었다. 선행연구 대조는 실행하지 않았다. grounding 은 시안의 과거 문구에 관한 주장 두 개(추정 문구, 칸 이름만 골랐을 때의 누락)를 출처로 확인하지 못했다.
