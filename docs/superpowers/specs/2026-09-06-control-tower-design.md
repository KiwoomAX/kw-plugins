# 사내 컨트롤 타워 설계 (2026-09-06)

설치기가 PC를 세우고 플러그인 하나만 깐다. 그 하나가 나머지 전부를 끌고 온다.

**셋째 판이다.** 두 판이 검진에서 무너졌고 **둘 다 감지 장치에서 무너졌다.** 첫 판은 재는 범위가 좁았고, 둘째 판은 재는 것과 고치는 것이 어긋났다. 기록은 `docs/superpowers/reviews/`의 두 회차에 있다.

## 목적

사내 플러그인을 앞으로 여럿 만든다. 지금 구조에서는 새 플러그인이 하나 생길 때마다 `kw_install`의 `$script:Plugins` 표를 고치고 모든 PC에서 설치기를 다시 돌려야 한다. 목록이 설치기 안에 있기 때문이다.

목록을 설치기 밖으로 꺼내 한 곳에 두고 각 PC가 그 한 곳을 바라보게 만든다. 새 플러그인을 더하는 일이 커밋 하나가 되고 각 PC는 다음 세션에 그것을 듣는다. 옮기는 것은 플러그인 목록만이 아니라 파이썬 라이브러리와 `CLAUDE.md`의 개인 문안과 사내 스킬처럼 **목록이 자라는 것 전부**다.

## 감지의 규칙

두 판이 같은 자리에서 무너졌으므로 감지를 먼저 정하고 나머지를 거기 맞춘다. 규칙은 셋이다.

- **훅이 재는 것은 맞춤이 고칠 수 있는 것뿐이다.** 고칠 수 없는 것을 재면 사용자가 끌 수 없는 소음이 되고, 소음은 옆의 진짜 알림까지 함께 묻는다.
- **훅이 읽는 파일은 맞춤이 쓰는 파일과 같다.** 다르면 맞춤이 성공해도 경보가 안 꺼진다. 둘째 판이 `installed_plugins.json`으로 재고 `settings.json`으로 고쳐 정확히 그렇게 됐다.
- **걸음마다 따로 재고 따로 적는다.** 하나가 영구히 실패하는 PC에서도 나머지 걸음은 조용하고, 알림 문구가 어느 걸음인지 말한다.

## 세 층

```
kw_install (설치기, PowerShell)
  0~7단계  이 PC에 매인 것
  8단계    마켓플레이스 kiwoom-ax 를 등록하고 kw-control-tower 하나만 깐다
  9단계    우산의 맞춤을 부르고 이어서 환경의 맞춤을 부른다
  10단계   검증

kw-control-tower (우산 — 목록만)
    ├ kw-environment      (필수)
    ├ kw-doc-formats      (필수)
    └ superpowers, document-skills, playwright, frontend-design  (권장)

kw-environment (환경 — 이 PC의 상태를 맞춘다)
  파이썬 라이브러리, CLAUDE.md 문안 블록, register-corp-certs 스킬,
  도커 인증서 훅, python3 가드
```

플러그인 사이에 부모와 자식 관계는 없다. 우산은 그것들을 담지 않고 **깔아 준다.** 우산은 자기를 목록에 안 적는다. 자기를 깔 수 없기 때문이고 그래서 설치기가 그 하나만 깐다.

**우산이 환경의 스크립트를 부르지 않는다.** 둘째 판은 우산의 걸음 하나가 환경을 이어 돌린다고 적었는데, 그러면 우산이 다른 프로세스가 방금 설치한 플러그인의 내부 경로를 알아야 한다. 층을 가른 뜻과 어긋난다. **설치기 9단계가 둘을 차례로 부른다.** 우산이 환경을 깐 뒤 설치기가 환경의 맞춤을 부른다.

## 레포

레포는 하나만 는다.

| 레포 | 담는 것 |
|---|---|
| `kw_install` | 설치기. 있는 것 |
| `KiwoomAX/KW-doc-formats` | 플러그인 하나. 있는 것을 그대로 둔다 |
| `KiwoomAX/kw-plugins` | 마켓플레이스 `kiwoom-ax` + 플러그인 둘 |

`kw-plugins`는 퍼블릭이고 `kw_install`은 비공개다. 각 PC가 마켓플레이스를 무인증으로 clone 해야 하므로 앞의 것은 퍼블릭이어야 하고, 설치기는 폴더를 복사해 나르므로 clone이 필요 없다.

**사내망 정보가 퍼블릭 쪽으로 간다.** `register-corp-certs` 스킬과 도커 훅이 환경 플러그인으로 옮겨 가는데, 그 훅에는 사내망에서 어느 도메인이 인증서를 요구하는지 실측한 목록이 들어 있다. 사용자가 그것을 공개해도 된다고 정했다. 담기는 것은 어느 공개 도메인이 인증서를 요구하더라는 관찰이고, 인증서 파일과 내부 주소는 들어가지 않는다.

새로 만드는 둘을 한 레포에 두는 이유는 셋이다. 지금 둘 다 작고, 판본이 한 벌로 움직여 우산의 선언과 환경의 실물이 어긋날 자리가 없으며, 새 플러그인을 더하는 것이 커밋 하나로 끝난다. 어느 하나가 커지면 그때 떼면 되므로 되돌릴 수 있다.

## 딛고 선 측정

이 PC에서 잰 것이다.

| 무엇 | 값 |
|---|---|
| 마켓플레이스 클론의 자리 | `~/.claude/plugins/marketplaces/<이름>/` 아래에 레포 전체가 그대로 있다 |
| 플러그인 사본의 자리 | `~/.claude/plugins/cache/<마켓플레이스>/<플러그인>/<판본>`. 판본마다 폴더가 따로 쌓인다 |
| 판본이 무엇에서 오나 | `plugin.json`에 `version`이 있으면 그 값, 없으면 마켓플레이스 커밋 접두. **그래서 한 레포의 플러그인들이 판본을 함께 쓴다.** 공식 플러그인 셋이 지금 `85cce0381e78`로 같다 |
| `gitCommitSha` | 항상 있지 않다. 공식 플러그인 셋에는 그 칸이 없다 |
| 자동 갱신 값이 사는 곳 | `~/.claude/plugins/known_marketplaces.json`. 클로드 코드가 실제로 읽는 파일이다 |
| 켜짐과 깔림이 갈린다 | `enabledPlugins`에 `false`인 것 셋이 `installed_plugins.json`에는 정상 항목으로 있다 |
| 은퇴가 한쪽에만 남는다 | `superpowers@superpowers-marketplace`와 `frontend-design@claude-code-plugins`가 `enabledPlugins`에는 없고 `installed_plugins.json`에는 있다 |
| 관리 설정 | 없다. 회사가 각 PC에 정책을 뿌릴 수단이 없다 |
| 설치기가 지금 나르는 것 | 플러그인 다섯, 은퇴 플러그인 둘, 라이브러리 일곱, 개인 문안 하나, 스킬 하나, 도커 훅 하나, 은퇴 스킬 하나 |
| 설치기가 파이썬을 찾는 법 | 절대 경로를 박은 것이 아니다. `Get-Command`로 PATH에서 이름을 찾은 뒤 `sys.executable`을 물어 절대 경로를 얻는다 |
| 설치기가 훅에 적는 인터프리터 | `pwsh.exe` 맨 이름이다 |
| WSL과 도커 | Ubuntu 둘과 `docker-desktop` 배포판이 있고 Docker Desktop이 깔려 있다 |
| 도커 훅의 자리 | `%LOCALAPPDATA%\corp-certs\`이고 그 절대 경로가 `settings.json`에 박힌다 |

## 왜 관리 설정이 아닌가

클로드 코드에는 이 일을 위해 마련된 자리가 이미 있다. 관리 설정은 사용자 설정보다 위에 있어 사용자가 못 지우고 `extraKnownMarketplaces`와 `enabledPlugins`와 `claudeMd`를 담는다. 그것이 정공법이다.

쓰지 않는 이유는 배포 수단이 없기 때문이다. 관리 설정은 조직 계정의 서버나 `HKLM\SOFTWARE\Policies\ClaudeCode`나 `C:\Program Files\ClaudeCode\managed-settings.json`에서 오고, 뒤의 둘은 관리자 권한과 배포 장치를 요구한다.

**그래서 무엇도 잠글 수 없다.** 이 설계가 만드는 것은 "못 끄게"가 아니라 "조용히 못 끄게"다.

## 우산이 하는 일

### 우산이 나르는 것

| 이름 | 무엇 |
|---|---|
| `manifest.json` | 선언 |
| `scripts/sync.sh` | 실제로 고친다. `/kw-sync`와 설치기 9단계가 부른다 |
| `hooks/session-check.sh` | 알리기만 한다 |
| `scripts/vendor/_resolve_home.sh` | `disciplined-coder`에서 받은 사본 |
| `skills/kw-sync/` | `/kw-sync` 스킬 |

우산은 `plugins/kw-control-tower/` 아래에 산다. 레포 루트를 플러그인으로 삼으면 이 마켓플레이스가 다른 플러그인을 담을 수 없다.

### 선언

목록 그 자체다. 가리키지 않는다.

```json
{
  "marketplaces": [
    { "name": "kiwoom-ax", "repo": "KiwoomAX/kw-plugins", "ours": true },
    { "name": "claude-plugins-official", "repo": "anthropics/claude-plugins-official" },
    { "name": "anthropic-agent-skills", "repo": "anthropics/skills" }
  ],
  "required": [ "kw-environment@kiwoom-ax", "kw-doc-formats@kiwoom-ax" ],
  "suggested": [
    "superpowers@claude-plugins-official",
    "document-skills@anthropic-agent-skills",
    "playwright@claude-plugins-official",
    "frontend-design@claude-plugins-official"
  ],
  "retiredPlugins": [
    "kw-doc-formats@kw-doc-formats",
    "superpowers@superpowers-marketplace",
    "frontend-design@claude-code-plugins"
  ],
  "retiredMarketplaces": [ "kw-doc-formats", "superpowers-marketplace" ]
}
```

**필수와 권장을 가른다.** 사내 것은 필수라 없으면 알리고 맞춤이 되돌려 놓는다. 공식 것은 권장이라 처음 한 번 깔고 **그 뒤로는 재지도 되돌리지도 않는다.** 사용자가 `playwright`를 안 쓴다고 지웠는데 매 세션 알리고 매번 다시 까는 것은 사용자 결정을 뒤집는 것이다. 자동 갱신에서 "남의 것은 존중한다"고 정한 것과 같은 규율을 플러그인 목록에도 건다.

**`ours`가 되켜기의 대상을 정한다.** 자동 갱신을 되켜는 것은 우리 마켓플레이스 하나이고, 남의 것은 키가 없을 때만 넣고 `false`로 둔 것은 그대로 둔다.

**은퇴가 둘이다.** `retiredPlugins`는 `enabledPlugins`의 키를 걷고 `retiredMarketplaces`는 `extraKnownMarketplaces`와 `known_marketplaces.json`의 항목을 걷는다. 설치기에서도 그 둘은 별개 코드다.

판 번호를 두지 않는다. 판 게이트는 읽는 쪽이 그 게이트를 이미 가질 때만 작동하는데 보호 대상이 정의상 그 코드를 갖지 않는다. 선언을 읽지 못하거나 형식이 아니면 멈추는 검사만 둔다.

### 훅이 재는 것

**`settings.json`의 `enabledPlugins`와 `known_marketplaces.json`의 우리 항목만 본다.** `installed_plugins.json`은 읽지 않는다. 그 파일은 아무도 안 지우므로 은퇴한 항목이 영원히 남아 끌 수 없는 경보가 된다.

- `required`의 플러그인이 `enabledPlugins`에 없거나 `false`면 알린다. **사용자가 `/plugin` 화면에서 끈 것이 여기서 잡힌다.**
- `retiredPlugins`가 `enabledPlugins`에 아직 있으면 알린다. 맞춤이 걷는 자리와 같으므로 고치면 꺼진다.
- `ours`인 마켓플레이스의 `autoUpdate`가 참이 아니면 알린다. **남의 마켓플레이스는 재지 않는다.** 되켤 수 없는 것을 재지 않는다.
- `suggested`는 재지 않는다.
- 이상이 없으면 아무 말도 하지 않는다.

파일 둘을 읽고 끝난다. 어떤 경우에도 파일을 고치지 않고 세션을 막지 않으며 스스로 실패하면 조용히 물러난다.

### `/kw-sync`가 고친다

걸음 넷이고 각각 독립이며 멱등이다.

1. 선언의 마켓플레이스를 등록한다. `ours`가 꺼져 있으면 되켠다. 남의 것은 키가 없을 때만 넣는다.
2. `required` 가운데 `enabledPlugins`에 없거나 `false`인 것을 깐다. `suggested`는 **`enabledPlugins`에 그 키가 아예 없을 때만** 깐다. `false`면 사용자가 정한 것이므로 그대로 둔다.
3. `retiredPlugins`를 `enabledPlugins`에서 걷고 `retiredMarketplaces`를 두 자리에서 걷는다.
4. 무엇을 했는지 요약한다. 되켠 것이 있으면 그것을 적는다.

되켜는 것은 우리 마켓플레이스 하나다. **이 결정은 `PYTHONUTF8`에서 "사용자 값을 존중한다"고 정한 것과 반대 방향이다.** 회사가 켠 것이 꺼졌으면 되켜는 쪽을 골랐고, 대신 되켠 것을 요약에 적어 조용하지 않게 한다.

### 훅이 재는 것 — 걸음마다 입력의 해시

판본을 재지 않는다. 판본은 `plugin.json`의 선언에 좌우되고, 없으면 마켓플레이스 커밋이 되어 **우산 쪽 커밋에도 바뀐다.** 선언에 한 줄 더한 날 모든 PC가 "환경이 바뀌었다"를 받는다. 반대로 `plugin.json`에 판 번호를 적으면 `requirements.txt`를 고쳐도 조용하다. 어느 쪽이든 틀린다.

**걸음마다 그 걸음의 입력 파일 해시를 잰다.** 상태 파일 `~/.claude/kw-environment.state`에 걸음 이름별로 마지막에 성공한 입력의 해시가 적혀 있다.

| 걸음 | 입력 |
|---|---|
| 라이브러리 | `requirements.txt` |
| 문안 | `templates/personal-memory-ko.md` |
| 은퇴 정리 | `env-manifest.json` |

훅은 파일 셋을 읽어 해시를 내고 상태와 비교한다. 다른 걸음이 있으면 **그 걸음의 이름을 넣어** 알린다. 첫 판이 실패한 것은 "선언 파일"의 해시를 잰 것이고, 이 판은 **가리킨 파일 자체**의 해시를 잰다.

상태 파일이 없으면 전부 다르다고 보고 알린다. 훅은 파일을 고치지 않는다.

### `/kw-env-sync`가 고친다

걸음 셋이고 각각 독립이며 멱등이다.

1. 파이썬 라이브러리를 고정한 3.12에 맞춘다.
2. `CLAUDE.md`의 `# BEGIN AX 설치` 블록을 다시 쓴다. 마커 바깥은 건드리지 않는다.
3. `env-manifest.json`의 은퇴 스킬과 은퇴 훅을 걷는다.

**걸음마다 그 걸음이 성공했을 때 그 걸음의 해시만 적는다.** 라이브러리를 못 깐 PC는 그 걸음만 계속 알리고 문안과 은퇴 정리는 조용하다. 둘째 판은 전부 성공했을 때만 적게 해서, 영구히 실패하는 PC가 매 세션 같은 문구를 받고 그 문구가 원인을 틀리게 말했다.

마지막에 무엇을 했는지 요약한다.

### 은퇴 스킬의 삭제 가드

설치기가 그 삭제에 조건을 걸어 두었다. 걸음 3이 그것을 들고 가되 **기준 하나를 바꾼다.**

- **대체가 확인된 뒤에만 지운다.** 먼저 지우고 설치가 실패하면 그 스킬이 아예 없는 PC가 된다. 그래서 선언이 대체자를 함께 적는다.
- **지우기 전에 사본을 뜬다.**
- **폴더에 `SKILL.md` 하나뿐일 때만 지운다.** 설치기의 기준은 "설치기가 쓴 바이트와 같은가"였는데, 설치기가 물러나면 그 기준의 주인이 사라진다. 환경 플러그인은 옛 설치기가 쓴 바이트를 알 수 없으므로 파일 개수로 바꾼다. 사용자가 무엇을 더해 두었으면 파일이 는다.
- **가드에 걸려 안 지운 것은 걸음의 성공이다.** 알리고 넘어간다. 실패로 세면 그 PC가 영원히 알림을 받는다.

```json
{
  "retiredSkills": [
    { "name": "document-formats", "replacedBy": "kw-doc-formats@kiwoom-ax" },
    { "name": "register-corp-certs", "replacedBy": "kw-environment@kiwoom-ax" }
  ],
  "retiredHooks": [ "docker-cert-reminder.ps1" ]
}
```

`register-corp-certs`가 은퇴 목록에 있는 것은 이미 설치기를 돌린 PC에 그 사본이 놓여 있기 때문이다. 걷지 않으면 같은 스킬이 두 벌 실린다.

`retiredHooks`는 `settings.json`의 `hooks`에서 그 이름을 인자로 갖는 항목을 걷는다. 설치기가 `%LOCALAPPDATA%\corp-certs\`의 절대 경로를 거기 박아 두었다.

### 훅을 어느 도구에 거나

**Bash와 PowerShell 두 매처에 각각 건다.** 설치기가 도커 훅을 그렇게 걸고 있고, 이 PC는 `defaultShell`이 `powershell`이라 하나만 걸면 실제로 쓰이는 경로가 감시에서 빠진다.

### 셸 스크립트가 어느 홈을 보나

훅과 맞춤 스크립트는 클로드 코드가 훅 배선을 읽어 부르므로 설치기가 정한 경로를 물려받지 못한다. 윈도에는 이름이 같은 다른 bash가 있고 WSL의 것이 잡히면 리눅스 쪽 홈에서 돈다.

**그래서 모든 스크립트가 첫 줄에서 `_resolve_home.sh`로 홈을 정한다.** 그 함수는 `USERPROFILE`을 먼저 보므로 WSL bash에서 돌아도 윈도 홈을 가리킨다. 도메인 PC의 네트워크 홈 리다이렉트도 같은 함수가 다룬다. `USERPROFILE`이 없으면 순수 리눅스이므로 아무것도 안 하고 물러난다.

이 사본이 우산에도 필요하다. 우산이 읽고 쓰는 파일이 전부 설정 홈 아래에 있다.

## 경계

기준은 둘이다. **이 PC의 하드웨어와 사내망과 레지스트리에 매인 것**과 **자라지 않는 설정**은 설치기에 남고, 목록이 자라는 것은 밖으로 간다.

| 지금 자리 | 무엇 | 어디로 |
|---|---|---|
| 0단계 | pwsh 판과 payload와 winget 점검 | 설치기 |
| 1단계 | CA 번들과 인증서 환경변수 넷 | 설치기 |
| 2단계 | Python 3.12와 git과 Node와 Poppler | 설치기 |
| 3단계 | `PYTHONUTF8` | 설치기 |
| 3단계 | 라이브러리 일곱 | 환경 |
| 4단계 | 클로드 코드 설치 | 설치기 |
| 5단계 | 사용자 PATH | 설치기 |
| 6단계 | 윈도우 터미널 글꼴과 바로가기 | 설치기 |
| 7단계 | `settings.json`의 키 넷 | 설치기 |
| 7단계 | `settings.json`의 플러그인 절 | 우산 |
| 7단계 | 도커 인증서 훅 | 환경 |
| 7단계 | `register-corp-certs` 스킬 | 환경 |
| 7단계 | `CLAUDE.md` 개인 문안 블록 | 환경 |
| 8단계 | 플러그인 목록과 은퇴 목록 | 우산 |
| 8단계 | 마켓플레이스 등록과 우산 설치 | 설치기 |
| 9단계 | HTTPS 검증 | 설치기 |

설치기에 남는 `settings.json` 키는 넷이다. `env.CLAUDE_CODE_USE_POWERSHELL_TOOL`과 `defaultShell`과 `disableSkillShellExecution`과 `permissions.defaultMode`다. 하드웨어에 매이지는 않지만 자라지 않고 클로드 코드가 뜨는 방식을 정하는 것이라 부트스트랩과 같은 자리에 둔다.

바로가기가 설치기에 남는 것은 `.lnk`를 만드는 것이 COM 호출이고 윈도우 터미널 설정 파일과 짝이기 때문이다.

**`Merge-ClaudeSettings`의 플러그인 절을 걷어낸다.** 그 함수는 `$script:Plugins`를 진실로 삼아 `extraKnownMarketplaces`와 `enabledPlugins`를 쓰고 아무도 안 쓰는 마켓플레이스를 걷는다. 목록을 밖으로 빼면 그 진실이 비므로 절 전체를 우산에게 넘긴다.

## disciplined-coder와의 경계

**가르는 것은 만지는 자리가 아니라 스크립트의 소유다.** 두 체계가 PC에 남기는 결과는 겹쳐도 된다. 금지하는 것은 런타임에 상대의 스크립트를 부르는 것과 한 파일을 두 레포가 공동 소유하는 것이다. 사본을 받는 것은 걸리지 않는다.

겹쳐도 되게 하려면 걸음마다 둘을 지킨다. 멱등이어서 상대가 먼저 돌린 뒤에 돌아도 결과가 같아야 하고, 남이 써 둔 것을 지우지 않아야 한다. 주인 없는 사용자 값(`BASH_DEFAULT_TIMEOUT_MS`)도 건드리지 않는다.

| 무엇 | 우산 | 환경 | disciplined-coder |
|---|---|---|---|
| `~/.claude/CLAUDE.md` | 안 만진다 | `# BEGIN AX 설치` 블록 | `# BEGIN disciplined-coder` 블록 |
| `~/.claude/settings.json` | `extraKnownMarketplaces`, `enabledPlugins` | `hooks`의 옛 도커 항목 | `extraKnownMarketplaces`의 `chshin-tools` |
| `known_marketplaces.json` | 선언의 마켓플레이스 셋 | 안 만진다 | `chshin-tools` |
| `HKCU\Environment`의 `PYTHONUTF8` | 안 만진다 | 안 만진다 | 물어서 세운다 |
| `~/.claude/skills/` | 안 만진다 | 은퇴한 사본을 걷는다 | 안 만진다 |
| 파이썬 라이브러리 | 안 만진다 | 선언대로 깐다 | 안 만진다 |
| 상태 파일 | 없다 | `kw-environment.state` | 자기 이름의 파일 |

`disciplined-coder`가 `claude-plugins-official`도 만지겠다고 알려 왔지만 그쪽 사용자 승인 전이다. 승인되면 이 표에 더한다. 지금 그쪽 코드는 자기 마켓플레이스만 고른다.

### 잠금이 없는 자리

`CLAUDE.md`는 사본을 쓰므로 두 체계가 같은 잠금 파일을 잡고 서로 배제된다. **`known_marketplaces.json`과 `settings.json`에는 잠금이 없다.** 양쪽 다 잠금 없이 읽고 고쳐 쓰며 `disciplined-coder`의 쓰기는 고정 이름의 임시 파일을 쓴다. 창 둘을 열어 두고 한쪽이 맞춤을 도는 동안 다른 쪽 세션이 시작하면 한쪽 결과가 사라질 수 있다.

멱등은 순차 실행의 성질이라 동시 읽고 쓰기를 막지 못한다. 완화만 가능하다. 우산이 자기 쓰기를 짧게 유지하고 잠금을 두자는 제안을 정본에 올린다.

## 범용 함수의 사본

| 사본 | 어디에 | 왜 |
|---|---|---|
| `_resolve_home.sh` | 우산과 환경 둘 다 | 설정 홈을 정한다. WSL bash와 도메인 PC의 홈 리다이렉트를 함께 다룬다 |
| `_managed_block.sh` | 환경 | `CLAUDE.md`의 마커 블록을 다시 쓴다. 두 체계가 같은 잠금 파일을 잡게 되는 것이 이 사본의 값이다 |
| `_json_valid.sh` | 위 둘이 기대는 것 | |

**`_ensure_autoupdate.sh`는 받지 않는다.** 마켓플레이스 이름을 플러그인 루트의 `.claude-plugin/marketplace.json`에서 읽는데 우산은 그 자리에 그 파일이 없고, 내부 종료 코드 `10`이 "항목이 아예 없다"와 "이미 값이 있다"를 함께 덮어 등록과 되켜기를 가를 수 없다. 우산이 자기 코드로 쓴다. (그 함수가 바꾼 경로를 stdout으로 알린다는 것은 맞다. 둘째 판이 "알리지 않는다"고 적은 것은 틀렸다.)

마커는 처음부터 함수 인자였고 이름표는 `MANAGED_TAG`로 인자화가 끝났다. `source` 앞에 값을 세우면 되고 함수 시그니처는 그대로다.

사본 규율은 셋이다. 사본은 생성물이라 손으로 고치지 않고, 머리에 정본의 커밋 SHA와 파일 해시를 적으며, 낡음 검사는 사본 쪽 테스트에만 둔다. 정본 레포를 못 찾으면 통과로 끝내지 않고 "대조 불가"로 알린다.

사본을 만드는 것과 낡음을 재는 것은 개발 PC에서만 된다. 사본은 레포에 커밋되어 플러그인과 함께 배포되고 `vendor.sh`는 개발자 도구이며 런타임은 낡음을 재지 않는다. 정본 레포의 자리는 박아 넣지 않고 환경변수나 인자로 받는다.

**`_managed_block.sh` 사본은 잠금 규약 판 번호가 정본에 들어온 뒤에 들인다.** 이 사본의 값은 잠금 공유 하나인데, 정본이 규약을 고치고 사본이 옛 판이면 같은 잠금 파일을 잡고도 배제가 깨진다. 그리고 사용자 PC에서는 아무도 그것을 재지 않는다. **값이 조건부인데 장치를 무조건 만들지 않는다.** 그때까지 환경의 `CLAUDE.md` 걸음은 만들지 않고 그 일은 설치기에 남겨 둔다.

## 설치기가 바뀌는 것

```
0 사전 점검 -> 1 인증서 -> 2 프로그램 -> 3 PYTHONUTF8 -> 4 클로드 -> 5 PATH
-> 6 터미널 -> 7 배선 -> 8 마켓플레이스 등록과 우산 설치 -> 9 우산 맞춤과 환경 맞춤 -> 10 검증
```

9단계가 우산의 `sync.sh`를 부르고, 그것이 끝나면 환경의 `env-sync.sh`를 부른다. 둘 다 마켓플레이스 클론 아래의 알려진 경로에 있다. 설치기가 끝나면 PC는 지금과 똑같이 완성 상태다.

**bash를 이름으로 부르지 않는다.** 설치기는 Git 설치 경로의 bash를 찾고 못 찾으면 9단계를 건너뛰고 경고를 남긴다. 근거는 "설치기가 이미 그렇게 한다"가 아니다. 설치기는 파이썬을 PATH에서 이름으로 찾은 뒤 `sys.executable`로 절대 경로를 얻고, 훅에는 `pwsh.exe` 맨 이름을 적는다. **이 규율은 새로 세우는 것이고, 그 이유는 이 PC에 WSL 배포판이 셋 있어 이름이 같은 다른 bash가 실재하기 때문이다.**

**선언을 못 읽으면 9단계를 통째로 건너뛴다.** 백업 목록을 설치기에 두지 않는다. 같은 사실이 두 곳에 남으면 곧 어긋난다. 무엇을 못 했는지 경고로 남기고 다시 돌리게 한다.

## 이행

네 걸음이다. 걸음마다 이 PC에서 실제로 돌려 보고 되돌리는 길을 함께 적는다.

**첫째, `kw-plugins` 레포를 세운다.** 마켓플레이스와 플러그인 둘을 만든다. 이 시점의 선언에는 **발행처 이전을 담지 않는다.** `kw-doc-formats`는 아직 옛 마켓플레이스에서 오고 `retiredMarketplaces`도 비어 있다. 환경의 `CLAUDE.md` 걸음도 아직 만들지 않는다. 사본 조건이 안 갖춰졌고 설치기가 그 일을 하고 있기 때문이다.

`--plugin-dir`로 얹어 시험하되 **한계를 알고 한다.** 그렇게 얹은 플러그인은 `installed_plugins.json`에 항목을 안 만든다. 다만 이 판의 훅은 `enabledPlugins`를 보므로 그 키를 손으로 넣고 빼며 판정을 시험할 수 있다. 그것이 이 감지 방식이 주는 덤이다.

되돌리기는 로컬 커밋을 지우는 것뿐이다.

**둘째, 설치기를 얇게 만든다.** 옮겨 간 것을 걷어내고 8·9단계를 새로 쓰며 `Merge-ClaudeSettings`의 플러그인 절을 걷는다. 스킬 복사와 도커 훅 등록도 이때 걷는다. `CLAUDE.md` 문안은 아직 설치기에 남긴다.

**이 걸음 전에는 설치기를 다시 돌리지 않는다.** 얇아지지 않은 설치기의 청소 반복문이 우산이 넣어 둔 `kiwoom-ax` 항목을 남의 것으로 보고 걷어낸다.

되돌리기는 커밋 되돌리기다. **다만 이미 배포된 PC는 되돌아가지 않는다.** 우산과 환경이 그 PC에 남고, 걷으려면 새 선언에 그것들을 은퇴로 적어 내보내야 한다. 되돌리기의 진짜 수단은 레포가 아니라 선언이다.

**셋째, 잠금 규약 판 번호가 정본에 들어오면 `_managed_block.sh` 사본을 들이고 환경의 `CLAUDE.md` 걸음을 만든다.** 그 걸음이 각 PC에서 처음 돌 때 **접두로 옛 블록을 찾아 한 번 정규화한다.** 설치기는 접두 정규식으로 찾아 왔고 괄호 안 문구가 바뀌어도 살아남게 하려던 것이라고 `setup.ps1:1616`의 주석이 적는다. 사본은 전체 줄 일치라 옛 문구를 못 찾고 블록을 하나 더 붙인다. 정규화는 개발 PC 한 번이 아니라 **각 PC에서 그 걸음이 처음 돌 때** 한다. 드리프트가 각 PC에 있기 때문이다.

되돌릴 수 없는 걸음이라 정규화 전에 그 PC에 `CLAUDE.md.pre-normalize` 사본을 뜬다. 설치기 쪽의 `CLAUDE.md` 코드는 이때 걷는다.

**넷째, 발행처를 옮긴다.** `kiwoom-ax`가 `kw-doc-formats`를 발행하게 하고 선언에 은퇴를 적어 내보낸다. **각 PC에 그 선언이 도착해 옛 등록이 걷힌 것을 확인한 뒤에** `KW-doc-formats` 레포의 마켓플레이스 파일을 지운다.

되돌리기는 그 파일을 되살리는 것이다. 지운 파일은 git에 남아 있으므로 되돌릴 수 있다. **순서가 이런 것은 비대칭 때문이다.** 파일을 지우는 것은 되돌릴 수 있지만, 걷어낼 주체가 도착하기 전에 지워서 사라진 스킬은 그 PC에서 되돌릴 수 없다.

## 테스트

- **선언 읽기** — 형식이 아니거나 읽지 못하면 멈춘다.
- **우산의 훅** — `required`가 `enabledPlugins`에 있고 `true`면 조용하다. 없거나 `false`면 낸다. 은퇴한 것이 그 키에 있으면 낸다. 우리 마켓플레이스의 자동 갱신이 꺼졌으면 낸다. **남의 마켓플레이스가 꺼져 있어도 조용하다.** `suggested`가 `false`여도 조용하다. 파일이 깨져 있어도 세션을 막지 않는다.
- **우산의 맞춤** — 두 번 돌려도 결과가 같다. `suggested`가 `false`면 그대로 둔다. 되켜는 것이 우리 것 하나다. 은퇴 둘을 두 자리에서 걷는다. 되켠 것이 요약에 나온다.
- **환경의 훅** — 걸음별 해시가 같으면 조용하고 하나만 다르면 그 걸음의 이름을 넣어 낸다. 상태 파일이 없으면 전부 낸다.
- **환경의 맞춤** — 두 번 돌려도 결과가 같다. **걸음 하나가 실패하면 그 걸음의 해시만 안 적고 나머지는 적는다.** `CLAUDE.md`의 마커 바깥이 살아남는다. 삭제 가드가 걸리면 안 지우고 성공으로 센다.
- **`python3` 가드** — 호스트의 `python3`과 `python3.exe`를 막는다. `python`과 `py -3`은 안 막는다. **`wsl ... python3`과 `docker exec ... python3`은 안 막는다.**
- **훅 배선** — 훅마다 Bash와 PowerShell 두 매처에 걸린다.
- **홈 정하기** — `USERPROFILE`이 있으면 그것을 따르고 없으면 물러난다.
- **사본** — 낡음 검사가 정본과 대조한다. 정본 레포를 못 찾으면 통과가 아니라 "대조 불가"다.
- **경계** — `chshin-tools` 항목과 `# BEGIN disciplined-coder` 블록을 심어 놓고 자기 걸음을 돌린 뒤 글자 그대로 살아남는지 본다.
- **마커 정규화** — 괄호 문구가 다른 옛 블록을 접두로 찾아 하나로 만들고, 사본을 뜬 뒤에만 고친다.

멱등은 같은 프로세스가 아니라 **새 프로세스에서** 잰다. `kw_install` 테스트에 그 자리가 있고 같은 규율을 가져온다.

`kw_install` 쪽 테스트는 옮겨 간 것을 검사하던 자리를 지우고, 9단계가 bash를 절대 경로로 찾는지와 **선언을 못 읽으면 건너뛰는지**를 검사하는 자리를 더한다.

## 남는 위험

- **우산 하나가 단일 실패점이다.** 우산이 안 깔리면 사내 것 전부가 안 온다. 설치기가 그 실패를 경고가 아니라 실패로 다룬다.
- **무엇도 잠글 수 없다.** 사용자가 플러그인을 지우면 이 장치가 멈춘다.
- **`known_marketplaces.json`과 `settings.json`에 잠금이 없다.** 동시에 쓰면 한쪽 결과가 사라질 수 있다.
- **훅이 셋 돈다.** 우산의 세션 훅과 환경의 세션 훅과 `python3` 가드다. 앞의 둘은 파일 몇 개를 읽고 끝나지만 세션 시작이 그만큼 느려진다.
- **이미 배포된 PC는 커밋 되돌리기로 안 되돌아간다.** 되돌리는 수단은 선언이다.
- **`suggested`를 재지 않기로 해서, 처음 설치에 실패한 권장 플러그인은 아무도 알려 주지 않는다.** 사용자 결정을 존중하는 대가다.
- **레포가 셋이 되어 이름이 어긋날 수 있다.** 세 레포를 잇는 검사가 없다.

## 하지 않는 것

- 관리 설정을 쓰지 않는다.
- 훅이 설치하거나 파일을 고치지 않는다.
- 백업 목록을 설치기에 두지 않는다.
- `KW-doc-formats`의 스킬 내용을 손대지 않는다. 발행처만 옮긴다.
- 설치기의 0·1·2·4·5·6단계를 손대지 않는다.
- 선언에 판 번호를 두지 않는다.
- 플러그인 판본을 감지에 쓰지 않는다.
- `installed_plugins.json`을 감지에 쓰지 않는다.

## 이 설계에 흡수되는 것

`python3` 호출을 막는 훅이 환경 플러그인으로 온다. 호출을 거부하고 이유를 돌려준다.

**끄는 스위치를 두지 않는다.** 사용자 확정이다. 이 이름은 파이썬이 아니라 마이크로소프트 스토어로 보내는 안내판이라 부를 이유 자체가 없다.

**막는 것은 호스트의 호출뿐이다.** 이 PC에는 WSL 배포판이 셋 있고 Docker Desktop이 깔려 있다. 리눅스 안에서는 `python3`이 정확한 이름이므로 `wsl ... python3`과 `docker exec ... python3`은 지나간다. 확정은 그대로이고 범위만 정확해진다. 스위치를 안 두기로 한 근거가 "거짓 양성이 없다"인데, 범위를 안 좁히면 그 근거가 깨진다.
