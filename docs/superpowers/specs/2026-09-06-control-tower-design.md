# 사내 컨트롤 타워 설계 (2026-09-06)

설치기가 PC를 세우고 플러그인 하나만 깐다. 그 하나가 나머지 전부를 끌고 온다.

**둘째 판이다.** 첫 판은 우산 하나에 목록과 환경을 함께 담았고 검진에서 무너졌다. 감지 장치가 옮기려는 것의 3분의 1만 볼 수 있었다. 기록은 `docs/superpowers/reviews/2026-09-06-control-tower-review.md`에 있다.

## 목적

사내 플러그인을 앞으로 여럿 만든다. 지금 구조에서는 새 플러그인이 하나 생길 때마다 `kw_install`의 `$script:Plugins` 표를 고치고 모든 PC에서 설치기를 다시 돌려야 한다. 목록이 설치기 안에 있기 때문이다.

목록을 설치기 밖으로 꺼내 한 곳에 두고, 각 PC가 그 한 곳을 계속 바라보게 만든다. 그러면 새 플러그인을 더하는 일이 커밋 하나가 되고 각 PC는 다음 세션에 그것을 듣는다.

옮기는 것은 플러그인 목록만이 아니다. 파이썬 라이브러리와 `CLAUDE.md`의 개인 문안과 사내 스킬처럼 **목록이 자라는 것 전부**가 대상이다.

## 첫 판이 무너진 자리

검진이 짚은 뿌리는 하나다. **감지의 범위가 옮기려는 것의 범위보다 좁았다.**

첫 판은 우산 하나가 목록과 라이브러리와 문안을 함께 나르고, 세션 시작 훅이 선언 파일의 해시를 재게 했다. 그런데 선언은 라이브러리와 문안을 **가리키기만** 했다. `requirements.txt`에 한 줄을 더해도 선언의 바이트는 그대로여서 훅은 아무 말도 하지 않는다. 이 설계가 풀려던 상황이 통째로 조용히 지나간다.

원인은 성격이 다른 둘을 한 플러그인에 담은 것이다. **목록은 선언적이고 자주 바뀌며 되돌릴 것이 없다. 환경은 사용자 파일을 고치고 위험이 있으며 드물게 바뀐다.** 하나로 묶으니 감지 장치가 둘을 한꺼번에 재려다 실패했다.

## 세 층

```
kw_install (설치기, PowerShell)
  1~7단계  이 PC에 매인 것
  8단계    마켓플레이스 kiwoom-ax 를 등록하고 kw-control-tower 하나만 깐다
  9단계    우산의 맞춤 스크립트를 한 번 부른다
  10단계   검증

kw-control-tower (우산 — 목록만)
  manifest.json 에 적힌 것을 깔고 은퇴한 것을 걷는다
    ├ kw-environment
    ├ kw-doc-formats
    ├ superpowers@claude-plugins-official
    ├ document-skills@anthropic-agent-skills
    └ playwright, frontend-design ...

kw-environment (환경 — 이 PC의 상태를 맞춘다)
  파이썬 라이브러리, CLAUDE.md 문안 블록, register-corp-certs 스킬,
  도커 인증서 훅, python3 가드
```

플러그인 사이에 부모와 자식 관계는 없다. 우산은 그것들을 담지 않고 **깔아 준다.** 목록에 적히는 것이지 안에 들어 있는 것이 아니다.

우산은 자기를 목록에 안 적는다. 자기를 깔 수 없기 때문이고, 그래서 설치기가 그 하나만 깐다. 우산 자신의 갱신은 마켓플레이스 자동 갱신이 한다.

## 레포

레포는 하나만 는다.

| 레포 | 담는 것 |
|---|---|
| `kw_install` | 설치기. 있는 것 |
| `KiwoomAX/KW-doc-formats` | 플러그인 하나. 있는 것을 그대로 둔다 |
| `KiwoomAX/kw-plugins` | 마켓플레이스 `kiwoom-ax` + 플러그인 둘(`kw-control-tower`, `kw-environment`) |

새로 만드는 둘을 한 레포에 두는 이유는 셋이다. 지금 둘 다 작고, 판본이 한 벌로 움직여 우산의 선언과 환경의 실물이 어긋날 자리가 없으며, 새 플러그인을 더하는 것이 커밋 하나로 끝난다. 어느 하나가 커지면 그때 떼면 되므로 되돌릴 수 있다.

`KW-doc-formats`는 옮기지 않는다. 이미 자기 spec과 검진 기록과 테스트를 갖고 서 있고, 마켓플레이스가 가리키기만 하면 된다.

## 딛고 선 측정

이 PC에서 잰 것이다.

| 무엇 | 값 |
|---|---|
| 마켓플레이스 클론의 자리 | `~/.claude/plugins/marketplaces/<이름>/` 아래에 레포 전체가 그대로 있다 |
| 플러그인 사본의 자리 | `~/.claude/plugins/cache/<마켓플레이스>/<플러그인>/<판본>`. `installed_plugins.json`의 `installPath`가 가리키며 **판본마다 폴더가 따로 쌓인다** |
| 자동 갱신 값이 사는 곳 | `~/.claude/plugins/known_marketplaces.json`. 클로드 코드가 실제로 읽는 파일이다 |
| `settings.json`의 같은 항목 | `extraKnownMarketplaces`에도 자리가 있고 설치기가 양쪽 모두에 쓴다. `kw-doc-formats`의 두 자리가 지금 어긋나 있다 |
| 관리 설정 | 없다. 회사가 각 PC에 정책을 뿌릴 수단이 없다고 사용자가 답했다 |
| 설치기가 지금 나르는 것 | 플러그인 다섯, 은퇴 플러그인 둘, 라이브러리 **일곱**, 개인 문안 하나, 스킬 하나, 도커 훅 하나, 은퇴 스킬 하나 |
| `settings.json`의 기록자 | `Merge-ClaudeSettings` 하나다. 자동 갱신은 그 함수가 `settings.json`에 쓰고 `Set-MarketplaceAutoUpdate`가 `known_marketplaces.json`에 따로 쓴다 |
| 개인 스킬 폴더 | `register-corp-certs`가 실제로 놓여 있다 |
| 도커 훅의 자리 | `~/.claude/hooks/`가 아니라 `%LOCALAPPDATA%\corp-certs\`이고 그 절대 경로가 `settings.json`에 박힌다 |

## 왜 관리 설정이 아닌가

클로드 코드에는 이 일을 위해 마련된 자리가 이미 있다. 관리 설정은 사용자 설정보다 위에 있어 사용자가 못 지우고, `extraKnownMarketplaces`와 `enabledPlugins`와 `claudeMd`와 `pluginSuggestionMarketplaces`를 담는다. 그것이 정공법이다.

쓰지 않는 이유는 배포 수단이 없기 때문이다. 관리 설정은 조직 계정의 서버나 `HKLM\SOFTWARE\Policies\ClaudeCode`나 `C:\Program Files\ClaudeCode\managed-settings.json`에서 오고, 뒤의 둘은 관리자 권한과 배포 장치를 요구한다.

**그래서 무엇도 잠글 수 없다.** 이 설계가 만드는 것은 "못 끄게"가 아니라 "조용히 못 끄게"다.

## 우산이 하는 일

우산의 선언 `manifest.json`은 **목록 그 자체다.** 가리키지 않는다. 그래서 목록이 바뀌면 파일이 바뀐다.

```json
{
  "marketplaces": [
    { "name": "kiwoom-ax", "repo": "KiwoomAX/kw-plugins", "autoUpdate": true },
    { "name": "claude-plugins-official", "repo": "anthropics/claude-plugins-official", "autoUpdate": true },
    { "name": "anthropic-agent-skills", "repo": "anthropics/skills", "autoUpdate": true }
  ],
  "plugins": [
    "kw-environment@kiwoom-ax",
    "kw-doc-formats@kiwoom-ax",
    "superpowers@claude-plugins-official",
    "document-skills@anthropic-agent-skills",
    "playwright@claude-plugins-official",
    "frontend-design@claude-plugins-official"
  ],
  "retiredPlugins": [
    "kw-doc-formats@kw-doc-formats",
    "superpowers@superpowers-marketplace",
    "frontend-design@claude-code-plugins"
  ],
  "retiredMarketplaces": [ "kw-doc-formats" ]
}
```

**마켓플레이스와 플러그인을 따로 적는다.** 자동 갱신은 마켓플레이스 단위 값인데 첫 판은 그것을 플러그인 줄에 적어, 같은 마켓플레이스의 세 항목이 서로 다른 값을 가질 수 있는 꼴이었다.

**은퇴가 둘이다.** `retiredPlugins`는 `enabledPlugins`의 키를 걷고, `retiredMarketplaces`는 `extraKnownMarketplaces`와 `known_marketplaces.json`의 항목을 걷는다. 첫 판은 앞의 하나로 뒤의 일까지 하려 했는데, 설치기에서도 그 둘은 별개 코드다.

**`frontend-design@claude-code-plugins`가 은퇴 목록에 있다.** 첫 판이 설치기의 은퇴 둘 가운데 하나를 빠뜨렸다. 이 PC의 `installed_plugins.json`에 아직 남아 있다.

**판 번호를 두지 않는다.** 첫 판은 옛 설치기를 든 PC를 위해 `schema`를 두었는데, 판 게이트는 읽는 쪽이 그 게이트를 이미 가질 때만 작동한다. 보호 대상이 정의상 그 코드를 갖지 않으므로 한 번도 발동할 수 없다. 대신 선언을 읽지 못하거나 형식이 아니면 멈추는 검사만 남긴다.

### 우산의 훅은 실물을 잰다

해시를 쓰지 않는다. **선언과 `installed_plugins.json`을 대조한다.**

- 선언의 플러그인 가운데 `installed_plugins.json`에 없는 것이 있으면 알린다.
- 은퇴 목록에 있는 것이 아직 있으면 알린다.
- 선언의 마켓플레이스 가운데 `known_marketplaces.json`에서 `autoUpdate`가 참이 아닌 것이 있으면 알린다.
- 이상이 없으면 아무 말도 하지 않는다.

파일 둘을 읽고 끝난다. 해시라는 간접 신호를 거치지 않으므로 상태 파일도 필요 없고, 상태 파일이 지워지거나 낡아 생기는 거짓 판정도 없다.

어떤 경우에도 파일을 고치지 않고 세션을 막지 않는다. 스스로 실패하면 조용히 물러난다.

### `/kw-sync`가 고친다

걸음 넷이고 각각 독립이며 멱등이다.

1. 선언의 마켓플레이스를 등록한다. 없으면 넣고, `kiwoom-ax`가 꺼져 있으면 되켠다. 남의 마켓플레이스는 키가 없을 때만 넣고 `false`로 둔 것은 그대로 둔다.
2. 선언의 플러그인을 깐다.
3. `retiredPlugins`와 `retiredMarketplaces`를 걷는다.
4. 무엇을 했는지 요약한다. 되켠 것이 있으면 그것을 적는다.

되켜는 것은 `kiwoom-ax` 하나다. **이 결정은 `PYTHONUTF8`에서 "사용자 값을 존중한다"고 정한 것과 반대 방향이다.** 첫 판은 "결이 같다"고 적었는데 틀렸다. 회사가 켠 것이 꺼졌으면 되켜는 쪽을 골랐고, 대신 되켠 것을 요약에 적어 조용하지 않게 한다.

## 환경이 하는 일

환경 플러그인이 나르는 것은 이렇다.

| 이름 | 무엇 |
|---|---|
| `requirements.txt` | 파이썬 라이브러리 일곱. `kw_install`에서 옮겨 온다 |
| `templates/personal-memory-ko.md` | `CLAUDE.md`의 `# BEGIN AX 설치` 블록. `kw_install`에서 옮겨 온다 |
| `skills/register-corp-certs/` | `kw_install`에서 옮겨 온다 |
| `hooks/docker-cert-reminder.sh` | `kw_install`에서 옮겨 오며 셸로 옮겨 적는다 |
| `hooks/python3-guard.sh` | 새로 만든다 |
| `hooks/session-check.sh` | 판본을 비교해 알리기만 한다 |
| `scripts/env-sync.sh` | 실제로 고친다. `/kw-env-sync`와 우산의 걸음 2가 부른다 |
| `scripts/vendor/` | `disciplined-coder`에서 받은 사본 |
| `scripts/vendor.sh` | 사본을 다시 뜨는 개발자 도구 |

### 환경의 훅은 판본을 잰다

라이브러리를 매 세션 `pip`으로 세면 느리다. 그래서 **자기 설치 판본**을 잰다. `installed_plugins.json`의 이 플러그인 항목에 `version`과 `gitCommitSha`가 있고, `~/.claude/kw-environment.state`에 마지막으로 맞춘 판본이 적혀 있다. 둘이 다르면 "환경이 바뀌었다, `/kw-env-sync`를 돌려라"를 낸다.

**가리킨 파일이 무엇이든 판본이 함께 바뀐다.** 라이브러리 한 줄을 더해도, 문안을 고쳐도, 스킬을 손봐도 플러그인 판본이 바뀐다. 첫 판의 해시가 못 잡던 것을 이것이 다 잡는다.

### `/kw-env-sync`가 고친다

걸음 다섯이고 각각 독립이며 멱등이다.

1. 파이썬 라이브러리를 고정한 3.12에 맞춘다.
2. `CLAUDE.md`의 `# BEGIN AX 설치` 블록을 다시 쓴다. 마커 바깥은 건드리지 않는다.
3. 개인 스킬 폴더의 은퇴한 사본을 걷는다.
4. `settings.json`에 남은 옛 도커 훅 항목을 걷는다.
5. 무엇을 했는지 요약하고, **걸음 넷이 모두 성공했을 때만** 판본을 상태 파일에 적는다.

**부분 성공이면 상태를 적지 않는다.** 첫 판은 조건 없이 적게 해서, 라이브러리 설치가 실패한 PC가 「이상 없음」으로 표시된 채 도는 길이 있었다.

### 은퇴 스킬의 삭제 가드

설치기가 그 삭제에 조건 셋을 걸어 두었다. 걸음 3이 그것을 그대로 들고 간다.

- **대체가 확인된 뒤에만 지운다.** 먼저 지우고 설치가 실패하면 그 스킬이 아예 없는 PC가 된다.
- **설치기가 쓴 것 말고 아무것도 없을 때만 지운다.** 사용자가 손으로 더한 파일이 있으면 남기고 알린다.
- **지우기 전에 사본을 뜬다.**

은퇴 목록은 이름만이 아니라 대체자를 함께 적는다.

```json
{
  "retiredSkills": [
    { "name": "document-formats", "replacedBy": "kw-doc-formats@kiwoom-ax" },
    { "name": "register-corp-certs", "replacedBy": "kw-environment@kiwoom-ax" }
  ]
}
```

**`register-corp-certs`가 은퇴 목록에 있다.** 첫 판은 "플러그인이 나르면 개인 스킬 폴더에 복사할 일이 없어진다"고 적었는데, 그것은 새로 세우는 PC에만 참이다. 이미 설치기를 돌린 PC에는 사본이 놓여 있고 걷지 않으면 같은 스킬이 두 벌 실린다.

## 경계

나누는 기준은 하나다. **이 PC의 하드웨어와 사내망과 레지스트리에 매인 것은 설치기에 남고, 목록이 자라는 것은 밖으로 간다.**

| 지금 자리 | 무엇 | 어디로 |
|---|---|---|
| 0단계 | pwsh 판과 payload와 winget 점검 | 설치기 |
| 1단계 | CA 번들과 인증서 환경변수 넷 | 설치기 |
| 2단계 | Python 3.12와 git과 Node와 Poppler | 설치기 |
| 3단계 | `PYTHONUTF8` | 설치기 |
| 3단계 | 라이브러리 일곱 | 환경 |
| 4단계 | 클로드 코드 설치 | 설치기 |
| 5단계 | 사용자 PATH | 설치기 |
| 6단계 | 윈도우 터미널 글꼴과 바로가기 | 설치기 |
| 7단계 | `settings.json`의 PowerShell 도구와 기본 셸과 권한 모드 | 설치기 |
| 7단계 | `settings.json`의 플러그인 선언 절 | **우산** |
| 7단계 | 도커 인증서 훅 | 환경 |
| 7단계 | `register-corp-certs` 스킬 | 환경 |
| 7단계 | `CLAUDE.md` 개인 문안 블록 | 환경 |
| 8단계 | 플러그인 목록과 은퇴 목록 | 우산 |
| 8단계 | 마켓플레이스 등록과 우산 설치 | 설치기 |
| 9단계 | HTTPS 검증 | 설치기 |

바로가기가 설치기에 남는 것은 `.lnk`를 만드는 것이 COM 호출이고 윈도우 터미널 설정 파일과 짝이기 때문이다.

**`Merge-ClaudeSettings`의 플러그인 절을 걷어낸다.** 그 함수는 `$script:Plugins`를 진실로 삼아 `extraKnownMarketplaces`와 `enabledPlugins`를 쓰고, 아무도 안 쓰는 마켓플레이스를 걷는다. 목록을 밖으로 빼면 그 진실이 비므로 절 전체를 우산에게 넘긴다. 남기는 것은 하드웨어성 키 넷과 남의 것을 보존하는 규율이다.

## disciplined-coder와의 경계

같은 PC에 범용 체계가 하나 더 있다. 둘 다 사용자 폴더의 같은 파일들에 손이 닿으므로 경계를 못 박는다.

**가르는 것은 만지는 자리가 아니라 스크립트의 소유다.** 두 체계가 PC에 남기는 결과는 겹쳐도 된다. 둘 다 `PYTHONUTF8`을 `1`로 세워도 되고, 둘 다 `CLAUDE.md`의 자기 마커 블록을 다시 써도 된다.

**금지하는 것은 런타임에 상대의 스크립트를 부르는 것과 한 파일을 두 레포가 공동 소유하는 것이다.** 사본을 받는 것은 걸리지 않는다. 정본은 한 레포에만 있고 사본은 거기서 만들어진 생성물이며, 받은 쪽 레포 안에서 자기 테스트와 함께 돈다.

겹쳐도 되게 하려면 걸음마다 둘을 지킨다. 멱등이어서 상대가 먼저 돌린 뒤에 돌아도 결과가 같아야 하고, 남이 써 둔 것을 지우지 않아야 한다. 주인 없는 사용자 값(`BASH_DEFAULT_TIMEOUT_MS`)도 건드리지 않는다.

| 무엇 | 우산 | 환경 | disciplined-coder |
|---|---|---|---|
| `~/.claude/CLAUDE.md` | 안 만진다 | `# BEGIN AX 설치` 블록 | `# BEGIN disciplined-coder` 블록 |
| `~/.claude/settings.json` | `extraKnownMarketplaces`, `enabledPlugins` | `hooks`의 옛 도커 항목 | `extraKnownMarketplaces`의 `chshin-tools` |
| `known_marketplaces.json` | 선언의 마켓플레이스 셋 | 안 만진다 | `chshin-tools`, `claude-plugins-official` |
| `HKCU\Environment`의 `PYTHONUTF8` | 안 만진다 | 안 만진다. 설치기가 세운다 | 물어서 세운다 |
| `~/.claude/skills/` | 안 만진다 | 은퇴한 사본을 걷는다 | 안 만진다 |
| `~/.claude/hooks/` | 안 만진다 | 안 만진다 | 안 만진다 |
| 파이썬 라이브러리 | 안 만진다 | 선언대로 깐다 | 안 만진다 |
| 상태 파일 | 없다 | `kw-environment.state` | 자기 이름의 파일 |

`settings.json`의 하드웨어성 키는 설치기만 쓴다. `~/.claude/hooks/`가 비는 것은 훅을 플러그인이 나르기 때문이다.

**이 경계는 약속이 아니라 검사로 지킨다.** 양쪽 테스트가 상대의 자리를 심어 놓고 자기 걸음을 돌린 뒤 그것이 살아남는지 본다.

### 잠금이 없는 자리

`CLAUDE.md`는 `_managed_block.sh` 사본을 쓰므로 두 체계가 같은 잠금 파일을 잡고 서로 배제된다. **`known_marketplaces.json`과 `settings.json`에는 잠금이 없다.** 양쪽 다 잠금 없이 읽고 고쳐 쓰며, `disciplined-coder`의 쓰기는 고정 이름의 임시 파일을 쓴다. 창 둘을 열어 두고 한쪽이 맞춤을 도는 동안 다른 쪽 세션이 시작하면 한쪽 결과가 사라질 수 있다.

멱등은 순차 실행의 성질이라 동시 읽고 쓰기를 막지 못한다. 이것은 완화만 가능하다. 우산이 자기 쓰기를 짧게 유지하고, 잠금을 두자는 제안을 `disciplined-coder` 정본에 올린다. 그쪽이 정본의 주인이므로 결정은 그쪽 몫이다.

## 범용 함수의 사본

**사본은 환경 플러그인에만 둔다.** 우산은 사본이 필요 없다.

| 사본 | 왜 받나 |
|---|---|
| `_managed_block.sh` | `CLAUDE.md`의 마커 블록을 다시 쓴다. **두 체계가 같은 잠금 파일을 잡게 되는 것이 이 사본의 값이다.** 각자 구현하면 잠금 방식이 달라 배제가 아예 안 된다 |
| `_json_valid.sh`, `_resolve_home.sh` | 위 파일이 기대는 것 |

**`_ensure_autoupdate.sh`는 받지 않는다.** 셋을 못 채운다. 마켓플레이스 이름을 플러그인 루트의 `.claude-plugin/marketplace.json`에서 읽는데 우산은 그 자리에 그 파일이 없고, 공개 함수가 어떤 경우에도 0을 돌려주어 무엇을 했는지 알리지 않으며, 내부 종료 코드 `10`이 "항목이 아예 없다"와 "이미 값이 있다"를 함께 덮어 등록과 되켜기를 가를 수 없다. 우산이 자기 코드로 쓴다.

마커는 처음부터 함수 인자였다. 이름표는 `MANAGED_TAG`로 인자화가 끝났고 `source` 앞에 값을 세우면 된다. 함수 시그니처는 그대로다. 첫 판은 마커가 상수라고 잘못 적었다.

사본 규율은 셋이다.

- **사본은 생성물이다.** 손으로 고치지 않는다. 고칠 것이 있으면 정본을 고치고 다시 받는다. 사본 머리에 그 사실과 정본 경로를 적는다.
- **사본 머리에 정본의 커밋 SHA와 파일 해시를 적는다.**
- **낡음 검사는 사본 쪽 테스트에만 둔다.** 정본 레포를 못 찾으면 통과로 끝내지 않고 "대조 불가"로 알린다.

사본을 만드는 것과 낡음을 재는 것은 개발 PC에서만 된다. 사용자 PC에는 정본 레포가 없다. 그래서 사본은 레포에 커밋되어 플러그인과 함께 배포되고, `vendor.sh`는 개발자가 부르는 도구이며, **런타임 훅과 맞춤 스크립트는 사본의 낡음을 재지 않는다.** 재려 하면 매 세션 "대조 불가"가 떠서 알림이 소음이 된다.

정본 레포의 자리는 박아 넣지 않는다. `vendor.sh`와 그 테스트가 환경변수나 인자로 받고 못 찾으면 알린다.

**잠금 규약이 갈리는 위험은 남는다.** 정본이 잠금 규약을 고치고 사본이 옛 판이면 두 체계가 같은 잠금 파일을 잡고도 배제가 깨진다. 사용자 PC에서는 아무도 그것을 재지 않는다. 완화로 정본에 규약 판 번호를 두고 판이 바뀌면 잠금 디렉터리 이름이 바뀌게 하자고 제안한다. 이름이 다르면 규약이 다른 둘이 같은 잠금을 오해할 수 없다.

## 설치기가 바뀌는 것

단계를 다시 매기면 이렇게 된다. 앞에 0단계가 그대로 있고 뒤가 하나 는다.

```
0 사전 점검 -> 1 인증서 -> 2 프로그램 -> 3 PYTHONUTF8 -> 4 클로드 -> 5 PATH
-> 6 터미널 -> 7 배선 -> 8 마켓플레이스 등록과 우산 설치 -> 9 우산 맞춤 -> 10 검증
```

9단계는 우산의 `sync.sh`를 부르고, 그 안에서 환경 플러그인의 `env-sync.sh`가 이어 돈다. 설치기가 끝나면 PC는 지금과 똑같이 완성 상태다.

**bash를 이름으로 부르지 않는다.** 윈도에는 이름이 같은 다른 bash가 있고, WSL의 것이 잡히면 리눅스 쪽 홈에서 돌아 모든 걸음이 실패한다. 설치기는 이미 파이썬과 pwsh를 절대 경로로 못 박아 찾으므로 bash에도 같은 규율을 적용한다. Git 설치 경로의 bash를 찾고 못 찾으면 9단계를 건너뛰고 경고를 남긴다.

**선언을 못 읽으면 9단계를 통째로 건너뛴다.** 백업 목록을 설치기에 두지 않는다. 같은 사실이 두 곳에 남으면 곧 어긋난다. 무엇을 못 했는지 경고로 남기고 인증서를 고쳐 다시 돌리게 한다. 설치기는 멱등이라 재실행이 안전하다.

## 이행

네 걸음이다. 걸음마다 이 PC에서 실제로 돌려 보고, 되돌리는 길을 함께 적는다.

**첫째, `kw-plugins` 레포를 세운다.** 마켓플레이스와 플러그인 둘과 스크립트들을 만든다. `kw_install`은 손대지 않는다. `--plugin-dir`로 얹어 훅 셋과 맞춤 명령 둘이 실제로 도는 것을 본다.

이 걸음에서 **설치기와 환경 플러그인이 `CLAUDE.md`를 함께 쓰게 된다.** 첫 판은 "겹칠 뿐 해가 없다"고 적었는데 틀렸다. 매칭 규칙이 다르고(설치기는 접두 정규식, 사본은 전체 줄 일치) 직렬화 수단도 다르다. 설치기는 PowerShell이라 사본이 잡는 잠금을 모른다. 이 PC에 `CLAUDE.md.pre-dedup`이 남아 있어 같은 종류의 중복이 이미 한 번 일어났다. 그래서 **첫째 걸음에서는 환경 플러그인의 `CLAUDE.md` 걸음을 끄고 시험한다.** 켜는 것은 셋째 걸음에서 설치기의 해당 코드를 걷어낸 뒤다.

되돌리기는 로컬 커밋을 지우는 것뿐이다.

**둘째, 설치기를 얇게 만든다.** 옮겨 간 것을 걷어내고 8·9단계를 새로 쓰며 `Merge-ClaudeSettings`의 플러그인 절을 걷는다. `CLAUDE.md` 문안과 스킬 복사와 도커 훅 등록도 이때 걷는다. 되돌리기는 커밋 되돌리기다.

**셋째, 환경 플러그인의 `CLAUDE.md` 걸음을 켠다.** 그 전에 마커를 한 번 정규화한다. `kw_install`은 마커를 접두 정규식으로 찾아 왔고 괄호 안 문구를 바꿔도 살아남게 하려던 것이라고 `setup.ps1:1616`의 주석이 적는다. 받아 오는 사본은 전체 줄 일치로 찾으므로, 옛 판이 찍은 괄호 문구가 다르면 블록을 못 찾고 하나 더 붙인다. **되돌릴 수 없는 걸음이라 정규화 전에 `CLAUDE.md.pre-normalize` 사본을 뜬다.**

**넷째, 발행처를 옮긴다.** `kiwoom-ax`가 `kw-doc-formats`를 발행하게 하고, 각 PC에 새 선언이 도착해 옛 등록이 걷힌 뒤에 `KW-doc-formats` 레포의 마켓플레이스 파일을 지운다.

**순서가 첫 판과 반대다.** 첫 판은 발행처 이전을 둘째에 두었는데, 옛 등록을 걷는 것은 우산이고 우산은 셋째 걸음의 새 설치기가 깐다. 걷어낼 주체가 대상보다 늦게 도착한다. 그 사이에 마켓플레이스 파일이 사라지면 이미 깔린 PC가 세션 시작에 그것을 먼저 만나 사내 문서 스킬이 통째로 사라지고, 우산이 없어 복구할 수도 없다. **파일을 지우는 것은 되돌릴 수 있지만 사라진 스킬은 그 PC에서 되돌릴 수 없다.** 그 비대칭이 순서를 정한다.

## 테스트

`kw-plugins` 레포의 테스트가 본다.

- **선언 읽기** — 형식이 아니거나 읽지 못하면 멈춘다.
- **우산의 훅** — 선언과 `installed_plugins.json`이 맞으면 아무 말도 안 한다. 빠진 것이 있으면 낸다. 은퇴한 것이 남아 있으면 낸다. 자동 갱신이 꺼졌으면 낸다. 파일이 깨져 있어도 세션을 막지 않는다.
- **우산의 맞춤** — 두 번 돌려도 결과가 같다. 되켜는 것이 `kiwoom-ax` 하나다. 남이 `false`로 둔 것이 살아남는다. 되켠 것이 요약에 나온다.
- **환경의 훅** — 판본이 같으면 조용하고 다르면 낸다. 상태 파일이 없으면 낸다.
- **환경의 맞춤** — 두 번 돌려도 결과가 같다. 걸음 하나가 실패하면 **상태를 안 적는다.** `CLAUDE.md`의 마커 바깥이 살아남는다. 은퇴 스킬 삭제의 가드 셋이 걸린다.
- **`python3` 가드** — `python3`과 `python3.exe`를 막고 `python`과 `py -3`은 안 막는다.
- **사본** — 낡음 검사가 정본과 대조한다. 정본 레포를 못 찾으면 통과가 아니라 "대조 불가"다. 이름표를 갈아 끼운 것이 메시지에만 걸린다.
- **경계** — `chshin-tools` 항목과 `# BEGIN disciplined-coder` 블록을 심어 놓고 자기 걸음을 돌린 뒤 그것이 글자 그대로 살아남는지 본다.

멱등은 같은 프로세스가 아니라 **새 프로세스에서** 잰다. 같은 프로세스 안에서만 재면 매 실행 파일을 다시 쓰는 결함을 못 본다. `kw_install` 테스트에 그 자리가 있고 같은 규율을 가져온다.

`kw_install` 쪽 테스트는 옮겨 간 것을 검사하던 자리를 지우고, 9단계가 bash를 절대 경로로 찾아 스크립트를 부르는지 검사하는 자리를 더한다.

## 남는 위험

- **우산 하나가 단일 실패점이다.** 우산이 안 깔리면 사내 것 전부가 안 온다. 설치기가 우산 설치 실패를 경고가 아니라 실패로 다루고, 이미 깐 것은 그대로 돈다.
- **무엇도 잠글 수 없다.** 사용자가 자동 갱신을 끄거나 플러그인을 지우면 이 장치가 멈춘다. 관리 설정이 생기기 전까지 조용히 못 끄게 하는 것이 최선이다.
- **`known_marketplaces.json`과 `settings.json`에 잠금이 없다.** 동시에 쓰면 한쪽 결과가 사라질 수 있다. 완화만 가능하다.
- **마켓플레이스 클론과 플러그인 캐시가 다른 시점에 갱신될 수 있다.** 설치기는 클론의 선언을 읽고 훅은 캐시의 선언을 읽는다. 우산의 훅이 해시가 아니라 실물을 재게 한 것이 이 위험을 줄이지만 없애지는 않는다.
- **사본의 잠금 규약이 갈리면 배제가 깨진다.** 사용자 PC에서는 아무도 재지 않는다.
- **9단계가 Git Bash에 의존한다.** winget이 실패한 PC에서는 git이 없어 그 단계가 못 돈다. 경고를 남기고 재실행을 안내한다.
- **레포가 셋이 되어 이름이 어긋날 수 있다.** 세 레포를 잇는 검사가 없다.

## 하지 않는 것

- 관리 설정을 쓰지 않는다. 배포 수단이 없다.
- 훅이 설치하거나 파일을 고치지 않는다.
- 백업 목록을 설치기에 두지 않는다.
- `KW-doc-formats`의 스킬 내용을 손대지 않는다. 발행처만 옮긴다.
- 설치기의 0·1·2·4·5·6단계를 손대지 않는다.
- 선언에 판 번호를 두지 않는다.

## 이 설계에 흡수되는 것

`python3` 호출을 막는 훅을 `kw_install`에 넣기로 했던 앞선 결정은 환경 플러그인으로 온다. 호출을 거부하고 이유를 돌려준다.

**끄는 스위치를 두지 않는다.** 사용자 확정이다. 이 이름은 파이썬이 아니라 마이크로소프트 스토어로 보내는 안내판이라 부를 이유 자체가 없고, 이름을 정확히 부르는 것을 막는 데에는 거짓 양성이 없다. `python`과 `py -3`은 막지 않는다. `disciplined-coder`가 이 가드를 사본으로 가져갈 때 스위치를 붙일지는 그쪽 정본의 결정이고, 그쪽은 맥과 리눅스를 함께 보므로 판단이 다를 수 있다.
