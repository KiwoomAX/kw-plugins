# 사내 컨트롤 타워 설계 (2026-09-06)

설치기 하나가 PC를 세우고, 그 뒤로 사내 플러그인과 라이브러리와 문안이 자라는 것은 우산 플러그인 하나가 끌고 간다.

## 목적

사내 플러그인을 앞으로 여럿 만든다. 지금 구조에서는 새 플러그인이 하나 생길 때마다 `kw_install`의 `$script:Plugins` 표를 고치고 모든 PC에서 설치기를 다시 돌려야 한다. 목록이 설치기 안에 있기 때문이다.

목록을 설치기 밖으로 꺼내 한 곳에 두고, 각 PC가 그 한 곳을 계속 바라보게 만든다. 그러면 새 플러그인을 더하는 일이 커밋 하나가 되고, 각 PC는 다음 세션에 그것을 듣는다.

옮기는 것은 플러그인 목록만이 아니다. 파이썬 라이브러리와 `CLAUDE.md`의 개인 문안과 사내 스킬처럼 **목록이 자라는 것 전부**가 대상이다.

## 딛고 선 측정

이 PC에서 잰 것이다.

| 무엇 | 값 |
|---|---|
| 마켓플레이스 클론의 자리 | `~/.claude/plugins/marketplaces/<이름>/` 아래에 레포 전체가 그대로 있다. `kw-doc-formats` 아래에 `README.md` `docs` `skills` `tests`가 보인다 |
| 플러그인 사본의 자리 | `~/.claude/plugins/cache/<마켓플레이스>/<플러그인>/<판본>`. `installed_plugins.json`의 `installPath`가 가리킨다 |
| 자동 갱신 값이 사는 곳 | `~/.claude/plugins/known_marketplaces.json`. `kw-doc-formats`에 `autoUpdate: true`가 들어 있다 |
| `settings.json`의 같은 항목 | `extraKnownMarketplaces`의 `kw-doc-formats`에는 `autoUpdate`가 **없다.** 두 자리가 어긋나 있다 |
| 관리 설정 | 없다. 회사가 각 PC에 정책을 뿌릴 수단이 없다고 사용자가 답했다 |
| 설치기가 지금 나르는 것 | 플러그인 다섯과 은퇴 목록 둘, 라이브러리 여덟(`requirements.txt`), 개인 문안(`templates/personal-memory-ko.md`), 스킬 하나(`skills/register-corp-certs`), 도커 훅 하나(`hooks/docker-cert-reminder.ps1`) |
| `settings.json`의 기록자 | `Merge-ClaudeSettings` 하나뿐이다. 자동 갱신은 `Set-MarketplaceAutoUpdate`가 레지스트리에 따로 넣는다 |

## 왜 관리 설정이 아닌가

클로드 코드에는 이 일을 위해 마련된 자리가 이미 있다. 관리 설정은 사용자 설정보다 위에 있어 사용자가 못 지우고, `extraKnownMarketplaces`와 `enabledPlugins`와 `claudeMd`와 `pluginSuggestionMarketplaces`를 담는다. 그것이 정공법이다.

쓰지 않는 이유는 배포 수단이 없기 때문이다. 관리 설정은 조직 계정의 서버나 `HKLM\SOFTWARE\Policies\ClaudeCode`나 `C:\Program Files\ClaudeCode\managed-settings.json`에서 오고, 뒤의 둘은 관리자 권한과 배포 장치를 요구한다. 사용자 권한만 있는 조건이므로 같은 일을 플러그인으로 흉내 낸다.

**그래서 무엇도 잠글 수 없다.** 이 설계가 만드는 것은 "못 끄게"가 아니라 "조용히 못 끄게"다. 이 한계는 아래 「남는 위험」에 다시 적는다.

## 결정한 것

| 항목 | 결정 | 근거 |
|---|---|---|
| 우산의 형태 | 플러그인 | 스킬은 훅을 등록하지 못하고, 개인 스킬 폴더의 사본은 스스로 갱신되지 않는다 |
| 레포 구조 | 새 레포가 마켓플레이스와 우산만 담고, 사내 플러그인은 각자 레포에 남는다 | 각 플러그인이 자기 spec과 검진 기록과 테스트를 자기 레포에 계속 갖는다. `KW-doc-formats`를 옮기지 않아도 된다 |
| 이름 | 마켓플레이스 `kiwoom-ax`, 레포 `KiwoomAX/kw-plugins`, 우산 `kw-control-tower` | 마켓플레이스 이름이 `플러그인@마켓플레이스` 꼴로 눈에 뜬다. 조직을 가리켜야 앞으로 몇이 더 붙어도 읽힌다 |
| 선언의 자리 | 우산 플러그인 안에 파일 하나 | 훅은 `${CLAUDE_PLUGIN_ROOT}`로, 설치기는 마켓플레이스 클론 안의 같은 파일로 닿는다. 파일 하나에 경로 둘이고 선언이 우산의 판본과 함께 움직인다 |
| 선언이 담는 것 | 목록이 아니라 가리킴 | `requirements.txt`의 주석에 판 제약의 이유가 적혀 있다. JSON 배열로 옮기면 그 이유가 사라진다 |
| 설치 직후의 상태 | 설치기가 지금처럼 한 번에 완성한다 | 우산은 설치기가 못 한 것을 맡는 것이 아니라, 설치기가 끝낸 뒤 시간이 지나며 어긋나는 것을 맡는다 |
| 훅이 하는 일 | 알리기만 한다 | 사용자 파일을 고치는 일을 묻지 않고 하지 않는다 |
| 훅이 재는 것 | 선언의 해시와 자동 갱신 값 둘뿐 | 라이브러리를 실제로 세면 매 세션 `pip`이 돈다. 파일 읽기 둘이면 세션 시작이 느려지지 않는다 |
| 고치는 것 | `/kw-sync` 하나 | 고치는 자리가 하나여야 무엇이 언제 바뀌었는지 셀 수 있다 |
| 자동 갱신이 꺼져 있으면 | 훅이 알리고 `/kw-sync`가 되켠다. **되켜는 것은 `kiwoom-ax` 하나다** | 사용자 값을 몰래 덮지 않는다. `PYTHONUTF8`에서 내린 결정과 결이 같다 |
| 남의 마켓플레이스의 자동 갱신 | 키가 없을 때만 넣고, `false`로 둔 것은 그대로 둔다 | 우리 것이 아니다. 사용자가 일부러 끈 것을 매번 되켜면 끄는 길이 없어진다 |
| 진실의 자리 | `known_marketplaces.json` | 클로드 코드가 실제로 읽는 파일이다. `settings.json`의 선언과 어긋나면 이쪽을 따른다 |
| 두 소비자의 공통 구현 | 스크립트 하나 | 설치기의 마지막 단계와 `/kw-sync`가 같은 스크립트를 부른다. 같은 일을 두 벌로 쓰지 않는다 |

## 경계

나누는 기준은 하나다. **이 PC의 하드웨어와 사내망과 레지스트리에 매인 것은 설치기에 남고, 목록이 자라는 것은 우산으로 간다.**

| 지금 자리 | 무엇 | 어디로 | 왜 |
|---|---|---|---|
| 0단계 | pwsh 판과 payload와 winget 점검 | 설치기 | 클로드가 아직 없는 시점의 일이다 |
| 1단계 | CA 번들과 인증서 환경변수 넷 | 설치기 | 사내망과 레지스트리에 매였다 |
| 2단계 | Python 3.12와 git과 Node와 Poppler | 설치기 | winget과 관리자성 설치다 |
| 3단계 | `PYTHONUTF8` | 설치기 | 레지스트리다 |
| 3단계 | `requirements.txt`의 라이브러리 여덟 | 우산 | 새 플러그인이 새 라이브러리를 부른다 |
| 4단계 | 클로드 코드 설치 | 설치기 | 부트스트랩이다 |
| 5단계 | 사용자 PATH | 설치기 | 레지스트리다 |
| 6단계 | 윈도우 터미널 글꼴 | 설치기 | 이 PC의 터미널 설정 파일이다 |

| 7단계 | 도커 인증서 훅 | 우산 | 사내 인증서 지식이고 스킬과 함께 움직인다 |

| 8단계 | 플러그인 다섯과 은퇴 목록 | 우산 | 이 작업의 출발점이다 |
| 8단계 | 사내 마켓플레이스 등록과 우산 설치 | 설치기 | 부트스트랩이다. 우산이 자기를 깔 수는 없다 |
| 9단계 | HTTPS 검증 | 설치기 | 1단계가 된 것을 확인하는 짝이다 |

## disciplined-coder와의 경계

같은 PC에 범용 체계가 하나 더 있다. `disciplined-coder`가 자기 요건을 점검하고 갱신하는 장치를 갖는다. 둘 다 사용자 폴더의 같은 파일들에 손이 닿으므로 경계를 먼저 못 박는다.

**가르는 것은 만지는 자리가 아니라 스크립트의 소유다.** 두 체계가 PC에 남기는 결과는 겹쳐도 된다. 둘 다 `PYTHONUTF8`을 `1`로 세워도 되고, 둘 다 `CLAUDE.md`의 자기 마커 블록을 다시 써도 된다. 멱등이면 나중에 도는 쪽이 앞의 결과를 그대로 두거나 같은 값으로 다시 쓸 뿐이다.

**금지하는 것은 한 스크립트를 두 체계가 함께 갖는 것이다.** 우산의 스크립트를 `disciplined-coder`가 런타임에 부르거나 그 반대이거나, 같은 파일을 두 레포가 공동으로 소유하는 것을 하지 않는다. 그렇게 하면 한쪽 레포의 변경이 다른 쪽을 말없이 바꾸고, 어느 레포의 테스트도 그것을 못 잡는다.

**사본을 받는 것은 이 금지에 걸리지 않는다.** 정본은 한 레포에만 있고 사본은 거기서 만들어진 생성물이며, 받은 쪽 레포 안에서 자기 테스트와 함께 돈다. 런타임에 상대 레포가 있어야 할 이유가 없고 소유자도 하나다. 어떻게 받고 낡음을 어떻게 재는지는 아래 「범용 함수의 사본」이 정한다.

`kw_install` 계열 안에서는 반대다. 설치기와 우산은 한 체계이므로 스크립트를 하나만 둔다. 설치기의 마지막 단계가 우산의 `sync.ps1`을 부르는 것이 그 계열의 정본을 하나로 지키는 방법이다.

겹쳐도 되게 하려면 걸음마다 두 가지를 지켜야 한다.

- **멱등이다.** 두 번 돌려도 결과가 같고, 상대가 먼저 돌린 뒤에 돌아도 결과가 같다.
- **남이 써 둔 것을 지우지 않는다.** `CLAUDE.md`는 자기 마커 블록 바깥을 그대로 옮겨 담고, `settings.json`은 자기 키만 쓰고 나머지를 있는 그대로 둔다. 주인 없는 사용자 값(`BASH_DEFAULT_TIMEOUT_MS` 같은 것)도 건드리지 않는다.

| 무엇 | 우산 | disciplined-coder |
|---|---|---|
| `~/.claude/CLAUDE.md` | `# BEGIN AX 설치` 블록 | `# BEGIN disciplined-coder` 블록 |
| `~/.claude/settings.json` | `extraKnownMarketplaces`의 `kiwoom-ax` 항목 | `chshin-tools` 항목 |
| `~/.claude/plugins/known_marketplaces.json` | `kiwoom-ax`와 공식 둘의 `autoUpdate` | `chshin-tools`와 `claude-plugins-official`의 `autoUpdate` |
| `HKCU\Environment`의 `PYTHONUTF8` | 설치기가 세운다 | 물어서 세운다. 값이 같아 겹쳐도 된다 |
| `~/.claude/skills/` | 은퇴한 사본을 걷는 것뿐 | 건드리지 않는다 |
| `~/.claude/hooks/` | 건드리지 않는다 | 건드리지 않는다 |
| 파이썬 라이브러리 | 선언대로 깐다 | 깔지 않는다 |
| 상태 파일 | `kw-control-tower.state` | 자기 이름의 파일 |
| 스크립트 | 자기 레포 것만 | 자기 레포 것만 |

`settings.json`의 하드웨어성 키(PowerShell 도구, 기본 셸, 권한 모드)는 설치기만 쓴다.

`~/.claude/hooks/`가 비는 것은 훅을 플러그인이 나르기 때문이다. 도커 훅과 `python3` 훅이 우산 안으로 들어오면 사용자 폴더에 훅 파일을 놓을 이유가 없어진다.

**이 경계는 약속이 아니라 검사로 지킨다.** 양쪽 테스트가 상대의 자리를 심어 놓고 자기 걸음을 돌린 뒤 그것이 살아남는지 본다. `kw_install`의 「somebody else hook survives」와 「their ask list is left exactly as found」가 이미 그 꼴이다.

## 순서

선언이 마켓플레이스 클론 안에 있으므로 등록 전에는 읽을 수 없다. 지금 3단계에 있는 `pip install`이 뒤로 밀린다. 단계를 다시 매기면 이렇게 된다.

```
1 인증서 -> 2 프로그램 -> 3 PYTHONUTF8 -> 4 클로드 -> 5 PATH -> 6 터미널
-> 7 배선 -> 8 마켓플레이스 등록과 우산 설치 -> 9 선언대로 나머지 -> 10 검증
```

9단계는 우산이 나르는 동기화 스크립트를 그대로 부른다.

**이 순서가 낳는 새 실패 모드는 실패의 전파다.** 지금은 마켓플레이스 클론이 깨져도 라이브러리는 이미 깔려 있었는데, 이제는 클론이 깨지면 라이브러리까지 못 깐다. 대비로 백업 목록을 설치기에 두지 않는다. 그러면 같은 사실이 두 곳에 남아 곧 어긋난다. 선언을 못 읽으면 9단계를 통째로 건너뛰고 무엇을 못 했는지 경고로 남긴 뒤, 인증서를 고치고 다시 돌리게 한다. 설치기는 멱등이라 재실행이 안전하다.

## 선언 파일

우산 플러그인 안에 `manifest.json` 하나를 둔다.

```json
{
  "schema": 1,
  "plugins": [
    { "id": "superpowers@claude-plugins-official", "marketplaceRepo": "anthropics/claude-plugins-official", "autoUpdate": true },
    { "id": "document-skills@anthropic-agent-skills", "marketplaceRepo": "anthropics/skills", "autoUpdate": true },
    { "id": "playwright@claude-plugins-official", "marketplaceRepo": "anthropics/claude-plugins-official", "autoUpdate": true },
    { "id": "frontend-design@claude-plugins-official", "marketplaceRepo": "anthropics/claude-plugins-official", "autoUpdate": true },
    { "id": "kw-doc-formats@kiwoom-ax", "marketplaceRepo": "KiwoomAX/kw-plugins", "autoUpdate": true }
  ],
  "retiredPlugins": [ "kw-doc-formats@kw-doc-formats", "superpowers@superpowers-marketplace" ],
  "retiredSkills": [ "document-formats" ],
  "pythonRequirements": "requirements.txt",
  "claudeMdBlock": "templates/personal-memory-ko.md"
}
```

**남의 플러그인도 여기 적는다.** 지금 설치기의 `$script:Plugins`가 공식 넷과 사내 하나를 함께 들고 있고, 그 목록이 자라는 것이 이 작업의 출발점이다. 사내 것만 옮기면 설치기를 고쳐야 하는 이유가 그대로 남는다.

`marketplaceRepo`는 플러그인이 사는 레포가 아니라 **마켓플레이스를 등록할 때 넘길 레포**다. `claude plugin marketplace add`가 받는 값이 그것이다. `kw-doc-formats` 플러그인의 소스는 `KW-doc-formats` 레포에 있지만, 그것을 발행하는 마켓플레이스는 `kw-plugins`다.

### 자동 갱신을 어디까지 켜나

**사내 것과 공식 것을 켠다.** `kiwoom-ax`와 `claude-plugins-official`과 `anthropic-agent-skills`다. 그 밖의 개인·외부 마켓플레이스는 지금처럼 둔다. 남의 회귀를 사내 PC 전부가 같은 날 함께 받는 것을 공식 것에 한해 받아들인다는 뜻이다.

이 PC에서 잰 지금 상태는 이렇다. 켜진 것이 `chshin-tools`와 `claude-community`와 `im-not-ai`와 `kw-doc-formats` 넷이고, **꺼진 것이 다섯**이다. `claude-plugins-official`과 `anthropic-agent-skills`와 `superpowers-marketplace`와 `claude-code-plugins`와 `karpathy-skills`다. 설치기의 플러그인 표에서 `AutoUpdate`가 붙은 것이 `kw-doc-formats` 하나뿐이라, 지금은 `superpowers`와 `document-skills`와 `frontend-design`과 `playwright`의 고침이 자동으로 오지 않는다.

`chshin-tools`는 켜져 있지만 우산이 건드리지 않는다. `disciplined-coder`가 자기 것으로 관리하며, 그것이 경계 합의다.

자동 갱신이 하는 일과 안 하는 일을 갈라 둔다. **이미 깔린 플러그인을 갱신할 뿐 새로 깔지 않는다.** 그래서 선언에 새 플러그인이 들어오는 것, 은퇴한 것을 걷어내는 것, 라이브러리와 문안과 옛 스킬 사본은 모두 훅이 알리고 `/kw-sync`가 고치는 쪽에 남는다.

`schema`는 판 번호다. 읽는 쪽이 모르는 판을 만나면 멈추고 알린다. 옛 설치기를 든 PC가 새 선언의 모르는 필드를 조용히 지나가는 것을 막는다.

`register-corp-certs` 스킬은 목록에 적지 않는다. 우산 플러그인이 자기 `skills/`에 담으면 배포가 끝나므로 개인 스킬 폴더에 복사할 일 자체가 없어진다.

## 우산이 나르는 것

우산은 레포 루트가 아니라 `plugins/kw-control-tower/` 아래에 산다. 루트를 플러그인으로 삼으면 이 마켓플레이스가 다른 플러그인을 담을 수 없다. 그래서 설치기가 부를 스크립트의 자리가 `~/.claude/plugins/marketplaces/kiwoom-ax/plugins/kw-control-tower/scripts/sync.ps1`로 정해진다.

| 이름 | 무엇 |
|---|---|
| `manifest.json` | 선언 |
| `requirements.txt` | 파이썬 라이브러리 목록이며 `kw_install`에서 옮겨 온다 |
| `templates/personal-memory-ko.md` | `CLAUDE.md`에 넣을 관리 블록이며 `kw_install`에서 옮겨 온다 |
| `scripts/sync.sh` | 실제로 고치는 스크립트다. `/kw-sync`와 설치기 9단계가 같이 부른다 |
| `hooks/session-check.sh` | 세션 시작 훅이다. 해시와 자동 갱신 값을 보고 알리기만 한다 |
| `scripts/vendor/` | `disciplined-coder`에서 받은 사본 넷. 손으로 고치지 않는다 |
| `hooks/docker-cert-reminder.ps1` | `kw_install`에서 옮겨 온다 |
| `skills/kw-sync/` | `/kw-sync` 스킬이다. 스크립트를 부르고 결과를 사람 말로 옮긴다 |
| `skills/register-corp-certs/` | `kw_install`에서 옮겨 온다 |

**고치는 일을 스킬 문서로 적지 않고 스크립트로 둔다.** 스킬 문서로만 두면 매 회차 다르게 실행되어 멱등을 지킬 수 없고 테스트할 것도 남지 않는다.

**우산의 스크립트는 셸로 쓴다.** 클로드 코드 훅의 관례가 bash이고, `disciplined-coder`와 사본을 주고받으려면 언어가 같아야 한다. **설치기는 PowerShell 그대로 둔다.** 레지스트리와 winget과 터미널 설정은 PowerShell이 맞고 이미 테스트가 두껍게 붙어 있다. 그래서 두 언어가 만나는 자리는 설치기 9단계가 `sync.sh`를 한 번 부르는 곳 하나뿐이다.

## 범용 함수의 사본

`disciplined-coder`가 클로드 코드를 건드리는 범용 함수 넷을 이미 갖고 있고 계약 테스트도 붙어 있다. 다시 짜지 않고 사본으로 받는다. **정본은 `disciplined-coder`가 갖고 우산은 사본을 나른다.**

| 사본 | 계약 | 상태 |
|---|---|---|
| `_json_valid.sh` | `json_run <파이썬 프로그램> [인자...]`. 파이썬을 고르고 `PYTHONUTF8=1`을 앞에 세운다 | 그대로 받는다 |
| `_resolve_home.sh` | `resolve_home claude`가 설정 홈을 돌려준다 | 그대로 받는다 |
| `_ensure_autoupdate.sh` | `ensure_marketplace_autoupdate <설정홈> <플러그인루트>`. 마켓플레이스 이름은 그 루트의 `marketplace.json`에서 읽는다. 종료 코드 `0`은 고쳤다, `10`은 고칠 것이 없다, `3`은 이름이 없다, `4`는 파이썬이 없다, `5`는 읽었으나 못 썼다 | 그대로 받되 **되켜기는 못 한다** |
| `_managed_block.sh` | 마커 사이만 교체하고 바깥을 보존한다. 잠금을 잡고 CRLF에 내성이 있으며 고아 BEGIN을 중화한다 | **마커가 상수로 박혀 있어 인자로 빼는 리팩터를 기다린다** |

반대 방향으로 이쪽이 주는 것은 셋이다. `PYTHONUTF8`을 재는 법(변수를 비운 자식에서 `locale.getpreferredencoding(False)`를 묻는다), 새 프로세스에서 멱등을 재는 검사, `python3` 가드다.

**`_ensure_autoupdate.sh`의 `10`은 "키가 없어서 넣었다"의 반대가 아니라 "키가 있으니 값이 무엇이든 물러난다"이다.** `disciplined-coder`는 자기 마켓플레이스도 되켜지 않는 규율이라 그렇게 만들어져 있다. 이 설계는 `kiwoom-ax`를 되켜기로 했으므로, 사본은 "없으면 넣는다"까지만 쓰고 **되켜기는 우산이 자기 코드로 한 겹 얹는다.** 사본을 고쳐 쓰지 않는다. 규율이 갈리는 자리라 어느 쪽도 틀리지 않았다. 그쪽은 범용 플러그인이라 사용자 결정을 뒤집지 않고, 이쪽은 사내 PC를 세우는 체계라 회사가 켠 것이 꺼졌으면 되켠다.

되켤 때는 무엇을 되켰는지 `/kw-sync`의 요약에 적는다. 사용자가 일부러 끈 것을 다른 볼일로 명령을 돌리다 되살리는 일이 생길 수 있는데, 적으면 몰래가 아니다.

사본 규율은 셋이다.

- **사본은 `generated`다.** 손으로 고치지 않는다. 고칠 것이 있으면 정본을 고치고 다시 받는다. 사본 머리에 그 사실과 정본 경로를 적는다.
- **사본 머리에 정본의 커밋 SHA와 파일 해시를 적는다.** 검사가 그 값으로 낡음을 잰다.
- **낡음 검사는 사본을 가진 쪽이 갖고, 테스트에만 둔다.** 정본 레포가 그 PC에 없으면 조용히 통과시키지 않고 "대조 불가"로 알린다. 통과로 끝내면 낡은 사본이 아무 표시 없이 돈다.

사본을 만드는 것과 낡음을 재는 것은 **개발 PC에서만** 된다. 둘 다 정본 레포가 있어야 하는데 사용자 PC에는 없다. 그래서 사본은 이 레포에 커밋되어 플러그인과 함께 배포되고, `scripts/vendor.sh`는 개발자가 부르는 도구이며, 낡음 검사는 테스트 안에만 산다. **런타임 훅과 `sync.sh`는 사본의 낡음을 재지 않는다.** 재려 하면 사용자 PC에서 매 세션 "대조 불가"가 떠서 알림이 소음이 된다. 사본은 우산의 판본과 함께 오므로 런타임에 잴 것이 없다.

정본 레포의 자리는 박아 넣지 않는다. `vendor.sh`와 그 테스트가 환경변수나 인자로 받고, 못 찾으면 그 사실을 알린다.

**사본을 받는 실질 이득이 잠금에 있다.** `_managed_block.sh`의 잠금 경로는 마커가 아니라 대상 파일에서 나온다(`lock="$uc.lock"`). 그래서 우산이 이 사본으로 `~/.claude/CLAUDE.md`를 고치면 `disciplined-coder`와 **같은 잠금 파일**을 잡고, 두 체계가 같은 순간에 그 파일을 쓰려 해도 서로 배제된다. 각자 따로 구현했다면 잠금 방식이 달라 배제가 안 된다. 낡은 잠금을 회수하는 시간과 총 대기가 같은 값이 되는 것도 같은 이유로 값이 있다.

사본이 쓰는 이름표는 인자로 받는다. 고아 마커 주석과 경고 문구 넷이 정본의 이름을 물고 있어, 그대로 쓰면 우산이 고친 블록의 경고가 `disciplined-coder` 이름으로 찍힌다. 마커 자체는 이미 인자라 손댈 것이 없다.

## 훅의 계약

세션 시작 훅은 파일 둘을 읽고 그 자리에서 끝난다.

- 선언의 해시가 `~/.claude/kw-control-tower.state`에 적힌 값과 다르면 "사내 선언이 바뀌었다, `/kw-sync`를 돌려라"를 낸다.
- `known_marketplaces.json`에서 `kiwoom-ax`의 `autoUpdate`가 참이 아니거나 항목이 없으면 그것을 알린다.
- 둘 다 이상이 없으면 아무 말도 하지 않는다.
- 어떤 경우에도 파일을 고치지 않고, 어떤 경우에도 세션을 막지 않는다. 스스로 실패하면 조용히 물러난다.

상태 파일은 `/kw-sync`가 쓴다. 훅은 읽기만 한다.

## `/kw-sync`의 걸음

여섯이고 각각 독립이며 멱등이다. 하나가 실패해도 나머지는 돈다.

1. 마켓플레이스 등록을 확인하고 없으면 등록한다. 자동 갱신이 꺼져 있으면 되켠다.
2. 선언의 플러그인을 깔고 은퇴 목록에 있는 것을 걷어낸다.
3. 파이썬 라이브러리를 고정한 3.12에 맞춘다.
4. `CLAUDE.md`의 관리 블록을 다시 쓴다. 마커 바깥은 건드리지 않는다.
5. 개인 스킬 폴더의 은퇴한 사본을 걷어낸다.
6. 무엇을 했는지 요약하고 새 해시를 상태 파일에 적는다.

설치기의 9단계는 이 스크립트를 부르는 자리가 된다.

## 이행

레포 셋을 한 번에 고치지 않는다. 세 걸음으로 나누고 걸음마다 이 PC에서 실제로 돌려 본다.

첫째 걸음은 `kw-plugins` 레포를 세우는 것이다. 마켓플레이스와 우산과 선언과 스크립트 둘을 만들고, `kw_install`은 손대지 않는다. 이 시점에는 우산이 깔려도 하는 일이 설치기와 겹칠 뿐 해가 없다. `--plugin-dir`로 얹어 훅과 `/kw-sync`가 실제로 도는 것을 본다.

둘째 걸음은 발행처를 옮기는 것이다. `kiwoom-ax`가 `kw-doc-formats`를 발행하게 하고 `KW-doc-formats` 레포의 마켓플레이스 파일을 지운다.

셋째 걸음은 `kw_install`을 얇게 만드는 것이다. 옮겨 간 것을 걷어내고 8단계와 9단계를 새로 쓴다. 앞의 두 걸음이 서 있어야 이 걸음이 안전하다.

`CLAUDE.md`의 AX 블록을 한 번 정규화한다. `kw_install`은 마커를 접두 정규식(`^#\s*BEGIN AX\b`)으로 찾아 왔고, 누가 괄호 안 문구를 바꿔도 살아남게 하려던 것이라고 주석에 적혀 있다. 받아 오는 사본은 **전체 줄 일치**로 찾는다. 그래서 옛 판이 찍은 블록의 괄호 문구가 지금과 다르면 우산이 그것을 못 찾고 블록을 하나 더 붙인다. 이행할 때 접두로 찾아 한 번 정규화하고, 그 뒤로 마커 문자열을 상수로 고정해 다시 바꾸지 않는다.

옛 마켓플레이스 `kw-doc-formats`를 은퇴시키고 `kiwoom-ax`로 옮긴다. 두 마켓플레이스가 같은 플러그인을 각각 내면 한 PC에 같은 스킬이 두 벌 실린다. `superpowers`에서 겪은 일이고 설치기 주석에 남아 있다.

옮기는 방법은 새 마켓플레이스의 항목이 `KW-doc-formats` 레포를 가리키게 하고, `KW-doc-formats` 레포의 `.claude-plugin/marketplace.json`을 지워 발행처를 하나로 만드는 것이다. 옛 등록은 선언의 `retiredPlugins`가 걷어낸다.

## 테스트

새 레포의 테스트가 스크립트 둘을 본다.

- 선언을 읽는 것은 모르는 `schema` 판이면 멈추고, 가리킨 파일이 없어도 멈춘다.
- 훅은 해시가 같으면 아무 말도 안 하고 다르면 낸다. 자동 갱신이 꺼졌으면 낸다. 파일이 깨져 있어도 세션을 막지 않는다.
- 동기화는 두 번 돌려도 결과가 같다. 걸음 하나가 실패해도 나머지가 돌고, `CLAUDE.md`의 마커 바깥이 살아남는다.

`kw_install` 쪽 테스트는 옮겨 간 것을 검사하던 자리를 지우고, 9단계가 스크립트를 부르는지 검사하는 자리를 더한다.

## 남는 위험

- **우산 하나가 단일 실패점이다.** 우산이 안 깔리면 사내 것 전부가 안 온다. 설치기가 우산 설치 실패를 경고가 아니라 실패로 다루고, 이미 깐 것은 그대로 돈다.
- **갱신할 때는 선언이 라이브러리보다 먼저 도착한다.** 마켓플레이스가 세션 시작에 갱신되므로, 새 선언이 새 라이브러리를 요구하는 날에는 선언은 왔는데 라이브러리는 없는 세션이 반드시 한 번 있다. 순서로 피할 수 없고, 그 창을 메우는 것이 훅의 알림이다.
- **무엇도 잠글 수 없다.** 사용자가 자동 갱신을 끄거나 플러그인을 지우면 이 장치 전체가 멈춘다. 관리 설정이 생기기 전까지는 조용히 못 끄게 하는 것이 최선이다.
- **우산이 사용자 파일을 고친다.** `CLAUDE.md`와 개인 스킬 폴더와 파이썬 환경이다. 걸음마다 독립과 멱등으로 두고 훅은 절대 고치지 않는다.
- **`kw_install`과 우산이 같은 선언을 읽는데 판본이 다를 수 있다.** 옛 설치기를 든 PC를 위해 `schema`를 둔다.
- **코드 사본은 문서 사본보다 조용히 어긋난다.** `disciplined-coder`가 오늘 끝낸 감사에서 가장 무거운 뿌리가 「소유자 규칙의 복제」였다. 문서는 어긋나도 사람이 읽다가 알아채지만 코드 사본은 어긋난 채로 돈다. 사본 규율 셋이 그것을 막는 장치이고, 그중 「대조 불가」를 알리는 것이 가장 중요하다.
- **설치기 9단계가 Git Bash에 의존한다.** 우산 스크립트가 셸이라 설치기가 bash를 부른다. 2단계가 git을 깔고 9단계가 그 뒤이므로 순서상으로는 늘 있지만, winget이 실패한 PC에서는 git이 없어 그 단계가 통째로 못 돈다. 그때는 선언을 못 읽을 때와 같이 경고를 남기고 재실행을 안내한다.
- **레포가 둘로 늘어 이름이 어긋날 수 있다.** 지금도 `kw_install`의 문자열이 `KW-doc-formats`의 매니페스트와 맞아야 하는데 두 레포를 잇는 검사가 없다. 우산이 생기면 그 짝이 하나 더 는다.

## 하지 않는 것

- 관리 설정을 쓰지 않는다. 배포 수단이 없다.
- 훅이 설치하거나 파일을 고치지 않는다.
- 백업 목록을 설치기에 두지 않는다. 같은 사실을 두 곳에 두지 않는다.
- `KW-doc-formats`의 스킬 내용을 손대지 않는다. 발행처만 옮긴다.
- 설치기의 1단계와 2단계와 5단계와 6단계를 손대지 않는다.

## 이 설계에 흡수되는 것

`python3` 호출을 막는 훅을 `kw_install`에 넣기로 했던 앞선 결정은 여기로 온다. 도커 훅이 우산으로 가므로 훅의 자리가 우산이 되고 `python3` 훅도 같은 자리에 선다. 호출을 거부하고 이유를 돌려준다.

**끄는 스위치를 두지 않는다.** `disciplined-coder`가 차단보다 알림이 먼저라는 자기 관례를 들어 빠져나갈 길을 두라고 권했고, 사용자가 그것을 물리쳤다. 이 PC에서 `python3`을 부르고 싶은 경우는 영원히 없다는 것이 사용자의 말이고 확정이다.

근거가 있다. 이 이름은 파이썬이 아니라 마이크로소프트 스토어로 보내는 안내판(`AppInstallerPythonRedirector.exe`)이라 부를 이유 자체가 없다. 끄는 스위치를 두는 것은 안내판을 부르고 싶은 경우를 위해 길을 내는 것인데 그런 경우가 없다. 빠져나갈 길이 필요한 것은 거짓 양성이 있을 때인데, 이 이름을 정확히 부르는 것을 막는 것에는 거짓 양성이 없다. `python`과 `py -3`은 막지 않는다.

`disciplined-coder`가 이 가드를 사본으로 가져갈 때도 같은 모양으로 간다. 그쪽이 스위치를 붙이겠다면 그것은 그쪽 정본의 결정이고, 이쪽 사본은 스위치 없이 쓴다.
