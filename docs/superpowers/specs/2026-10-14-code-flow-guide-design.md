# 코드 동작 흐름 안내 화면 스킬 설계 (2026-10-14)

스킬 `explaining-code-flow` 는 레포 이름을 받아 HTML 한 장을 만든다. 그 HTML 은 기능마다 버튼을 누른 뒤 자료가 어디로 오가는지를 움직이는 그림으로 보여 준다. 읽는 사람은 바이브 코딩으로 레포를 만든 사람이고, 함수 이름과 API 개념을 모른다고 가정한다.

## 목적

스킬은 실제 화면의 버튼과 그 뒤의 자료 이동을 한 화면에 함께 보여 준다. 바이브 코더는 자기 레포가 어느 DB 에서 무엇을 읽고 어느 서버를 거쳐 결과를 내는지 모르고, 코드 위치를 알려 주어도 읽지 못하기 때문이다.

주 세션(Claude)이 아래 시제품을 손으로 만들었고, 사용자가 검토를 마쳤다. 시제품은 `~/02.github/flow_guide/` 에 있고 git 레포가 아니다.

| 시제품 | 대상 레포 | 범위 |
|---|---|---|
| `esg_movie.html` | Kiwoom-ESG (main `ac717211`) · llm-manager (`feat/llm-manager-chat-function` 브랜치 `2b2d3b6`) | 「회사 평가 실행」 기능 하나 |
| `wholesale_movie.html` | wholesale-dashboard (main `0758137`) | 메뉴의 모든 기능, 장면마다 실제 화면 캡처와 줌 |

줌은 화면 칸의 캡처를 누를 버튼 쪽으로 확대했다가 결과 쪽으로 다시 확대하는 동작이다. JSON 에서는 장면의 `screen.start` · `screen.end` 사각형이 확대할 곳을 정한다.

스킬은 시제품을 만든 순서를 절차로 옮기고, 시제품 템플릿에서 레포별로 손으로 넣은 값을 JSON 입력으로 옮긴다.

## 위치

스킬은 `plugins/kw-dashboard/skills/explaining-code-flow/` 에 둔다. 스킬 이름과 위치는 사용자가 정했다(2026-10-14). 사용자는 kw-dashboard 를 사내 공용 기능을 모으는 플러그인으로 쓰고, 기능마다 스킬을 나눈다.

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 절차와 고정 명칭표와 문장 규칙 |
| `analysis-prompt.md` | 기능 하나를 맡는 분석 서브에이전트의 지침과 출력 JSON 형식 |
| `tips-prompt.md` | 「알아 둘 점」을 코드에서 찾아 근거와 함께 적는 지침 |
| `scripts/run_repo.py` | 레포의 의존성 설치와 사설 패키지 토큰 발급과 서버 실행 · 종료 |
| `scripts/capture.py` | 기능마다 화면을 캡처하고 API 응답으로 실패 이유를 판정하는 단계 |
| `scripts/render.py` | JSON 을 검사하고 템플릿에 넣어 HTML 을 만드는 단계 |
| `scripts/movie_template.html` | 시제품 템플릿에서 레포별 값을 뺀 사본 |

플러그인 설명은 `plugins/kw-dashboard/.claude-plugin/plugin.json` 과 `.claude-plugin/marketplace.json` 두 곳에 같은 문장으로 있고, 지금은 대시보드 스킬만 설명한다. 이 스킬을 넣을 때 두 파일의 `description` 에 「`explaining-code-flow` 는 레포의 기능별 동작 흐름을 움직이는 안내 화면으로 만든다」는 문장을 함께 넣는다.

kw-plugins 는 윈도우 PowerShell 을 전제한다. 스크립트는 모두 파이썬이고 하위 명령을 `subprocess` 의 인자 목록으로 실행하므로, PowerShell 5 · 7 의 따옴표와 변수 문법에 영향받지 않는다. 스크립트 자신의 의존성(Playwright, PyJWT)은 `uv run --with` 로 임시 환경에 설치하고 PC 전역 파이썬에는 설치하지 않는다.

## 절차

스킬은 아래 순서로 진행하고, 기능 목록 승인과 클릭 승인과 결과 확인에서 사용자에게 묻는다.

| 단계 | 하는 일 | 확인 방법 |
|---|---|---|
| 레포 찾기 | 현재 폴더와 그 상위 폴더에서 이름이 같은 git 레포를 찾는다. 후보가 여럿이거나 없으면 사용자에게 경로를 묻는다. 브랜치와 커밋을 기록한다 | 화면 머리에 `레포 (브랜치 커밋)` 이 나온다 |
| 기능 목록 도출 | 주 세션이 메뉴 · 탭 · 라우트를 코드에서 읽어 사용자에게 보이는 기능 단위로 나열하고 승인을 받는다 | 사용자가 목록을 승인한다 |
| 기능별 분석 | 주 세션이 기능마다 분석 서브에이전트를 동시에 실행한다. 분석 서브에이전트는 `analysis-prompt.md` 에 따라 장면 · 동작 · 화면 표기(`startName` · `endName`) · 장면의 데이터 API 경로를 근거 줄과 함께 낸다 | 모든 동작에 `파일:줄` 근거가 있다 |
| 알아 둘 점 | 분석 서브에이전트가 `tips-prompt.md` 에 따라 화면 해석 규칙(색 뜻, 표시 조건, 단위)을 근거와 함께 낸다 | 주 세션이 근거 줄을 열어 모든 항목을 대조한다 |
| 클릭 승인 | 버튼을 눌러야 결과가 나오는 장면을 모아 클릭이 일으키는 동작을 한 목록으로 보여 주고, 모두 누를지 사용자에게 한 번 묻는다 | 사용자 답이 있다 |
| 화면 캡처 | `run_repo.py` 로 서버를 실행하고 `capture.py` 로 기능마다 캡처한 뒤 서버를 종료한다(「화면 캡처」 절) | 모든 장면에 캡처 또는 `screen.unavailable` 이 있고, 서버 프로세스가 남지 않는다 |
| JSON 합치기 | 주 세션이 분석 결과에 캡처 결과(이미지 경로, 사각형, 실패 문구)를 넣어 `flow.json` 하나로 만든다 | `render.py` 의 필드 검사를 통과한다 |
| 렌더 | `render.py` 로 HTML 을 만들고 브라우저로 연다 | 주 세션은 정지 상태를 캡처해 확인하고, 애니메이션 재생은 사용자가 브라우저에서 확인한다 |
| 코드와 다른 점 보고 | 분석 중 발견한 주석과 동작의 불일치, 쓰이지 않는 경로를 고치지 않고 사용자에게 알린다 | 답에 목록이 있다 |

## 고정 명칭표

사용자가 승인한 명칭을 모든 레포에 그대로 쓴다. 템플릿은 노드 종류(`kind`)마다 고정 라벨을 노드 이름 위에 표시하고, 레포별로는 노드 이름(`name`)과 설명(`sub`)만 바꾼다.

| 종류 | 템플릿 고정 라벨 | 노드 이름 예 |
|---|---|---|
| `screen` | 사람이 보는 화면 | 내 PC (브라우저) |
| `server` | 서버 · 프로그램 | 대시보드 서버 · ESG 서버 |
| `db` | 저장소 · DB | Redis 저장소 · AX팀 DB · WINUS |
| `ai` | AI 모델 | Claude · Gemini |
| `web` | 외부 사이트 | 크롤링 대상 사이트 이름 |
| `local` | 팀 공용폴더 | 팀 공용폴더 (Y: 드라이브) |
| `officepc` | 담당자 PC | 담당자 PC |
| `code` | 샘플 데이터 | 샘플 데이터 |
| `clock` | 정해진 시각 자동 실행 | 자동 실행 |

MDB · RDB · 파일 서버는 노드 하나로 묶어 「AX팀 DB」로 부른다. `clock` 노드는 구역 안에서도 시계 아이콘을 유지한다.

구역은 운영 주체를 나타내는 상자이고, 템플릿이 표시 이름을 고정한다. 시제품 템플릿 주석은 구역을 다른 이름으로 부르므로 사본에서는 「구역」으로 통일한다.

| 구역 | 표시 이름 |
|---|---|
| `office` | 내 PC · 사무실 |
| `app` | JSON 의 `appZone` 값 |
| `ax` | AX팀 서버 |
| `winus` | WINUS (회사 DW) |
| `fund` | 우리펀드서비스 |
| `external` | 외부 서비스 |

## JSON 형식

`render.py` 는 아래 필드를 검사하고, 필수 필드가 빠지면 HTML 을 만들지 않고 빠진 필드를 출력한다. 시제품의 `zoneNames` · `dock` · `group` 은 두 시제품 JSON 에서 쓰이지 않거나 템플릿이 읽지 않으므로 옮기지 않는다.

| 위치 | 필드 | 필수 여부 |
|---|---|---|
| 최상위 | `title` · `repo` · `appZone` · `features` | 필수 |
| 기능 | `key` · `name` · `summary` · `nodes` · `scenes` | 필수 |
| 기능 | `screenImg` | 캡처에 성공한 기능만 |
| 노드 | `id` · `name` · `kind` · `zone` · `x` · `y` | 필수(`zone` 은 구역 밖 노드만 생략) |
| 노드 | `sub` | 선택 |
| 장면 | `title` · `actions` | 필수 |
| 장면 | `screen.startName` · `screen.endName` · `tips` | 필수 |
| 장면 | `screen.start` · `screen.end` · `screen.startImg` · `screen.endImg` | 캡처에 성공한 장면만 |
| 장면 | `screen.unavailable` | 캡처에 실패한 장면만 |
| 장면 | `nodeOverride` | 선택(장면마다 노드 설명을 바꿀 때) |
| 동작 | `from` · `to` · `icon` · `text` · `say` | 필수 |
| 동작 | `items` | 선택 |

노드 좌표는 폭 960, 높이 520 무대의 노드 중심 기준이다. 템플릿은 아래 진행 목록이 한 화면에 들어오도록 세로 좌표를 `30 + (y - 30) × 0.86` 으로 줄여 높이 460 무대에 그린다. 화면 사각형(`screen.start` · `screen.end`)은 1440×1000 캡처 기준의 `[x, y, 폭, 높이]` 다.

## 화면과 문장 규칙

시제품 검토에서 사용자가 정한 규칙을 `SKILL.md` 와 `analysis-prompt.md` 와 `tips-prompt.md` 에 모두 적는다.

| 규칙 | 근거가 된 사용자 지적 |
|---|---|
| 함수 이름 대신 「누가 무엇을 어디에 보낸다」는 서술형으로 쓴다 | 바이브 코더는 함수 이름을 모른다 |
| 버튼 하나를 누른 뒤 일어나는 일을 장면으로 나누고, 화면 표기는 「홈」 메뉴 클릭처럼 버튼 이름으로 쓴다 | 「누를 곳으로 확대」 같은 표기는 어색하다 |
| 동시 처리 건수 제한 같은 내부 수치는 넣지 않는다 | 사용자가 알 필요가 없다 |
| 코드가 하지 않는 동작은 그리지 않고, 값을 하나씩 따로 가져오면 따로 그린다 | 정보를 한 묶음으로 모아 보내는 그림은 코드와 달라 거짓이 된다 |
| 예시 값은 「샘플 데이터」라고 밝힌다 | 실제 집계로 오해한다 |
| 노드 상자는 회색 테두리로 두고, 색은 구역 상자에만 쓴다 | 구역 색과 상자 색이 겹쳐 어지럽다 |
| 왼쪽 세로 띠를 쓰지 않고, 현재 줄은 회색 면으로 표시한다 | 사용자가 띠를 빼라고 했다. 대시보드 스킬의 강제 규칙과도 같다 |
| 「알아 둘 점」은 남색 테두리와 큰 글자로 두고, 분홍 같은 튀는 색은 쓰지 않는다 | 중요한 정보지만 화려할 필요는 없다 |

## 템플릿 변경

스킬 템플릿은 시제품 템플릿에서 레포 id 를 전제한 표를 지우고, 그 표를 읽던 대체 경로도 함께 지운다. 노드의 `kind` · `zone` · `x` · `y` 는 JSON 이 적고, `render.py` 가 빠진 값을 미리 잡는다.

| 대상 | 시제품의 내용 | 스킬 템플릿의 처리 |
|---|---|---|
| `SPOT` 과 `useFeature` 의 좌표 대체 | wholesale 노드 id 별 좌표 | 지운다 |
| `ZONE_BY_ID` 와 `zoneOf` 의 대체 | id 로 구역을 정하는 표 | 지우고 `n.zone` 만 읽는다 |
| `KIND_BY_ID` 와 `kindOf` 의 `'server'` 대체 | ESG · wholesale id 로 종류를 정하는 표 | 지우고 `n.kind` 만 읽는다 |
| `DOCK_BY_ID` 와 `dockOf` 의 붙여 그리기 | 빈 표와 그 처리 | 지운다 |
| `setupShot` 의 화면 칸 숨김 | `screenImg` 가 없으면 칸 전체를 숨김 | `screen.unavailable` 이 있으면 줌 없이 문구를 회색 면에 표시하고, 둘 다 없을 때만 숨긴다 |
| `ZONE` · `KIND` · `ICON` | 구역 · 종류 · 자료 아이콘 목록 | 고정 명칭표이므로 남긴다 |

`render.py` 는 레포 의존이 없어 그대로 옮기고, 기본 템플릿을 `movie_template.html` 로 바꾸며 필드 검사를 넣는다. 개발자용 단계 화면(`flow_template.html`)은 옮기지 않는다.

## 화면 캡처

스킬은 레포를 사용자 PC 에서 실행하고 헤드리스 Chrome 으로 기능마다 화면을 캡처한다(사용자 결정 2026-10-14). 사용자는 바이브 코더이므로 스킬은 Docker 를 쓰지 않고, 사용자에게 보이는 문장에도 Docker 라는 말을 쓰지 않는다.

화면 코드는 분석 대상 레포 안에 있다고 사용자가 확인했다(2026-10-14). 시제품의 Kiwoom-ESG 는 화면이 Kiwoom-RAG 에 있는 예외다. 화면 코드가 없는 레포는 캡처하지 않고 모든 장면에 「이 레포에는 화면 코드가 없어 화면을 만들 수 없습니다.」를 적는다.

`run_repo.py` 는 레포를 아래 방식으로 실행한다. 프론트엔드와 백엔드가 함께 있으면 백엔드를 먼저 실행하고, 응답을 확인한 뒤 프론트엔드를 실행한다.

| 레포 종류 | 설치 | 실행 |
|---|---|---|
| Node(`package.json` 의 `dev` 스크립트) | 잠금 파일이 있으면 `npm ci`, 없으면 `npm install --no-save` | `npm run dev -- -H 127.0.0.1 -p <빈 포트>`(Next.js). `vercel.json` 이 있어도 로그인이 필요한 `vercel dev` 는 쓰지 않는다 |
| 파이썬(`pyproject.toml`) | `uv sync --frozen` | `uv run uvicorn ... --host 127.0.0.1 --port <빈 포트>` |
| 파이썬(`requirements.txt`) | `uv venv` 뒤 `uv pip install -r requirements.txt` | 위와 같다 |

서버는 레포 종류와 상관없이 `127.0.0.1` 에만 연결한다. 캡처는 같은 PC 의 헤드리스 Chrome 이 하므로 바깥 연결이 필요 없다. 시제품 작업 중에는 wholesale-dashboard 를 `next dev -H 0.0.0.0 -p 3110` 으로 실행해 사내망에 열려 있었다. 이 실수를 반복하지 않도록 스킬이 호스트와 포트를 직접 지정한다. 빈 포트는 `run_repo.py` 가 운영체제에 받아 쓰므로 사용자가 띄워 둔 서버와 충돌하지 않는다. 캡처가 끝나거나 실패하면 `run_repo.py` 가 프로세스 트리를 종료한다(윈도우 `taskkill /T /F /PID`).

스킬은 레포의 추적 파일을 고치지 않는다. 시제품 작업 중 `npm install` 이 `package-lock.json` 을 바꿔 되돌린 일이 있어, 설치 명령은 잠금 파일을 고치지 않는 형태(`npm ci` · `--no-save` · `uv sync --frozen`)로 고정한다. `node_modules` 와 `.venv` 는 레포 폴더 안에 생긴다. `run_repo.py` 는 실행 전후의 `git status --porcelain` 을 비교하고, 추적 파일이 바뀌었으면 사용자에게 알린다.

사설 패키지(Kiwoom-Manager 등)는 레포의 `certs/kiwoom.pem` 으로 GitHub App 설치 토큰을 발급해 설치한다. 사용자 PC 에 `certs/kiwoom.pem` 과 `certs/ePrism.crt` 가 있다고 사용자가 확인했다(2026-10-14). 사설 패키지 목록은 `requirements.txt` · `pyproject.toml` 의 `git+https` 줄과, Dockerfile 의 설치 줄에서 읽는다. Kiwoom-ESG 는 사설 패키지를 Dockerfile 에서만 설치한다.

토큰 발급은 Kiwoom-ESG 의 `gen_token.sh` 와 `backend/Dockerfile` 이 쓰는 방식을 파이썬으로 옮긴다. JWT 를 RS256 으로 서명해 GitHub API 에서 1시간짜리 설치 토큰을 받는다. App ID(`2826312`)와 설치 ID(`108948292`)는 두 파일에 적힌 공개 식별자이므로 `run_repo.py` 에 상수로 둔다. `.env` 는 읽지 않는다.

토큰은 화면 출력과 파일과 명령줄 인자에 남기지 않는다. `run_repo.py` 는 토큰을 설치 하위 프로세스의 환경변수로만 넘긴다. git 의 `GIT_CONFIG_COUNT` · `GIT_CONFIG_KEY_0` · `GIT_CONFIG_VALUE_0` 환경변수로 `insteadOf` 를 주므로 `~/.gitconfig` 에 쓰지 않는다(git 2.31 이상). Kiwoom-ESG Dockerfile 의 `git config --global` 방식은 쓰지 않는다.

사내 SSL 프록시는 레포의 `certs/ePrism.crt` 로 통과한다. `run_repo.py` 는 Python 표준 `ssl` 이 읽는 OS 인증서(윈도우는 `ssl.enum_certificates("ROOT")`)에 `ePrism.crt` 를 붙인 임시 파일을 레포 밖에 만든다. 그리고 `SSL_CERT_FILE` 환경변수로 `uv` 와 토큰 요청에 함께 넘긴다. 표준 라이브러리만 쓰므로 스크립트 의존성을 내려받기 전에도 묶음을 만들 수 있고, `run_repo.py exec` 가 이 환경변수를 준 채 `uv run --with ...` 를 실행해 스크립트 의존성 설치도 같은 묶음으로 프록시를 통과한다. Kiwoom-ESG 도 같은 방식으로 CA 묶음을 만든다(`docker-compose.yml` 의 `SSL_CERT_FILE`). 이 PC 에서는 `uv --native-tls` 도 동작했지만, 윈도우 인증서 저장소에 ePrism 루트가 있는지가 사용자 PC 마다 달라 쓰지 않는다.

`capture.py` 는 Playwright 의 `channel="chrome"` 으로 PC 에 설치된 Chrome 을 구동한다. 이 방식은 브라우저를 내려받지 않으므로 사내 프록시를 거치지 않는다. Playwright 는 화면이 보낸 요청의 응답 코드와 본문을 이벤트로 받는다. 뷰포트는 1440×1000 으로 고정하고, 버튼과 결과 요소의 화면 좌표를 구해 `screen.start` · `screen.end` 에 적는다.

`capture.py` 는 기본으로 화면을 열기만 하고 버튼을 누르지 않는다(사용자 결정 2026-10-14). 사용자 PC 의 기존 설정으로 실행한 레포에서 버튼을 누르면 실제 동작이 일어나기 때문이다. wholesale-dashboard 에서는 공고 「새로고침」이 Claude API 를 호출해 과금이 생기고 운영 Redis 에 쓰며, 자동화 탭의 발송 POST 는 메일 발송 스크립트(`07-send.ps1`)를 실행한다.

버튼을 눌러야만 결과 화면이 나오는 장면은 주 세션이 캡처 전에 사용자에게 한 번만 묻는다(사용자 결정 2026-10-14). 분석 서브에이전트는 이런 장면마다 그 클릭이 일으키는 동작(외부 API 호출과 과금, 저장소 쓰기, 메일 발송)을 근거 줄과 함께 적는다. 주 세션은 클릭할 버튼과 각 동작을 한 목록으로 보여 주고, 비용을 감수하고 모두 누를지 묻는다. 사용자가 승인하면 목록의 버튼을 모두 클릭해 결과 화면을 캡처한다. 승인하지 않으면 목록의 장면은 시작 화면만 캡처하고, 줌은 시작 화면 안의 결과 위치로 이동한다.

캡처 이미지는 `docs/code-flow/screens/` 에 PNG 로 두고 HTML 이 상대 경로로 읽는다(사용자 결정 2026-10-14). 스킬이 결과를 알릴 때는 두 가지를 함께 적는다. 다른 사람에게 줄 때는 HTML 과 `screens/` 폴더를 함께 줘야 한다. 그리고 캡처와 HTML 에는 화면에 뜬 실제 데이터가 들어 있으므로 받을 사람을 확인해야 한다.

## 캡처 실패 판정

템플릿은 캡처하지 못한 장면의 화면 칸에 빈 화면 대신 이유 문구를 표시한다(사용자 결정 2026-10-14). `capture.py` 는 페이지 문서 요청의 응답과, 분석 서브에이전트가 장면의 데이터 API 로 지정한 경로의 응답만 판정에 쓴다. 판정은 위에서부터 처음 해당하는 조건으로 정한다.

| 판정 조건 | 화면 칸 문구 |
|---|---|
| 레포 실행 실패 | 이 PC 에서 레포를 실행하지 못해 화면을 만들 수 없습니다. |
| 문서 요청이 401 · 403 이거나 로그인 화면으로 이동 | 접근 권한이 없어 화면을 만들 수 없습니다. |
| 데이터 API 가 401 · 403 | 접근 권한이 없어 화면을 만들 수 없습니다. |
| 데이터 API 가 5xx 이거나 연결 실패 | 실행에 필요한 설정이 없어 화면을 만들 수 없습니다. |
| 데이터 API 의 응답 본문에서 목록이 비어 있음 | 실행에 필요한 데이터가 없어 화면을 만들 수 없습니다. |

목록이 비었는지는 분석 서브에이전트가 장면마다 응답의 목록 필드 이름(예: wholesale 공고 API 의 `notices`)을 함께 적어 정한다. wholesale-dashboard 의 로컬 전용 가드(`lib/localOnly.ts`)는 503 을 돌려주므로 「설정 없음」으로 판정된다. 샘플 데이터를 200 으로 돌려주는 API(예: `institution-news-insights`)는 정상 캡처로 둔다. 분석 서브에이전트가 그 장면의 노드를 `code`(샘플 데이터)로 그리므로 화면이 실제 집계로 보이지 않는다.

실제로 데이터가 0건인 조건(예: 오늘 접수 중인 공고가 없음)도 「데이터 없음」 문구가 나온다. v1 은 이 조건을 구분하지 않는다.

## 결과물 위치

결과물은 분석 대상 레포의 `docs/code-flow/` 폴더에 만들고, 폴더 전체를 git 에서 제외한다(사용자 결정 2026-10-14). 캡처 이미지와 HTML 안의 JSON 에는 화면에 뜬 실제 데이터(고객명 · AUM · 담당자 정보)가 들어가고, 커밋하면 지워도 git 이력에 남기 때문이다.

| 파일 | 내용 |
|---|---|
| `docs/code-flow/index.html` | 안내 화면 |
| `docs/code-flow/screens/*.png` | 캡처 이미지 |
| `docs/code-flow/flow.json` | 문구만 고쳐 다시 렌더할 때 쓰는 합친 JSON |
| `docs/code-flow/.gitignore` | 내용이 `*` 한 줄인 제외 파일 |

스킬은 레포 루트 `.gitignore` 를 고치지 않는다. `docs/code-flow/.gitignore` 는 자기 자신을 포함한 폴더 전체를 제외하므로 git 변경을 만들지 않는다. `uv` 가 `.venv` 를 만들 때도 같은 방식을 쓴다(uv 0.11.5 로 만든 `Kiwoom-ETF/.venv/.gitignore` 의 내용이 `*` 다). 다시 실행하면 폴더 내용을 덮어쓴다. 스킬은 결과를 만든 뒤 `git status --short docs/code-flow` 가 빈 출력인지 확인한다.

## 제외 범위

아래 작업은 이 스킬이 하지 않는다.

- 레포 코드를 고치지 않고, 불일치는 보고만 한다.
- 주 세션은 애니메이션 재생을 헤드리스로 검증하지 않고, 재생은 사용자가 브라우저에서 확인한다.
- 개발자용 단계 화면은 만들지 않는다.

애니메이션을 헤드리스로 검증하지 않는 이유는 시제품 작업 중 관찰에 있다. `--virtual-time-budget` 을 준 헤드리스 Chrome 캡처에서 Web Animations 와 CSS 전환이 진행되지 않았다. 그래서 주 세션은 정지 상태만 캡처해 확인한다.
