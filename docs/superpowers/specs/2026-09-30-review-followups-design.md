## 맞춤 구조

세션 시작의 맞춤은 불일치한 단계만, 시간 상한 안에서, 한 번에 하나씩 실행되고, 같은 원인으로 실패한 단계는 그날 다시 호출하지 않는다. 지금은 불일치 한 건에도 여덟 단계를 모두 실행하고(2026-09-30 이 PC 의 맞춤은 싣지도 않는 사본 하나 때문에 배포처 받아오기와 pip 을 실행했다), 실패를 기억하는 곳이 설치본 뒤처짐 하나뿐이라 영구 실패가 세션마다 되풀이된다.

| 결정 | 내용 | 근거 |
|---|---|---|
| 불일치한 단계만 실행 | 감지가 불일치마다 단계 번호를 붙여 `-Steps` 로 넘긴다. 인자를 넘기지 않으면(설치기) 모두 실행하고, 넘겼는데 비어 있으면 아무것도 실행하지 않는다 | 감지는 무엇이 다른지 이미 안다 |
| pip 조건부 실행 | 상태 파일의 `requirements` 해시가 목록과 같으면 pip 을 호출하지 않는다 | 감지가 같은 해시로 판정한다 |
| 영구 실패 재시도 중단 | 실패하거나 시간 상한에 끊긴 단계에 `stuck-step<N>=<지문>` 을 적고, 감지는 지문이 같으면 그 단계를 넘기고 알리기만 한다. 지문은 목록 파일 둘의 내용과 날짜와 단계 번호의 MD5 다. 권장 플러그인 하나의 설치 실패는 적지 않는다 | 원인이 같은 동안 다시 호출해도 결과가 같다. 날짜를 넣어 하루에 한 번은 다시 시도한다. 권장 실패를 적으면 같은 날 필수 플러그인 교정까지 보류된다 |
| 켤 때만 실행 | SessionStart 의 matcher 를 `startup` 으로 좁힌다 | 설치 결과는 다시 켜야 적용되므로 `/clear`·resume 의 재실행은 효과가 없다 |
| 시간 상한 | 훅이 맞춤에 `-BudgetSeconds 60` 을 넘긴다. `claude` 호출마다 남은 시간으로 대기하고 넘으면 끊는다. 단계는 남은 시간이 여유(최대 20초) 이상일 때만 시작하고, 남은 단계는 다음 세션으로 미룬다 | 훅 제한이 90초다. 넘기면 알림이 사라진다고 보았다(가정 참조). pip 과 잠금 대기는 중간에 끊지 못해 여유를 둔다 |
| 동시 실행 잠금 | 상태 파일을 읽기 전에 맞춤 전체에 잠금 폴더를 잡고, 못 잡으면 이번 세션은 넘긴다. 10분 넘은 잠금과 약 10초 동안 치워지지 않은 `CLAUDE.md` 문지기 폴더는 치운다. disciplined-coder 와 함께 고치는 `settings.json`·`known_marketplaces.json` 의 사본 이름은 `.kw.bak` 이다 | 창 둘이 pip·`claude plugin`·상태 파일을 동시에 고친다 |
| 문안 사본 범위 | `CLAUDE.md` 가 실제로 싣는 파일과, 원칙이 근거로 가리키는 사본만 복사하고 대조한다 | 싣지 않는 사본 하나가 맞춤을 호출한다 |
| 권장 플러그인별 기록 | 한 번 깔았거나 이미 있던 권장 플러그인을 `suggestedDone` 에 적는다. `ranOnce` 만 있는 PC 는 이행 때(2026-09-30)의 권장 목록(kw-devops·superpowers·document-skills·playwright·frontend-design)을 처리한 것으로 본다 | `ranOnce` 는 하나라도 실패하면 안 적혀, 사용자가 지운 권장이 되살아난다 |
| PYTHONUTF8 | 비어 있으면 1 을 넣고, 0 과 1 은 그대로 둔다 | 판정식 `sys.getdefaultencoding()` 이 파이썬 3 에서 늘 utf-8 이라 한 번도 넣지 못했다 |
| python3 가드 | 가드가 호출할 때 직접 판정한다. 맞춤 단계 8 과 상태 파일의 `python3` 기록을 없앤다 | 불일치한 단계만 실행하면 단계 8 이 거의 실행되지 않아 판정이 굳는다 |

권장 플러그인별 기록에는 설계가 정하지 않았던 결과가 하나 따른다. 앞으로 권장 목록에 새로 올린 플러그인은 이미 맞춤이 실행된 PC 에도 한 번 깔린다. 예전에는 `ranOnce` 가 분기를 닫아 새 PC 에만 깔렸다.

## 플러그인 등급

kw-dashboard 를 필수에서 권장으로, document-skills 를 권장에서 필수로 옮긴다. kw-dashboard 는 배포를 권장인 kw-devops 에 넘기므로 둘의 등급을 맞추고, kw-doc-formats 는 공식 document-skills 위에 얹는 보정 스킬이라 기본 스킬이 늘 있어야 한다.

## 공식 문서 스킬의 LibreOffice 단계

kw 보정 스킬에 오피스 COM 대체 경로를 적는다. 설치기 `\\cifs\ai\projects\kw_install\setup.ps1` 은 LibreOffice 를 깔지 않으므로 공식 스킬의 `recalc.py`·`soffice` 단계는 사내 PC 에서 실패한다. COM 은 사용자가 파일을 여는 바로 그 프로그램이 계산하고 그리므로 결과가 같다. 엑셀의 `recalc.py` 가 하는 세 가지(계산, 오류 값 세기, 결과를 파일에 쓰기)는 모두 COM 으로 대신한다.

## 배포 스킬

포트는 고른 직후 등록한다. 등록부 조회와 삽입 사이에 남이 같은 포트를 넣어 거부되면 「남이 먼저 잡았다」로 알아본다. 지금은 2단계에서 고르고 빌드 뒤인 5단계에서 넣어, 그 사이 다른 담당자가 같은 포트를 고를 수 있다.
