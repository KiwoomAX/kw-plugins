# AX 팀 스케줄·게이트웨이 등록 요청 — 보내는 법과 메일 모양

SKILL.md 의 「AX 팀에 요청하기」에서 연다. 언제 보내는지와 스크립트를 부르는 줄은 거기 있고, 여기는 보내기
전에 준비할 것과 결과를 다루는 법과 스케줄 등록 요청·게이트웨이 등록 요청의 모양을 정한다. 환경변수 등록은 메일로 보내지 않는다.

**본문은 `outlook-email` general plain 형식의 JSON 이다.** `blocks` 에 블록을 순서대로 쌓는다. 블록
값 안에서는 `**굵게**` 만 쓴다. 백틱은 글자 그대로 찍힌다. 예시의 `<…>` 를 실제 값으로 바꾸고,
표의 행과 목록 항목은 개수에 맞게 늘리거나 줄인다.

**메일 문장은 개조식으로 쓴다.** 명사형으로 닫고 부연은 `—` 뒤에 잇고 나열은 `·` 로 가른다. 담당자에게
받아 채우는 값(용도·예상 실행 시간 같은 것)도 같은 형식으로 적는다.

## 보내는 법

본문 JSON 을 저장소 밖(`$env:TEMP` 가 가리키는 폴더의 절대경로 같은 곳)에 Write 로 만든 뒤 부른다.

종료 코드로 다음을 정한다.

| 종료 코드 | 어떻게 한다 |
|---|---|
| 0 | "SMTP 가 받아들였다"고만 알린다 |
| 2 이고 사유가 `-Subject`·`-BodyPath` 이거나 본문 JSON 을 읽지 못한 것 | 부르는 쪽의 실수이고 메일은 나가지 않았다. 사유대로 인자나 본문 JSON 을 고쳐 한 번만 다시 부른다 |
| 4 이고 사유가 `렌더러가 종료 코드` | 본문 블록이 렌더러 형식과 다르고 메일은 나가지 않았다. 아래 블록 이름과 칸에 맞춰 고친 뒤 한 번만 다시 부른다 |
| 그 밖, 또는 다시 부른 뒤에도 실패 | 코드와 스크립트가 찍은 사유를 눈에 띄게 알린다. 만든 본문을 담당자에게 보여 직접 전달하게 한다. 값이 든 파일을 대화에 붙여 넣으라고 하지 않는다 |

## 스케줄 등록 요청

SKILL.md 6단계가 가른 요청 종류마다 형식이 다르다. 보내기 전에 셋을 챙긴다.

- `vercel.json` 의 `schedule` 은 UTC 이므로 실행 주기를 한국 시간으로 옮겨 적는다.
- 컨테이너 실행형이 자료를 쓰면 compose-and-env.md 의 「Jenkins 덮어쓰기와 런타임 자료」 절을 따라 자료 마운트를 먼저 적고
  push 한다.
- 스케줄에만 쓰는 비밀 키(주소 호출형이 헤더에 싣는 `CRON_SECRET` 같은 것)는 3단계 환경변수 등록 때 함께 올라간다.
  3단계 때 `.env` 에 없던 키가 새로 생겼을 때만 SKILL.md 의 「AX 팀에 요청하기」대로 그 키만 남긴 파일로 환경변수 등록을 한 번 더 안내한다. 등록은 이미 등록된 키에 더해진다.

### 컨테이너 실행형

제목은 `[배포 등록 요청] 스케줄 — <저장소> <서비스>` 로 한다.

| 차례 | 블록 | 담는 것 |
|---|---|---|
| 1 | `kv` | 저장소 주소, 브랜치, compose 파일, 덮어쓰기 파일, 프로젝트 이름, 서비스, 실행 주기, 실행 명령, 예상 실행 시간, 자료 경로 |
| 2 | `ol` | AX 팀이 할 일 |
| 3 | `note` | 프로젝트 이름 문장과, 비밀 키가 있으면 비밀 값 문장 |

할 일은 예시의 문장을 그대로 쓰고 `<…>` 만 바꾼다. compose 파일과 덮어쓰기 파일은 저장소 기준 경로로
적는다. 프로젝트 이름은 compose 의 `name:` 값이다. 실행 주기는 cron 식과 한국 시간 설명을 함께 적는다
(`0 6 * * *` — 매일 06:00 KST). 자료를 쓰지 않는 서비스는 자료 경로 행과 자료 폴더를 만드는 할 일을 뺀다.

**프로젝트 이름 문장** — `compose 프로젝트 이름이 Jenkins 배포와 같음 — 같은 compose 파일을 두 곳에서 사용`

**비밀 값 문장** — `비밀 값은 환경변수(env) 등록 문의로 전달`

`note` 는 프로젝트 이름 문장으로 쓴다. 이 서비스에 비밀 키가 있을 때만 뒤에 ` · ` 를 두고 비밀 값 문장을 잇는다. 아래 예시는 비밀 키가 있는 서비스다.

```json
{
  "docTitle": "[배포 등록 요청] 스케줄 — <저장소> <서비스>",
  "blocks": [
    { "type": "kv", "rows": [
      ["저장소 주소", "https://github.com/<조직>/<저장소>"],
      ["브랜치", "main"],
      ["compose 파일", "<compose 파일>"],
      ["덮어쓰기 파일", "<Jenkins 덮어쓰기 파일>"],
      ["프로젝트 이름", "<compose name 값>"],
      ["서비스", "<서비스>"],
      ["실행 주기", "<cron 식> — <한국 시간 설명>"],
      ["실행 명령", "docker compose -f <compose 파일> -f <Jenkins 덮어쓰기 파일> run --rm -T <서비스>"],
      ["예상 실행 시간", "<담당자가 답한 시간>"],
      ["자료 경로", "/home/chshin84/opt/<저장소 이름>/data"]
    ]},
    { "type": "ol", "items": [
      "서버에 저장소 클론",
      "자료 폴더 생성 — mkdir -p /home/chshin84/opt/<저장소 이름>/data",
      "체크아웃 루트에 .env 배치 — 이 compose 파일이 요구하는 키 전부 포함",
      "compose나 Dockerfile이 쓰는 certs/를 체크아웃에 배치",
      "체크아웃 폴더에서 실행 명령과 같은 파일로 빌드 — docker compose -f <compose 파일> -f <Jenkins 덮어쓰기 파일> build <서비스>",
      "crontab에 실행 주기와 실행 명령 등록 — 명령은 체크아웃 폴더에서 실행",
      "체크아웃 갱신 때마다 위 빌드 재실행"
    ]},
    { "type": "note", "text": "compose 프로젝트 이름이 Jenkins 배포와 같음 — 같은 compose 파일을 두 곳에서 사용 · 비밀 값은 환경변수(env) 등록 문의로 전달" }
  ]
}
```

### 주소 호출형

제목은 `[배포 등록 요청] 스케줄 — <저장소> <주소 경로>` 로 한다.

| 차례 | 블록 | 담는 것 |
|---|---|---|
| 1 | `kv` | 저장소, 컨테이너, 호출 주소, 실행 주기, 실행 명령, 예상 실행 시간 |
| 2 | `ol` | AX 팀이 할 일 |
| 3 | `note` | 고정 문장 |

호출 주소는 서버 안에서 부르는 `http://127.0.0.1:<호스트 포트><주소 경로>` 다. 실행 명령의 `-m` 은 예상 실행
시간보다 넉넉한 초로 적는다. 라우트가 비밀 키를 헤더로 확인하지 않으면 명령의 `-H` 와 키를 쓰는 할 일을 뺀다.

**note 고정 문장** — `저장소 체크아웃·빌드 불필요 — Jenkins가 띄운 컨테이너의 주소만 호출`

```json
{
  "docTitle": "[배포 등록 요청] 스케줄 — <저장소> <주소 경로>",
  "blocks": [
    { "type": "kv", "rows": [
      ["저장소", "<저장소>"],
      ["컨테이너", "<container_name>"],
      ["호출 주소", "http://127.0.0.1:<호스트 포트><주소 경로>"],
      ["실행 주기", "<cron 식> — <한국 시간 설명>"],
      ["실행 명령", "curl -fsS -m <초> -H \"Authorization: Bearer $<키 이름>\" http://127.0.0.1:<호스트 포트><주소 경로>"],
      ["예상 실행 시간", "<담당자가 답한 시간>"]
    ]},
    { "type": "ol", "items": [
      "crontab에 실행 주기와 실행 명령 등록",
      "명령의 $<키 이름>에 **env-<서비스>** 자격증명의 같은 키 값 사용"
    ]},
    { "type": "note", "text": "저장소 체크아웃·빌드 불필요 — Jenkins가 띄운 컨테이너의 주소만 호출" }
  ]
}
```

## 게이트웨이 등록 요청

대시보드에만 보낸다. 제목은 `[배포 등록 요청] 게이트웨이 — <저장소> /<접두어>/` 로 한다.

| 차례 | 블록 | 담는 것 |
|---|---|---|
| 1 | `kv` | 저장소, 조직, 접두어, 화면 이름, 화면 컨테이너, 컨테이너 포트, 볼 수 있는 사람, 번들 데이터, 업로드 크기, 응답 대기 시간, DBGateway 호출, 기존 포트, 최신 빌드, 요청자, 요청 시각 |
| 2 | `ol` | AX 팀이 할 일 |
| 3 | `note` | 고정 문장 |

값은 담당자에게 받거나 코드에서 찾아 적는다.

- 화면 이름은 로그인 화면에 보일 이름이다(예: 임원실 대시보드).
- 번들 데이터는 화면 코드(JS 번들)에 업무 데이터가 들어 있는지다. 들어 있으면 AX 팀이 화면 파일을 로그인 없이 공개하지 않는다.
- 업로드 크기는 화면이 올리는 파일의 최대 크기, 응답 대기 시간은 가장 오래 걸리는 API 의 시간이다. 없으면 「해당 없음」으로 적는다.
- DBGateway 호출은 화면 서버가 사내 데이터를 DBGateway 로 조회하는지다.
- 기존 포트는 이미 포트로 운영 중인 대시보드를 넘겨받을 때만 적고, 아니면 행과 마지막 할 일을 뺀다.
- 최신 빌드는 4단계에서 `Finished: SUCCESS` 를 확인한 빌드 번호다.

**note 고정 문장** — `화면 저장소 최신 Jenkins 빌드 성공 확인 후 게이트웨이 반영 — 등록 완료 후 요청자에게 회신 요청`

```json
{
  "docTitle": "[배포 등록 요청] 게이트웨이 — <저장소> /<접두어>/",
  "blocks": [
    { "type": "kv", "rows": [
      ["저장소", "<저장소>"],
      ["조직", "<조직>"],
      ["접두어", "/<접두어>/"],
      ["화면 이름", "<로그인 화면에 보일 이름>"],
      ["화면 컨테이너", "<화면 서비스의 container_name>"],
      ["컨테이너 포트", "<화면 서비스의 컨테이너 포트>"],
      ["볼 수 있는 사람", "<담당자가 답한 사람·팀>"],
      ["번들 데이터", "<포함 또는 미포함>"],
      ["업로드 크기", "<최대 크기 또는 해당 없음>"],
      ["응답 대기 시간", "<가장 오래 걸리는 API 시간 또는 해당 없음>"],
      ["DBGateway 호출", "<예 또는 아니오>"],
      ["기존 포트", "<기존 호스트 포트>"],
      ["최신 빌드", "#<빌드 번호> Finished: SUCCESS"],
      ["요청자", "<담당자 이름>"],
      ["요청 시각", "<YYYY-MM-DD HH:mm> KST"]
    ]},
    { "type": "ol", "items": [
      "게이트웨이 화면 파일·로그인 화면 이름 등록 — /<접두어>/",
      "접근 권한 등록 — 볼 수 있는 사람 기준",
      "기존 포트 전환 — 기존 포트 권한을 /<접두어>로 복사·기존 포트를 새 경로로 전달"
    ]},
    { "type": "note", "text": "화면 저장소 최신 Jenkins 빌드 성공 확인 후 게이트웨이 반영 — 등록 완료 후 요청자에게 회신 요청" }
  ]
}
```
