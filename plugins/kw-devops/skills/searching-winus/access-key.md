# 접근 키 발급과 등록

`fetch_manifest.py`나 managing-sandbox 의 `sandbox.py`가 접근 키 때문에 멈췄을 때 이 순서를 따른다. 두 스킬은 같은 키(환경 변수 `KIWOOM_ACCESS_KEY`)를 쓰므로 한 번 등록하면 둘 다에서 쓰인다. 요청 코드나 바로 조회 스크립트가 키 때문에 멈췄으면 `fetch_manifest.py`를 한 번 실행해 그 출력의 `조치`·`설정 뒤` 줄로 아래를 따른다. 키가 등록될 때까지 요청을 진행하지 않는다.

## `접근 키 없음`이나 `DBGateway 신원 거절(401)`로 멈췄을 때

출력의 `조치` 줄에 접근 키 화면 주소와 브라우저로 열었는지가 적혀 있다. 클로드는 아래 순서로 키를 직접 등록한다.

1. 사용자에게 아래 형식 그대로 안내한다.
   - 두 주소는 번호 목록 안에 넣지 않고 목록 앞에 따로 둔다. 목록 안에 넣으면 터미널이 줄 간격을 고르지 않게 그린다.
   - 주소 앞뒤에는 괄호나 조사를 붙이지 않는다. 붙이면 터미널이 그 글자까지 주소로 잡아 링크가 열리지 않는다.
   - 접근 키 화면 주소는 출력의 `조치` 줄에 있는 주소를 쓴다. `브라우저로 열림`이면 첫 줄을 "접근 키 발급(브라우저에 열림):"으로 바꾼다.
   - 아래 형식은 코드 블록으로 감싸지 말고 일반 글로 쓴다. 코드 블록 안의 주소는 눌러도 열리지 않는다.

   ```
   접근 키 발급:
   http://192.7.9.45:3000/#access-key

   초기 비밀번호 안내(처음 로그인할 때만):
   https://app.notion.com/p/WINUS-FAS-OMS-IIS-402c141487b880cf90f7d5a9fe425952

   방금 발급해 키 원문이 화면에 보이면 1·2는 하지 않고 그 키의 「복사」를 누릅니다. 새로 열린 탭에서 「재발급」을 누르면 그 키는 더 이상 쓸 수 없습니다.

   1. 위 접근 키 발급 주소에서 사내 계정으로 로그인합니다. 아이디는 사내 이메일의 @ 앞부분입니다. 처음 로그인하면 비밀번호를 바꾸는 화면이 나옵니다.
   2. 「키 발급」을 누릅니다. 키가 있는데 거절됐으면 「재발급」을 누릅니다. 키 원문은 발급 직후 한 번만 보입니다.
   3. 키의 「복사」를 누른 뒤 '복사했다'고 답해 주세요. 키 원문은 대화에 붙여 넣지 마세요.
   ```
2. 사용자의 답을 기다린다.
3. 사용자가 답하면 클립보드에서 키를 읽어 사용자 환경 변수 `KIWOOM_ACCESS_KEY`에 등록한다. 키는 명령 안에서 바로 넘기고, 대화에 쓰거나 명령에 직접 적거나 출력으로 보이게 하지 않는다.
   - Windows PowerShell: `[Environment]::SetEnvironmentVariable('KIWOOM_ACCESS_KEY', (Get-Clipboard).Trim(), 'User')`
   - WSL: `powershell.exe -NoProfile -Command Get-Clipboard`로 읽고 끝의 `\r`을 지운다. `$SHELL`이 zsh면 `~/.zshrc`, bash면 `~/.bashrc`에 `export KIWOOM_ACCESS_KEY=...` 줄로 넣는다. 다른 셸의 파일에 넣으면 새 터미널에서 키가 보이지 않는다. 그 파일에 이미 `export KIWOOM_ACCESS_KEY` 줄이 있으면 먼저 지운다.
   - 클립보드를 읽을 수 없거나 클로드 코드가 그 명령을 거부하면 등록하지 않는다. 그 사실과 거부 문구를 전하고, 접근 키 화면 「사용 방법」의 PowerShell 명령으로 사용자가 직접 등록하게 한다.
4. 등록한 값이 `kwam_`으로 시작하고 48자인지 참·거짓만 출력해 확인한다. 거짓이면 클립보드에 키가 아닌 내용이 있었던 것이므로, 「복사」를 다시 누르게 하고 3번부터 다시 한다.
5. 출력의 `설정 뒤` 줄을 그대로 전한다. 클로드는 사용자가 어느 프로그램을 쓰는지 묻지 않는다. 함께 사용자가 처음 한 요청을 한 줄로 적어 주고, `설정 뒤` 줄대로 창을 모두 닫았다 다시 연 뒤 새 세션에 그 줄을 그대로 붙여 넣으면 이어서 진행한다고 알린다.

## `접근 키는 설정됨`이나 `새 접근 키가 설정됨`으로 멈췄을 때

키는 이 PC에 설정됐지만 지금 창에 반영되지 않은 상태다. 스크립트는 발급 화면을 열지 않는다. 클로드는 출력의 `조치` 줄과 그 아래 줄을 그대로 전하고, 그 줄이 재발급을 안내할 때만 재발급을 권한다. 레지스트리에서 키를 꺼내 명령에 넘겨 우회하지 않는다. 위 5번처럼 처음 한 요청을 한 줄로 적어 준다.
