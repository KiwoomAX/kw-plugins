# searching-winus

등록된 쿼리는 모두 조회다. 이 스킬로는 데이터를 바꾸지 못한다. 조회도 인자를 요청 본문에 넣어 `POST`로 보내지만, 데이터는 바뀌지 않는다. DBGateway는 쿼리 id로 등록된 SQL을 찾아 인자를 바인딩해 실행하고, 클라이언트 코드는 쿼리 id와 인자만 보낸다. 클로드는 쿼리를 고르려고 등록된 SQL을 읽을 수 있지만, 사용자 코드나 문서에는 SQL을 옮겨 적지 않고 쿼리 id로만 요청하게 한다. 여러 쿼리를 잇는 일(앞 결과를 뒤 인자로 넘기기)은 호출하는 쪽이 한다.

```
[클라이언트 코드] --POST /winus/query/{id} + 접근 키 + 본문의 인자--> [DBGateway] --등록된 SQL + 인자--> [WINUS]
```

요청할 수 있는 쿼리 목록이 매니페스트다. 매니페스트는 목차와 쿼리별 상세 두 층이고, 상세는 id로 받는다. 목차는 표 두 개다.

- **승인 쿼리**: 무엇을 계산하는지 정해 둔 쿼리. 쿼리마다 id·이름·설명·사용 테이블을 한 행에 싣는다.
- **테이블 쿼리**: WINUS 테이블 하나를 가공하지 않고 그대로 읽는 쿼리. 위 칸에 종류(`WINUS`·`WFS`)를 더한다. 부를 때 받을 컬럼·조건·최대 행 수를 더할 수 있다(아래 「테이블 쿼리」).

목차의 설명은 쿼리가 무엇을 계산하는지 적는다. 인자 값의 뜻과 결과의 단위까지 적은 설명도 있지만, 모든 설명에 있지는 않다. 사용 테이블은 그 쿼리가 읽는 테이블·뷰·함수다.

```
python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py"
python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py" --query <id> [<id> …]
```

첫째 명령은 목차를 내고, 둘째 명령은 적은 id마다 이름·설명·사용 테이블·인자·등록된 SQL을 낸다. 인자 줄은 DBGateway가 요구하는 인자 이름과 그 종류(`스칼라`·`목록`)다. 테이블 쿼리면 `기간` 줄(시작일·종료일 인자와 최대 일수)과 `출력 컬럼` 줄이 더 나온다.

- **매니페스트는 이 스크립트의 출력으로만 읽는다.** 등록된 SQL과 테이블 쿼리의 출력 컬럼은 `--query`로 고른 쿼리만 받는다.
- **상세에 `부를 수 없음` 줄이 있으면 그 쿼리를 부르지 않는다.** 등록이 잘못된 쿼리라 DBGateway가 보내기 전에 막는다. 그 줄을 그대로 사용자에게 알리고 AX팀에 등록 수정을 요청하라고 안내한다.
- **상세에 `SQL 해석` 줄이 있으면 DBGateway가 SQL을 끝까지 읽지 못한 것이다.** `구문 분석 실패`면 인자가 모두 `스칼라`로 나온다. 설명이 목록을 받는다고 적었는데 인자 줄에 `목록`이 없으면 그 차이를 사용자에게 알리고, 인자 줄을 따른다. `SELECT 아님`이면 부르지 않고 AX팀에 알리라고 안내한다.
- **첫 줄의 경고는 사용자에게 알리고 작업을 이어 간다.** 경고는 매니페스트가 최신이 아닐 수 있다는 뜻이다.

> DBGateway는 PoC(0.1.0)다. 이 문서에 적힌 것과 실제 응답이 다르면 맞춰 넘기지 말고 사용자에게 알린다.

## 접근 키

DBGateway는 요청마다 접근 키로 요청한 사람을 확인하고, 그 사람에게 허용된 쿼리만 목차에 포함하고 실행한다. 접근 키는 `kwam_`으로 시작하는 개인 키이고, 이 PC의 환경 변수 `KIWOOM_ACCESS_KEY`에 설정해 둔다. `fetch_manifest.py`와 요청 코드는 그 환경 변수에서 키를 읽어 `Authorization: Bearer <키>` 헤더로 보낸다. 키 없이 보내면 팀 전용 쿼리는 없는 id처럼 거절되고, DBGateway가 키 없는 요청을 받지 않으면 401로 거절된다(Kiwoom-DBgateway ADR-0043). 그래서 `fetch_manifest.py`는 키가 없으면 요청하지 않고 멈춘다.

`fetch_manifest.py`가 `접근 키 없음`이나 `DBGateway 신원 거절(401)`로 멈추면, 출력의 `조치` 줄에 접근 키 화면 주소와 브라우저로 열었는지가 적혀 있다. `브라우저로 열지 못함`이면 그 주소를 사용자에게 알린다. 클로드는 아래 순서로 키를 직접 등록하고, 키가 등록될 때까지 조회를 진행하지 않는다.

1. 사용자에게 아래 형식 그대로 안내한다. 두 주소는 번호 목록 안에 넣지 않고 목록 앞에 따로 둔다. 목록 안에 넣으면 터미널이 줄 간격을 고르지 않게 그린다. 주소 앞뒤에는 괄호나 조사를 붙이지 않는다. 붙이면 터미널이 그 글자까지 주소로 잡아 링크가 열리지 않는다. 접근 키 화면 주소는 출력의 `조치` 줄에 있는 주소를 쓰고, `브라우저로 열림`이면 첫 줄을 "접근 키 발급(브라우저에 열림):"으로 바꾼다. 아래 형식은 코드 블록으로 감싸지 말고 일반 글로 쓴다. 코드 블록 안의 주소는 눌러도 열리지 않는다.

   ```
   접근 키 발급:
   http://192.7.9.45:3000/#access-key

   초기 비밀번호 안내(처음 로그인할 때만):
   https://app.notion.com/p/WINUS-FAS-OMS-IIS-402c141487b880cf90f7d5a9fe425952

   방금 발급해 키 원문이 화면에 보이면 1·2는 하지 않고 그 키의 「복사」를 누릅니다. 새로 열린 탭에서 「재발급」을 누르면 그 키는 더 이상 쓸 수 없습니다.

   1. 위 접근 키 발급 주소에서 사내 계정으로 로그인합니다. 아이디는 사내 이메일의 @ 앞부분입니다. 처음 로그인하면 비밀번호를 바꾸는 화면이 나옵니다.
   2. 「키 발급」을 누릅니다. 키가 있는데 거절됐으면 「재발급」을 누릅니다. 키 원문은 발급 직후 한 번만 보입니다.
   3. 키의 「복사」를 누른 뒤 '복사했다'고 답해 주세요. 키 원문은 대화에 붙여 넣지 마세요.
   ```
2. 사용자의 답을 기다린다.
3. 사용자가 답하면 클립보드에서 키를 읽어 사용자 환경 변수 `KIWOOM_ACCESS_KEY`에 등록한다. 키는 명령 안에서 바로 넘기고, 대화에 쓰거나 명령에 직접 적거나 출력으로 보이게 하지 않는다.
   - Windows PowerShell: `[Environment]::SetEnvironmentVariable('KIWOOM_ACCESS_KEY', (Get-Clipboard).Trim(), 'User')`
   - WSL: `powershell.exe -NoProfile -Command Get-Clipboard`로 읽고 끝의 `\r`을 지운다. 사용자 셸의 설정 파일에 `export KIWOOM_ACCESS_KEY=...` 줄로 넣는다. 셸은 `$SHELL`로 확인하고, zsh면 `~/.zshrc`, bash면 `~/.bashrc`에 넣는다. 다른 셸의 파일에 넣으면 새 터미널에서 키가 보이지 않는다. 그 파일에 이미 `export KIWOOM_ACCESS_KEY` 줄이 있으면 먼저 지운다.
   - 클립보드를 읽을 수 없거나 클로드 코드가 그 명령을 거부하면 등록하지 않는다. 그 사실과 거부 문구를 전하고, 접근 키 화면 「사용 방법」의 PowerShell 명령으로 사용자가 직접 등록하게 한다.
4. 등록한 값이 `kwam_`으로 시작하고 48자인지 참·거짓만 출력해 확인한다. 거짓이면 클립보드에 키가 아닌 내용이 있었던 것이므로, 「복사」를 다시 누르게 하고 3번부터 다시 한다.
5. 출력의 `설정 뒤` 줄대로 클로드 코드를 실행한 프로그램의 창을 모두 닫고 다시 연 뒤, 새 세션에서 같은 요청을 다시 하라고 알린다. 프로그램은 시작할 때 환경 변수를 복사해 두므로, 같은 창에서 클로드 코드만 다시 실행하면 새 키가 보이지 않는다. 접근 키 화면을 연 브라우저는 닫지 않아도 된다. 클로드는 사용자가 어느 프로그램을 쓰는지 묻지 않고 그 줄을 그대로 전한다.

`fetch_manifest.py`가 `접근 키는 설정됨`이나 `새 접근 키가 설정됨`으로 멈추면, 키는 이 PC에 설정됐지만 지금 창에 반영되지 않은 상태다. 이때 스크립트는 발급 화면을 열지 않는다. 클로드는 출력의 `조치` 줄과 그 아래 줄을 그대로 전하고, 그 줄이 재발급을 안내할 때만 재발급을 권한다. 레지스트리에서 키를 꺼내 명령에 넘겨 우회하지 않는다.

- **키 원문을 대화·코드·문서에 적지 않는다.** 사용자가 키를 대화에 붙여 넣으려 하면 멈추게 하고, 클로드도 키 값을 출력하는 명령을 실행하지 않는다. 키가 설정됐는지는 `fetch_manifest.py`를 실행해 확인한다.
- **여러 사람이 쓰는 서버나 배포한 서비스에는 개인 키를 설정하지 않는다.** 그 서비스의 모든 요청이 키 주인의 권한으로 처리된다. 그런 코드를 요청받으면 개인 키로 진행하지 말고 이 제한을 사용자에게 알린다.

## 작업 순서

1. **쿼리를 고른다.** 아래 「쿼리 고르기」대로 한다.
2. **앞 쿼리의 결과가 인자로 필요한지 본다.** 아래 「요청 형식」의 쿼리 연결 규칙을 따른다. 기준일이나 비교 날짜를 만드는 쿼리가 따로 있어서 대부분 이 단계에 해당한다.
3. **요청 코드를 쓴다.** 아래 「코드 예시」 형태를 따르고, 등록된 SQL은 코드에 옮겨 적지 않는다.
4. **결과를 쓸 때 설명의 단위와 0행의 뜻을 반영한다.** 억 원·백만 원·원 단위가 쿼리마다 다르고, "0행이면 …"처럼 0행에 뜻이 있는 쿼리도 있다. 설명에 단위나 0행의 뜻이 없으면 모른다고 알리고 한 번 호출해 확인하도록 권한다.
5. **가능하면 실제로 한 번 호출해 확인한다.** 읽기 전용이라 접근 키가 설정돼 있으면 사내망에서 바로 호출해 볼 수 있다. 결과 행 수와 열 이름을 확인하고 사용자에게 알린다.

## 쿼리 고르기

1. **목차의 두 표에서 후보를 고른다.** 필요한 데이터와 설명이 맞는 쿼리를 고른다. 사용자가 SQL을 주었으면 그 SQL이 읽는 테이블·뷰·함수를 목차의 사용 테이블과 대조한다. 집계·계산·여러 테이블 연결이 필요하면 승인 쿼리를 먼저 찾는다. 한 테이블의 행을 그대로 받거나 컬럼·조건으로 줄여 받으면 되는 요청이면 테이블 쿼리를 찾는다.
2. **후보의 SQL을 받아 확인한다.** `--query`로 후보의 등록된 SQL을 받아 결과 열·조건·집계·인자가 사용자가 요청한 데이터와 맞는지 본다. 사용자가 SQL을 주었으면 사용자의 SQL과 등록된 SQL의 결과 열·조건·집계·인자를 비교한다. 후보는 가능성이 높은 순서로 하나씩, 최대 세 개까지 확인한다. 목차만 보고 맞는 쿼리가 없다고 결론 내지 않는다.
3. **맞는 쿼리가 있으면 그 id로 안내한다.** 위 「작업 순서」 3단계대로 요청 코드를 쓴다. 사용자가 준 SQL과 결과 열·조건이 다른 점이 있으면 함께 적고, 실제로 한 번 호출해 확인하라고 권한다.
4. **맞는 쿼리가 없으면 등록 요청 여부를 묻는다.** 클로드는 사용자에게 다른 후보 중에서 고르라고 하지 않는다. 그 데이터를 읽는 쿼리가 아직 없으니 AX팀에 쿼리 등록을 요청할지 사용자에게 묻는다. 사용자가 요청하기로 하면 클로드는 받은 SQL(없으면 필요한 데이터 설명)·필요한 결과 열·관련 테이블과 확인한 쿼리 id를 정리한다. 사용자는 그 정리를 AX팀 요청에 그대로 쓴다.

## 요청 형식

| 항목 | 값 |
|---|---|
| 주소 | `http://192.7.9.45:9101` (사내망). 코드에서는 환경 변수 `QUERY_GATEWAY_URL`로 받고 이 주소를 기본값으로 둔다 |
| 메서드·경로 | `POST /winus/query/{id}`. id는 목차의 정수. 주소 뒤에 인자를 붙이는 `GET /winus/query/{id}?이름=값`은 이전 방식이라 곧 받지 않는다. 기존 코드에서 보이면 지금 동작하더라도 POST로 바꾼다 |
| 인자 | 요청 본문 `{"args": {이름: 값}}`. 이름은 `--query` 출력의 `인자`. 인자가 없는 쿼리는 `{}`를 보낸다 |
| 인증 | 헤더 `Authorization: Bearer <접근 키>`. 키는 환경 변수 `KIWOOM_ACCESS_KEY`에서 읽는다(위 「접근 키」) |

```
POST /winus/query/2    {"args": {"dt": "20260911", "cut": "200000000"}}
POST /winus/query/10   {"args": {"cls": "GT002", "codes": ["001", "002"]}}
POST /winus/query/7    {"args": {"오늘": "20260915"}}
```

인자를 채울 때 지킬 것:

- **키는 `인자` 줄의 이름과 정확히 같아야 한다.** 설명에 `:dt`로 적힌 인자의 키는 `dt`다. 하나라도 빠지거나 모르는 키가 섞이면 DBGateway가 400으로 거절하고, `detail`에 빠진 것·모르는 것·필요한 것을 적어 준다.
- **종류가 `목록`인 인자는 배열로 보낸다.** 값이 하나여도 `["001"]`처럼 배열로 보내고, 빈 배열은 400으로 거절된다. 종류가 `스칼라`인 인자는 문자열 하나를 보내며, 배열을 보내면 400으로 거절된다. 인자 줄에 최대 개수가 적혀 있으면 그보다 많은 값은 나눠 순차로 보낸다.
- **설명이 다른 쿼리의 결과를 넣으라고 하면 그 쿼리를 먼저 호출해 받은 값을 넘긴다.** 설명의 「`:d1`에는 기준일_비교일자(id 1)의 전일 결과를 넣는다」 같은 문장이 그 표시다.
- **값은 문자열이나 문자열 배열로만 보낸다.** 날짜는 `"20260911"`, 코드는 `"001"`처럼 맨 앞 0을 살린 문자열로 만든다. 숫자·`null`·`true`를 보내면 DBGateway가 422로 거절한다.

### 테이블 쿼리

테이블 쿼리는 같은 주소로 부르고, 본문에 아래 세 항목을 더할 수 있다. 셋 다 생략할 수 있고, 승인 쿼리에 보내면 400(`not_a_table_query`)으로 거절된다.

| 항목 | 값 |
|---|---|
| `columns` | 받을 컬럼 이름 배열. `--query` 출력의 `출력 컬럼`에서 고른다. 생략하면 전부 |
| `where` | 결과에서 조건에 맞는 행만 받는다. `{"컬럼": "값"}`은 같음, `{"컬럼": {"연산자": 값}}`은 비교. 연산자는 `=` `!=` `>` `>=` `<` `<=` `between`(값 2개의 배열) `in`(값 배열) `like`. 한 객체에 컬럼을 여럿 적으면 모두 만족하는 행이고, `{"or": [조건, …]}`·`{"and": [조건, …]}`로 묶는다 |
| `limit` | 받을 최대 행 수(3만 이하) |

```
POST /winus/query/177  {"args": {"fund_code": ["0101"], "from_dt": "20261101", "to_dt": "20261110"},
                        "columns": ["일자", "펀드코드", "펀드명"], "where": {"펀드명": {"like": "%채권%"}}}
```

- **기간이 `기간` 줄의 최대 일수를 넘으면 400(`period_too_long`)으로 거절된다.** 종료일 − 시작일이 그 일수 이하가 되게 나눠 순차로 부른다.
- **`where`의 값도 문자열만 받는다.** 크기 비교는 컬럼의 타입을 따르므로, 문자 컬럼은 사전순으로 비교된다. 자릿수가 다른 숫자 문자열(`"9"`와 `"10"`)은 틀리게 비교된다.
- **`in`에 넣을 수 있는 값의 개수에도 상한이 있다.** 넘으면 400(`too_many_in_values`)의 `detail`이 상한을 알려 주므로 그 개수 이하로 나눠 부른다.
- **`limit`보다 결과가 많으면 잘린 채로 200이 온다.** 이때 응답의 `truncated`가 참이다. 어느 행이 남는지는 정해지지 않으므로(등록된 SQL에 `ORDER BY`가 있으면 그 순서의 앞쪽), 잘렸다는 사실을 사용자에게 알린다. `limit`을 주지 않으면 승인 쿼리처럼 3만 행을 넘는 결과가 거절된다.

## 응답

성공하면 200과 함께 봉투가 온다.

```json
{"query_id": 7, "query_name": "기준일", "columns": ["기준일"], "rows": [{"기준일": "20260914"}],
 "truncated": false, "cached": true, "produced_at": "…T09:02:11+09:00", "source": {…}}
```

- **행은 `rows`에 있다.** 봉투째 쓰지 말고 `rows`를 꺼낸다. 결과가 없으면 `rows`가 빈 목록이고, 0행의 뜻은 쿼리 설명을 따른다. `columns`는 열 이름을 결과 순서대로 담는다.
- **`cached`가 참이면 DBGateway가 저장해 둔 결과로 답한 것이다.** 같은 쿼리를 같은 인자로 부르면 원본에서 받은 시각부터 10분 동안 그 결과로 답하고, 이를 건너뛰는 옵션은 없다. `produced_at`은 원본이 그 결과를 낸 시각이다. `cached`가 참이면 답에 「N분 전(HH:MM) 결과」라고 함께 적고, 여러 쿼리를 이어 부른 답이면 가장 이른 `produced_at`을 적는다. 실시간 결과가 꼭 필요하다는 요청에는 AX팀에 그 쿼리의 예외를 요청하라고 안내한다.
- **결과가 3만 행을 넘으면 잘리지 않고 400으로 거절된다.** `detail`이 기간이나 목록을 나눠 질의하라고 안내하므로, 범위 인자는 필요한 만큼만 쓰고 넓으면 나눠 순차로 부른다.
- **행의 키는 SQL의 열 별칭이다.** 한글 별칭은 그대로 오고, 영문 별칭은 대문자로 온다(`seq` → `SEQ`). 별칭이 없는 식은 식 자체가 키다(`COUNT(*)`).
- **값의 타입은 DB 열을 따른다.** 문자 열은 숫자처럼 보여도 `"10"`처럼 문자열로 오고 null도 올 수 있다. 그대로 정렬하면 `"10"`이 `"2"`보다 앞에 오므로, 숫자로 정렬하거나 계산하려면 변환하고 null을 처리한다.
- **응답 시간은 쿼리마다 다르다.** 타임아웃은 30초 이상으로 둔다.

실패 응답은 422·405를 빼면 모두 `{"kind": "…", "code": "…", "detail": "…"}` 모양이다. 무엇을 할지는 `code`로 정하고, 표에 없는 `code`는 `kind`로 정한다. `detail`은 사용자에게 보일 문장이라 그대로 전하고, 프로그램이 읽어 판단하지 않는다.

| 상태 | `kind` | 뜻과 할 일 |
|---|---|---|
| 401 | 신원 거절 | 접근 키가 틀렸거나 폐기됨(`unidentified`). DBGateway가 키 없는 요청을 받지 않으면 키가 없을 때도 온다. 같은 요청을 재시도하지 않고 위 「접근 키」의 순서를 안내한다 |
| 400 | 범위 초과 거절 | 요청을 고쳐야 받는다. 없는 id(허용되지 않은 쿼리의 id도 없는 id와 같게 거절된다), 인자 누락·모르는 인자, 스칼라 인자에 배열, 빈 배열, 목록 인자 개수 초과, 결과 3만 행 초과(`too_many_rows`), 실행 상한을 넘긴 조회, 위 「테이블 쿼리」의 거절. 같은 요청을 재시도하지 않는다. `detail`이 나눠 질의하라고 하면 그대로 나눠 순차로 부른다 |
| 422 | (없음) | 본문 형식 오류(값이 문자열·문자열 배열이 아님, 본문의 모르는 항목) 또는 경로의 id가 정수가 아님. 본문은 `{"detail": [{"type": "…", "loc": ["body", "args", "<인자 이름>", …], "msg": "…"}]}`이고, `loc`의 셋째 칸이 문제의 인자 이름이다. 보낸 값은 응답에 실리지 않는다 |
| 405 | (없음) | 이전 방식 `GET /winus/query/{id}?이름=값`으로 불렀음. 본문은 `{"detail": "Method Not Allowed"}`다. 같은 요청을 재시도하지 않고 위 「요청 형식」대로 POST 본문으로 바꾼다. 목록 인자는 같은 이름을 반복하지 않고 문자열 배열로, 숫자도 문자열로 보낸다 |
| 429 | 혼잡 거절 | 이 사람의 몫을 다 씀. 사람당 대기 조회 수·초당 요청 수 상한 초과, 큐 대기 예상 초과는 잠시 뒤 다시 보낸다. 아래 두 `code`는 다르게 처리한다 |
| 429 | 혼잡 거절 | `source_time_exceeded`: 이 사람이 쓸 수 있는 원본 사용 시간을 다 씀. 늦춰 보내도 다시 찰 때까지 풀리지 않는다. `Retry-After`의 초만큼 기다리거나, 그 시간이 길면 다시 보내지 않고 거절을 그대로 올린다. 기간이나 목록을 줄이면 한 번에 쓰는 원본 시간이 준다 |
| 429 | 혼잡 거절 | `caller_stopped`: 운영자가 이 사람의 조회를 중지함. `detail`에 운영자가 적은 사유가 있다. 언제 풀리는지 알리지 않으므로 다시 보내지 않고 거절을 그대로 올린다. `detail`과 함께 AX팀에 문의하라고 전한다 |
| 503 | 혼잡 거절 | 원본이 받을 수 없음(원본 불통·차단, 운영자의 원본 조회 중지 `source_stopped`, 이 쿼리가 쓰는 WINUS 계정을 지금 쓸 수 없음 `account_unavailable`). 언제 풀릴지 DBGateway도 모르므로 정한 횟수만 다시 보내고, 그래도 같으면 거절을 그대로 올린다 |
| 503 | 판정 불능 | DBGateway가 요청을 받을지 거절할지 정하지 못함. 일시적일 수도, DBGateway 쪽 문제일 수도 있다. 한 번만 다시 보내고, 같으면 거절을 그대로 올린다. `detail`과 함께 AX팀에 알리라고 전한다 |
| 그 밖 5xx | 형식 미확인 | DBGateway나 DB 쪽 오류 |

**여러 번 호출할 때는 순차로 보낸다.** DBGateway는 사람마다 대기 조회 수와 초당 요청 수를 제한하므로, 펀드마다 쿼리를 호출하는 반복문을 스레드로 늘려 봐야 429만 늘어난다. 다시 보낼 때는 응답 헤더 `Retry-After`가 있으면 그 초만큼 기다리고, 없으면 몇 초씩 늘려 가며 정한 횟수만 보낸다.

**거절을 그대로 올리면 그다음은 누가 부르느냐에 따라 다르다.** 클로드가 직접 조회했으면 클로드가 그 오류를 보고 `detail`과 할 일을 사용자에게 전한다. 예약 작업처럼 자동으로 실행되는 코드면 알려 줄 사람이 없으므로, 호출한 쪽이 거절(코드 예시의 `Refused`)을 받아 기록을 남기거나 담당자에게 알리게 짠다.

## 코드 없이 바로 조회할 때

사용자가 코드가 아니라 데이터 자체를 물으면(예: 어제 기준 당사 ETF 순자산 상위 5개) 쿼리를 고르고 잇는 방법은 위 「작업 순서」 1·2단계와 같다. 조회는 짧은 파이썬 스크립트로 한다.

- **아래 코드 예시의 `fetch_retrying`을 쓴 스크립트 파일을 만들어 `uv run --with httpx <스크립트 파일>`로 실행한다.** 본문 만들기와 응답 해석을 `httpx`가 맡는다.
- **스크립트 파일에 `# /// script` 의존성 블록을 넣지 않는다.** 이 블록이 있으면 uv가 서명 없는 자체 런처로 환경을 만들고, 사내 PC의 V3가 그 런처를 차단한다. 의존성은 `--with`로만 준다.
- **스크립트 첫머리에서 `sys.stdout.reconfigure(encoding="utf-8")`를 호출한다.** Windows에서 출력이 파이프로 나가면 파이썬이 CP949로 쓰기 때문에 `−`·`—` 같은 문자에서 `UnicodeEncodeError`로 멈춘다.
- **PowerShell의 `Invoke-RestMethod`·`Invoke-WebRequest`와 `curl` 별칭을 쓰지 않는다.** DBGateway 응답 헤더에 문자 인코딩이 적혀 있지 않아 PowerShell 5가 한글 열 이름과 값을 깨뜨린다. PowerShell 5의 `curl`은 `Invoke-WebRequest`를 가리킨다.
- **답에는 기준일과 단위를 함께 적는다.** 단위는 쿼리 설명을 따르고, 설명에 없으면 단위를 모른다고 적는다. 저장해 둔 결과(`cached`)였거나 잘린 결과(`truncated`)였으면 그것도 적는다.

## 코드 예시

```python
import os
import time

import httpx

GATEWAY_URL = os.environ.get("QUERY_GATEWAY_URL", "http://192.7.9.45:9101")
KEY_PAGE = "http://192.7.9.45:3000/#access-key"
# 키 원문은 코드에 적지 않고 환경 변수로만 받는다. 앞뒤 공백·줄바꿈이 섞이면 헤더가 깨지므로 지운다.
ACCESS_KEY = os.environ.get("KIWOOM_ACCESS_KEY", "").strip()
if not ACCESS_KEY:
    raise SystemExit(f"접근 키 없음: 환경 변수 KIWOOM_ACCESS_KEY. 설정했으면 창을 모두 닫고 다시 열기, 아니면 {KEY_PAGE} 에서 발급해 설정")

# id만으로는 무엇인지 알 수 없으므로 목차의 이름을 상수 이름에 남긴다.
Q_기준일_비교일자 = 1
Q_당사_ETF_순자산 = 5
Q_내부코드명 = 10
Q_펀드마스타_기간_테이블 = 177
MAX_TRIES = 3


class Refused(Exception):
    """DBGateway 의 400·429·503 거절. 무엇을 할지는 code 로 정하고, detail 은 사용자에게 그대로 전한다."""

    def __init__(self, query_id: int, status: int, body: dict, retry_after: str | None):
        super().__init__(f"쿼리 {query_id} {body.get('kind')}({status}, {body.get('code')}): {body.get('detail')}")
        self.status, self.kind, self.code = status, body.get("kind"), body.get("code")
        self.retry_after = float(retry_after) if retry_after else None


def fetch(query_id: int, args: dict[str, str | list[str]], **table) -> dict:
    """한 번 부른다. table 은 테이블 쿼리에만 주는 columns·where·limit 이다."""
    r = httpx.post(f"{GATEWAY_URL}/winus/query/{query_id}", json={"args": args, **table},
                   headers={"Authorization": f"Bearer {ACCESS_KEY}"}, timeout=30)
    if r.status_code == 401:
        raise PermissionError(f"DBGateway 신원 거절(401): {r.json()['detail']}. 새 키를 설정했으면 창을 모두 닫고 다시 열기, 아니면 {KEY_PAGE} 에서 재발급해 설정")
    if r.status_code == 422:
        names = sorted({e["loc"][2] for e in r.json()["detail"] if len(e["loc"]) > 2})
        raise ValueError(f"쿼리 {query_id} 형식 오류: 인자 {names}의 값이 문자열이나 문자열 배열이 아님")
    if r.status_code in (400, 429, 503):
        raise Refused(query_id, r.status_code, r.json(), r.headers.get("Retry-After"))
    r.raise_for_status()
    # 행과 함께 언제 결과인지(cached·produced_at), 잘렸는지(truncated)를 돌려준다. 답에 함께 적어야 한다.
    return r.json()


# 이보다 오래 기다려야 하면 다시 보내지 않는다. 사람이 결과를 기다리는 조회 기준이고, 자동으로 실행되는 작업이면 늘려도 된다.
MAX_WAIT_SECONDS = 10


def wait_before_retry(e: Refused, tries: int) -> float | None:
    """거절 e 를 tries 번째로 받았을 때 다시 보내기 전에 기다릴 초. None 이면 다시 보내지 않고 거절을 그대로 올린다."""
    if e.status == 400 or e.code == "caller_stopped" or tries >= MAX_TRIES:
        return None
    if e.code == "source_time_exceeded":
        # 원본 사용 시간이 다시 찰 때까지는 늦춰 보내도 같은 답이다. 오래 걸리면 조용히 기다리지 않는다.
        return e.retry_after if e.retry_after and e.retry_after <= MAX_WAIT_SECONDS else None
    if e.kind == "판정 불능":
        return 5.0 if tries == 1 else None
    return e.retry_after or 5.0 * 2 ** (tries - 1)


def fetch_retrying(query_id: int, args: dict[str, str | list[str]], **table) -> dict:
    """혼잡 거절이면 wait_before_retry 가 정한 만큼 기다렸다 다시 보낸다. 그 밖의 거절은 그대로 올린다."""
    tries = 0
    while True:
        try:
            return fetch(query_id, args, **table)
        except Refused as e:
            tries += 1
            wait = wait_before_retry(e, tries)
            if wait is None:
                raise
            time.sleep(wait)


날짜 = fetch_retrying(Q_기준일_비교일자, {"오늘": "20260915"})["rows"][0]
당사_etf = fetch_retrying(Q_당사_ETF_순자산, {
    "d0": 날짜["기준일"], "d1": 날짜["전일"],
    "d2": 날짜["당사전월말"], "d3": 날짜["당사전년말"],
    "cls": "44",
})
```
