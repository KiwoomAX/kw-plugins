# searching-winus

등록된 쿼리는 모두 조회다. 이 스킬로는 데이터를 바꾸지 못한다. 클라이언트는 SQL을 모른 채 쿼리 id와 인자만 보낸다. DBGateway가 id로 등록된 SQL을 찾아 인자를 바인딩해 실행한다. SQL을 클라이언트에 드러내지 않으려고 이렇게 나눴다. 여러 쿼리를 잇는 일(앞 결과를 뒤 인자로 넘기기)은 호출하는 쪽이 한다.

```
[클라이언트 코드] --GET /winus/query/{id}?인자--> [DBGateway] --등록된 SQL + 인자--> [WINUS]
```

요청할 수 있는 쿼리 목록이 매니페스트다. 매니페스트는 목차와 화면별 상세 두 층이다. 목차는 사내 DB 화면 단위로, 화면마다 화면 설명과 그 화면 쿼리의 id·이름·한 줄 요약만 싣는다. 화면별 상세는 그 화면 쿼리의 사용법으로, 쿼리마다 설명과 인자 표(뜻·보내는 법·예시·값을 얻는 곳)와 결과 항목 표(뜻·단위·비어 올 수 있음)를 싣는다. 코드를 쓰기 전에 목차를 받아 화면을 고르고, 고른 화면의 상세를 받아 읽는다.

```
uv run --no-project --with "kiwoom-mdb-manager @ git+https://github.com/KiwoomAM/Kiwoom-Manager.git@807890e686106719a0aa2f0aa054d6573dc16d65#subdirectory=mdb-manager" python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py"
uv run --no-project --with "kiwoom-mdb-manager @ git+https://github.com/KiwoomAM/Kiwoom-Manager.git@807890e686106719a0aa2f0aa054d6573dc16d65#subdirectory=mdb-manager" python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py" --screen <화면번호>
```

첫째 명령은 목차를, 둘째 명령은 적은 화면의 상세를 낸다. 화면번호는 목차의 화면 제목에 적힌 번호를 그대로 쓴다. 한 요청에 쓸 쿼리가 여러 화면에 걸쳐 있다는 것을 이미 알 때만 번호를 여럿 적는다.

명령은 줄이지 말고 그대로 쓴다. `uv run <스크립트>`로 줄이면 uv가 서명 없는 자체 런처로 환경을 만들고, 사내 PC의 V3가 그 런처를 차단해 명령이 응답 없이 멈추거나 `os error 5`로 실패한다.

- **매니페스트는 이 스크립트의 출력으로만 읽는다.** 스크립트가 남기는 사본 파일을 직접 열면 필요 없는 화면까지 모두 읽게 된다.
- **후보 화면은 가능성이 높은 순서로 하나씩, 최대 세 개까지 확인한다.** 요청한 데이터가 목차에 드러나지 않으면(열 이름 등) 가장 유력한 화면 하나를 받아 결과 항목 표를 보고, 없을 때만 다음 후보를 받는다. 목차만 보고 맞는 쿼리가 없다고 결론 내지 않는다.
- **세 화면에도 없으면 등록 요청을 안내한다.** 사용자에게 그 데이터를 읽는 쿼리가 아직 없으며 AX팀에 쿼리 등록을 요청해야 한다고 알린다. 확인한 화면과 필요한 결과 항목을 함께 적어 요청에 바로 쓸 수 있게 한다.
- **인자의 값을 얻는 곳은 언제나 같은 화면의 쿼리다.** 쿼리를 이을 때 다른 화면의 상세를 더 받을 필요가 없다.

첫 줄에 **경고**가 붙어 나오면 매니페스트가 최신이 아닐 수 있다는 뜻이다. 그 문장을 그대로 사용자에게 알리고 작업을 이어 간다.

> DBGateway는 PoC(0.1.0)다. 이 문서에 적힌 것과 실제 응답이 다르면 맞춰 넘기지 말고 사용자에게 알린다.

## 요청 형식

| 항목 | 값 |
|---|---|
| 주소 | `http://192.7.9.45:9101` (사내망). 코드에서는 환경변수 `QUERY_GATEWAY_URL`로 받고 이 주소를 기본값으로 둔다 |
| 메서드·경로 | `GET /winus/query/{id}` — id는 매니페스트의 정수 |
| 인자 | 질의 문자열에 `이름=값`. 이름은 매니페스트의 `인자 키` |
| 인증 | 없음 |

```
GET /winus/query/2?dt=20260911&cut=200000000
GET /winus/query/10?cls=GT002&codes=001&codes=002
GET /winus/query/7?%EC%98%A4%EB%8A%98=20260915        # 키 '오늘'을 퍼센트 인코딩
```

인자를 채울 때 지킬 것:

- **키는 매니페스트의 `인자 키`와 정확히 같아야 한다.** 설명에 `:dt`로 적힌 인자의 키는 `dt`다. 하나라도 빠지거나 모르는 키가 섞이면 DBGateway가 400으로 거절하고, `detail`에 빠진 것·모르는 것·필요한 것을 적어 준다.
- **목록 인자는 같은 키를 반복한다.** `httpx`·`requests`는 값에 리스트를 주면 그렇게 보낸다(`params={"codes": ["001", "002"]}`). 값이 하나여도 된다.
- **한글 키(`오늘`)는 퍼센트 인코딩해야 한다.** `httpx`·`requests`·`urllib.parse.urlencode`는 알아서 인코딩한다. URL 문자열을 손으로 이어 붙이거나 `curl --data-urlencode '오늘=…'`을 쓰면 키가 인코딩되지 않은 채 나가 서버에 닿기 전에 거부된다(`Invalid HTTP request received`).
- **값은 문자열로 만든다.** 질의 문자열이라 어차피 문자열로 전달되지만, 날짜는 `"20260911"`, 코드는 `"001"`처럼 맨 앞 0을 살린 문자열로 만들어 넘긴다.

## 응답

성공하면 200과 함께 봉투가 온다.

```json
{"query_id": 7, "query_name": "기준일", "rows": [{"기준일": "20260914"}], "truncated": false}
```

- **행은 `rows`에 있다.** 봉투째 쓰지 말고 `rows`를 꺼낸다. 결과가 없으면 `rows`가 빈 목록이고, 0행의 뜻은 매니페스트의 쿼리 설명을 따른다.
- **`truncated`가 true면 DBGateway가 행을 잘랐다는 뜻이다.** 일부 행만 온 것이므로 조용히 쓰지 말고 오류로 올리거나 사용자에게 알린다. 등록된 쿼리 중 결과가 가장 큰 id 8(전체 펀드로 조회하면 사백여 행)도 잘리지 않는다.
- **행의 키는 SQL의 열 별칭이다.** 한글 별칭은 그대로 오고, 영문 별칭은 대문자로 온다(id 6의 `SEQ`·`CNT`·`DEPT_SRT`, id 8의 `D1_F`). 별칭이 없는 식은 식 자체가 키다(id 3의 `COUNT(*)`).
- **값의 타입은 DB 열을 따른다.** 문자 열은 숫자처럼 보여도 문자열로 온다. id 9의 `순서`는 `"10"`처럼 오고 null인 행도 있어서, 그대로 정렬하면 `"10"`이 `"2"`보다 앞에 온다. 숫자로 정렬하거나 계산하려면 변환하고 null을 처리한다.
- **응답 시간은 쿼리마다 다르다.** 0.03~5초이고 id 4가 가장 느리다. 타임아웃은 30초 이상으로 둔다.

실패 응답:

| 상태 | 본문 | 뜻 |
|---|---|---|
| 400 | `{"kind": "범위 초과 거절", "detail": "…"}` | 없는 id, 인자 누락, 모르는 인자. `detail`을 그대로 오류 메시지로 올린다 |
| 422 | FastAPI 검증 오류 | 경로의 id가 정수가 아님 |
| 429 | `{"kind": "혼잡 거절", "detail": "동시 조회 2건 사용 중…"}` | 동시 조회 한도(2건) 초과. 한도는 다른 사용자와 함께 쓴다 |
| 503 | 형식 미확인 | DBGateway 안에서 조회가 제한 시간(약 17초)을 넘긴 것으로 보고됐다 |
| 그 밖 5xx | 형식 미확인 | DBGateway나 DB 쪽 오류 |

**여러 번 호출할 때는 순차로 보낸다.** 동시 조회 한도가 2건이고 다른 사용자와 나눠 쓰므로, 펀드마다 쿼리를 호출하는 반복문을 스레드로 늘려 봐야 429만 늘어난다. 429와 503은 읽기 요청이라 몇 초 기다렸다 다시 보내도 안전하니, 횟수를 정해 재시도한다.

## 코드 없이 바로 조회할 때

사용자가 코드가 아니라 데이터 자체를 물으면(예: 어제 기준 당사 ETF 순자산 상위 5개) 쿼리를 고르고 잇는 방법은 아래 작업 순서 1·2단계와 같다. 조회는 짧은 파이썬 스크립트로 한다.

- **아래 코드 예시의 `fetch`를 쓴 스크립트 파일을 만들어 `uv run --with httpx <스크립트 파일>`로 실행한다.** 한글 키 인코딩과 응답 해석을 `httpx`가 맡는다.
- **스크립트 파일에 `# /// script` 의존성 블록을 넣지 않는다.** 이 블록이 있으면 uv가 서명 없는 자체 런처로 환경을 만들고, 사내 PC의 V3가 그 런처를 차단한다. 의존성은 `--with`로만 준다.
- **스크립트 첫머리에서 `sys.stdout.reconfigure(encoding="utf-8")`를 호출한다.** Windows에서 출력이 파이프로 나가면 파이썬이 CP949로 쓰기 때문에 `−`·`—` 같은 문자에서 `UnicodeEncodeError`로 멈춘다.
- **PowerShell의 `Invoke-RestMethod`·`Invoke-WebRequest`와 `curl` 별칭을 쓰지 않는다.** DBGateway 응답 헤더에 문자 인코딩이 적혀 있지 않아 PowerShell 5가 한글 열 이름과 값을 깨뜨린다. PowerShell 5의 `curl`은 `Invoke-WebRequest`를 가리킨다.
- **답에는 기준일과 단위를 함께 적는다.** 단위는 `결과 항목` 표를 그대로 따른다.

## 작업 순서

1. **목차로 화면을 고르고 상세로 쿼리를 정한다.** 위 `fetch_manifest.py` 를 인자 없이 돌려 목차를 읽고, 필요한 데이터가 화면 설명·쿼리 요약과 맞는 화면을 고른다. 그 화면을 `--screen`으로 받아 `결과 항목` 표와 맞는 쿼리를 정하고, 없으면 다음 후보 화면을 받는다. 후보 화면 세 개까지 확인해도 맞는 쿼리가 없으면 SQL을 직접 쓰지 말고, 아직 등록된 쿼리가 없으니 AX팀에 등록을 요청해야 한다고 사용자에게 알린다.
2. **앞 쿼리의 결과가 인자로 필요한지 본다.** 인자 표의 `값을 얻는 곳`에 쿼리 이름과 결과 항목이 적혀 있으면, 그 쿼리를 먼저 호출해 받은 값을 넘긴다. 기준일이나 비교 날짜를 만드는 쿼리가 따로 있어서 대부분 이 단계에 해당한다.
3. **요청 코드를 쓴다.** 아래 예시 형태를 따른다.
4. **결과를 쓸 때 `결과 항목` 표의 단위와 `비어 올 수 있음`을 반영한다.** 억 원·백만 원·원 단위가 쿼리마다 다르고, "0행이면 …"처럼 빈 결과에 뜻이 있는 쿼리도 있다.
5. **가능하면 실제로 한 번 호출해 확인한다.** 읽기 전용이라 사내망에서 바로 호출해 볼 수 있다. 결과 행 수와 열 이름을 확인하고 사용자에게 알린다.

## 코드 예시

```python
import os

import httpx

GATEWAY_URL = os.environ.get("QUERY_GATEWAY_URL", "http://192.7.9.45:9101")

# id만으로는 무엇인지 알 수 없으므로 매니페스트의 이름을 상수 이름에 남긴다.
Q_기준일_비교일자 = 1
Q_당사_ETF_순자산 = 5
Q_내부코드명 = 10


def fetch(query_id: int, args: dict[str, str | list[str]]) -> list[dict]:
    r = httpx.get(f"{GATEWAY_URL}/winus/query/{query_id}", params=args, timeout=30)
    if r.status_code == 400:
        raise ValueError(f"쿼리 {query_id} 거절: {r.json()['detail']}")
    r.raise_for_status()
    body = r.json()
    if body["truncated"]:
        raise RuntimeError(f"쿼리 {query_id} 결과가 잘렸다 — 일부 행만 왔다")
    return body["rows"]


날짜 = fetch(Q_기준일_비교일자, {"오늘": "20260915"})[0]
당사_etf = fetch(Q_당사_ETF_순자산, {
    "d0": 날짜["기준일"], "d1": 날짜["전일"],
    "d2": 날짜["당사전월말"], "d3": 날짜["당사전년말"],
    "cls": "44",
})
카테고리명 = fetch(Q_내부코드명, {"cls": "GT002", "codes": ["001", "002"]})  # 코드는 분류에 맞게: GT002는 카테고리
```

- `async def` 안에서는 `httpx.AsyncClient`를 쓰고 앱 종료 시 닫는다. 동기 호출은 이벤트 루프를 차단한다.
- 결과 열 이름은 매니페스트 `결과 항목`의 이름과 대조해 쓴다.
