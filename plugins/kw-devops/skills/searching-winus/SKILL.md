# searching-winus

등록된 쿼리는 모두 조회다. 이 스킬로는 데이터를 바꾸지 못한다. 조회도 인자를 요청 본문에 넣어 `POST`로 보내지만, 데이터는 바뀌지 않는다. DBGateway는 쿼리 id로 등록된 SQL을 찾아 인자를 바인딩해 실행하고, 클라이언트 코드는 쿼리 id와 인자만 보낸다. Claude는 쿼리를 고르려고 등록된 SQL을 읽을 수 있지만, 사용자 코드나 문서에는 SQL을 옮겨 적지 않고 쿼리 id로만 요청하게 한다. 여러 쿼리를 잇는 일(앞 결과를 뒤 인자로 넘기기)은 호출하는 쪽이 한다.

```
[클라이언트 코드] --POST /winus/query/{id} + 접근 키 + 본문의 인자--> [DBGateway] --등록된 SQL + 인자--> [WINUS]
```

요청할 수 있는 쿼리 목록이 매니페스트다. 매니페스트는 목차와 쿼리별 SQL 두 층이고, 쿼리별 SQL은 id로 받는다. 목차는 쿼리마다 id·이름·설명·사용 테이블을 한 행에 싣는다.

목차의 설명은 쿼리가 무엇을 계산하는지 적는다. 인자 값의 뜻과 결과의 단위까지 적은 설명도 있지만, 모든 설명에 있지는 않다. 사용 테이블은 그 쿼리가 읽는 테이블·뷰·함수다.

```
python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py"
python "${CLAUDE_SKILL_DIR}/scripts/fetch_manifest.py" --query <id> [<id> …]
```

첫째 명령은 목차를 내고, 둘째 명령은 적은 id마다 이름·설명·사용 테이블·인자·등록된 SQL을 낸다. 인자 줄은 DBGateway가 요구하는 인자 이름과 그 종류(`스칼라`·`목록`)다.

- **매니페스트는 이 스크립트의 출력으로만 읽는다.** 등록된 SQL은 `--query`로 고른 쿼리만 받는다.
- **첫 줄의 경고는 사용자에게 알리고 작업을 이어 간다.** 경고는 매니페스트가 최신이 아닐 수 있다는 뜻이다.

> DBGateway는 PoC(0.1.0)다. 이 문서에 적힌 것과 실제 응답이 다르면 맞춰 넘기지 말고 사용자에게 알린다.

## 접근 키

DBGateway는 요청마다 접근 키로 요청한 사람을 확인하고, 그 사람에게 허용된 쿼리만 목차에 포함하고 실행한다. 접근 키는 `kwam_`으로 시작하는 개인 키이고, 이 PC의 환경변수 `KIWOOM_ACCESS_KEY`에 설정해 둔다. `fetch_manifest.py`와 요청 코드는 그 환경변수에서 키를 읽어 `Authorization: Bearer <키>` 헤더로 보낸다. 키 없이 보내면 전환 기간에는 `PUBLIC` 쿼리만 보이고 팀 전용 쿼리는 없는 id처럼 거절되며, 전환이 끝나면 401로 거절된다(Kiwoom-DBgateway ADR-0043). 그래서 `fetch_manifest.py`는 키가 없으면 요청하지 않고 멈춘다.

`fetch_manifest.py`가 `접근 키 없음`이나 `DBGateway 신원 거절(401)`로 멈추면, 출력의 `조치` 줄에 접근 키 화면 주소와 브라우저로 열었는지가 적혀 있다. `브라우저로 열지 못함`이면 그 주소를 사용자에게 알린다. Claude는 사용자에게 아래 순서를 안내하고, 키가 설정될 때까지 조회를 진행하지 않는다.

1. 열린 화면에서 사내 계정으로 로그인하고 「키 발급」을 누른다. 키가 있는데 거절됐으면 「재발급」을 누른다. 키 원문은 발급 직후 한 번만 보인다.
2. 같은 화면 「사용 방법」의 Windows 명령이나 Claude Code 프롬프트로 키를 환경변수 `KIWOOM_ACCESS_KEY`에 설정한다.
3. 새 Claude Code 세션을 시작해 같은 요청을 다시 한다. 환경변수는 설정한 뒤에 시작한 세션에만 보인다.

- **키 원문을 대화·코드·문서에 적지 않는다.** 사용자가 키를 대화에 붙여 넣으려 하면 멈추게 하고, Claude도 키 값을 출력하는 명령을 실행하지 않는다. 키가 설정됐는지는 `fetch_manifest.py`를 실행해 확인한다.
- **여러 사람이 쓰는 서버나 배포한 서비스에는 개인 키를 설정하지 않는다.** 그 서비스의 모든 요청이 키 주인의 권한으로 처리된다. 그런 코드를 요청받으면 개인 키로 진행하지 말고 이 제한을 사용자에게 알린다.

## 작업 순서

1. **쿼리를 고른다.** 아래 「쿼리 고르기」대로 한다.
2. **앞 쿼리의 결과가 인자로 필요한지 본다.** 아래 「요청 형식」의 쿼리 연결 규칙을 따른다. 기준일이나 비교 날짜를 만드는 쿼리가 따로 있어서 대부분 이 단계에 해당한다.
3. **요청 코드를 쓴다.** 아래 「코드 예시」 형태를 따르고, 등록된 SQL은 코드에 옮겨 적지 않는다.
4. **결과를 쓸 때 설명의 단위와 0행의 뜻을 반영한다.** 억 원·백만 원·원 단위가 쿼리마다 다르고, "0행이면 …"처럼 0행에 뜻이 있는 쿼리도 있다. 설명에 단위나 0행의 뜻이 없으면 모른다고 알리고 한 번 호출해 확인하도록 권한다.
5. **가능하면 실제로 한 번 호출해 확인한다.** 읽기 전용이라 접근 키가 설정돼 있으면 사내망에서 바로 호출해 볼 수 있다. 결과 행 수와 열 이름을 확인하고 사용자에게 알린다.

## 쿼리 고르기

1. **목차에서 후보를 고른다.** 필요한 데이터와 설명이 맞는 쿼리를 고른다. 사용자가 SQL을 주었으면 그 SQL이 읽는 테이블·뷰·함수를 목차의 사용 테이블과 대조한다.
2. **후보의 SQL을 받아 확인한다.** `--query`로 후보의 등록된 SQL을 받아 결과 열·조건·집계·인자가 사용자가 요청한 데이터와 맞는지 본다. 사용자가 SQL을 주었으면 사용자의 SQL과 등록된 SQL의 결과 열·조건·집계·인자를 비교한다. 후보는 가능성이 높은 순서로 하나씩, 최대 세 개까지 확인한다. 목차만 보고 맞는 쿼리가 없다고 결론 내지 않는다.
3. **맞는 쿼리가 있으면 그 id로 안내한다.** 위 「작업 순서」 3단계대로 요청 코드를 쓴다. 사용자가 준 SQL과 결과 열·조건이 다른 점이 있으면 함께 적고, 실제로 한 번 호출해 확인하라고 권한다.
4. **맞는 쿼리가 없으면 등록 요청 여부를 묻는다.** Claude는 사용자에게 다른 후보 중에서 고르라고 하지 않는다. 그 데이터를 읽는 쿼리가 아직 없으니 AX팀에 쿼리 등록을 요청할지 사용자에게 묻는다. 사용자가 요청하기로 하면 Claude는 받은 SQL(없으면 필요한 데이터 설명)·필요한 결과 열·관련 테이블과 확인한 쿼리 id를 정리한다. 사용자는 그 정리를 AX팀 요청에 그대로 쓴다.

## 요청 형식

| 항목 | 값 |
|---|---|
| 주소 | `http://192.7.9.45:9101` (사내망). 코드에서는 환경변수 `QUERY_GATEWAY_URL`로 받고 이 주소를 기본값으로 둔다 |
| 메서드·경로 | `POST /winus/query/{id}` — id는 목차의 정수 |
| 인자 | 요청 본문 `{"args": {이름: 값}}`. 이름은 `--query` 출력의 `인자`. 인자가 없는 쿼리는 `{}`를 보낸다 |
| 인증 | 헤더 `Authorization: Bearer <접근 키>`. 키는 환경변수 `KIWOOM_ACCESS_KEY`에서 읽는다(위 「접근 키」) |

```
POST /winus/query/2    {"args": {"dt": "20260911", "cut": "200000000"}}
POST /winus/query/10   {"args": {"cls": "GT002", "codes": ["001", "002"]}}
POST /winus/query/7    {"args": {"오늘": "20260915"}}
```

인자를 채울 때 지킬 것:

- **키는 `인자` 줄의 이름과 정확히 같아야 한다.** 설명에 `:dt`로 적힌 인자의 키는 `dt`다. 하나라도 빠지거나 모르는 키가 섞이면 DBGateway가 400으로 거절하고, `detail`에 빠진 것·모르는 것·필요한 것을 적어 준다.
- **종류가 `목록`인 인자는 배열로 보낸다.** 값이 하나여도 `["001"]`처럼 배열로 보내고, 빈 배열은 400으로 거절된다. 종류가 `스칼라`인 인자는 문자열 하나를 보내며, 배열을 보내면 400으로 거절된다. 인자 줄에 최대 개수가 적혀 있으면 그보다 많은 값은 나눠 순차로 보낸다.
- **설명이 다른 쿼리의 결과를 넣으라고 하면 그 쿼리를 먼저 호출해 받은 값을 넘긴다.** 설명의 「`:d1`에는 기준일_비교일자(id 1)의 전일 결과를 넣는다」 같은 문장이 그 표시다.
- **값은 문자열이나 문자열 배열로만 보낸다.** 날짜는 `"20260911"`, 코드는 `"001"`처럼 맨 앞 0을 살린 문자열로 만든다. 숫자·`null`·`true`를 보내면 DBGateway가 422로 거절한다.

## 응답

성공하면 200과 함께 봉투가 온다.

```json
{"query_id": 7, "query_name": "기준일", "rows": [{"기준일": "20260914"}]}
```

- **행은 `rows`에 있다.** 봉투째 쓰지 말고 `rows`를 꺼낸다. 결과가 없으면 `rows`가 빈 목록이고, 0행의 뜻은 쿼리 설명을 따른다.
- **결과가 3만 행을 넘으면 잘리지 않고 400으로 거절된다.** `detail`이 기간이나 목록을 나눠 질의하라고 안내하므로, 범위 인자는 필요한 만큼만 쓰고 넓으면 나눠 순차로 부른다.
- **행의 키는 SQL의 열 별칭이다.** 한글 별칭은 그대로 오고, 영문 별칭은 대문자로 온다(`seq` → `SEQ`). 별칭이 없는 식은 식 자체가 키다(`COUNT(*)`).
- **값의 타입은 DB 열을 따른다.** 문자 열은 숫자처럼 보여도 `"10"`처럼 문자열로 오고 null도 올 수 있다. 그대로 정렬하면 `"10"`이 `"2"`보다 앞에 오므로, 숫자로 정렬하거나 계산하려면 변환하고 null을 처리한다.
- **응답 시간은 쿼리마다 다르다.** 타임아웃은 30초 이상으로 둔다.

실패 응답:

| 상태 | 본문 | 뜻 |
|---|---|---|
| 401 | `{"kind": "신원 거절", "code": "unidentified", "detail": "…"}` | 접근 키가 없거나(키 확인 전환이 끝난 뒤) 틀렸거나 폐기됨. 같은 요청을 재시도하지 않고 위 「접근 키」의 순서를 안내한다 |
| 400 | `{"kind": "범위 초과 거절", "detail": "…"}` | 없는 id(허용되지 않은 쿼리의 id도 없는 id와 같게 거절된다), 인자 누락·모르는 인자, 스칼라 인자에 배열, 빈 배열, 목록 인자 개수 초과, 결과 3만 행 초과, 실행 상한을 넘긴 조회. `detail`을 그대로 올리고 같은 요청을 재시도하지 않는다(시간 초과는 조건을 좁혀 다시 질의한다) |
| 422 | `{"detail": [{"type": "…", "loc": ["body", "args", "<인자 이름>", …], "msg": "…"}]}` | 본문 형식 오류(값이 문자열·문자열 배열이 아님, 본문의 모르는 칸) 또는 경로의 id가 정수가 아님. `loc`의 셋째 칸이 문제의 인자 이름이다. 보낸 값은 응답에 실리지 않는다 |
| 429 | `{"kind": "혼잡 거절", "detail": "큐에 세운 조회 N건 사용 중…"}` | 사람당 대기 조회 수·초당 요청 수 상한 초과, 또는 큐 대기 예상 초과 |
| 503 | `{"kind": "혼잡 거절" 또는 "판정 불능", "detail": "…"}` | 원본 DB 불통·차단 상태 등으로 DBGateway가 판정하지 못함 |
| 그 밖 5xx | 형식 미확인 | DBGateway나 DB 쪽 오류 |

**여러 번 호출할 때는 순차로 보낸다.** DBGateway는 사람마다 대기 조회 수와 초당 요청 수를 제한하므로, 펀드마다 쿼리를 호출하는 반복문을 스레드로 늘려 봐야 429만 늘어난다. 429와 503은 읽기 요청이라 몇 초 기다렸다 다시 보내도 안전하니, 횟수를 정해 재시도한다.

## 코드 없이 바로 조회할 때

사용자가 코드가 아니라 데이터 자체를 물으면(예: 어제 기준 당사 ETF 순자산 상위 5개) 쿼리를 고르고 잇는 방법은 위 「작업 순서」 1·2단계와 같다. 조회는 짧은 파이썬 스크립트로 한다.

- **아래 코드 예시의 `fetch`를 쓴 스크립트 파일을 만들어 `uv run --with httpx <스크립트 파일>`로 실행한다.** 본문 만들기와 응답 해석을 `httpx`가 맡는다.
- **스크립트 파일에 `# /// script` 의존성 블록을 넣지 않는다.** 이 블록이 있으면 uv가 서명 없는 자체 런처로 환경을 만들고, 사내 PC의 V3가 그 런처를 차단한다. 의존성은 `--with`로만 준다.
- **스크립트 첫머리에서 `sys.stdout.reconfigure(encoding="utf-8")`를 호출한다.** Windows에서 출력이 파이프로 나가면 파이썬이 CP949로 쓰기 때문에 `−`·`—` 같은 문자에서 `UnicodeEncodeError`로 멈춘다.
- **PowerShell의 `Invoke-RestMethod`·`Invoke-WebRequest`와 `curl` 별칭을 쓰지 않는다.** DBGateway 응답 헤더에 문자 인코딩이 적혀 있지 않아 PowerShell 5가 한글 열 이름과 값을 깨뜨린다. PowerShell 5의 `curl`은 `Invoke-WebRequest`를 가리킨다.
- **답에는 기준일과 단위를 함께 적는다.** 단위는 쿼리 설명을 따르고, 설명에 없으면 단위를 모른다고 적는다.

## 코드 예시

```python
import os

import httpx

GATEWAY_URL = os.environ.get("QUERY_GATEWAY_URL", "http://192.7.9.45:9101")
KEY_PAGE = "http://192.7.9.45:3000/#access-key"
# 키 원문은 코드에 적지 않고 환경변수로만 받는다. 앞뒤 공백·줄바꿈이 섞이면 헤더가 깨지므로 지운다.
ACCESS_KEY = os.environ.get("KIWOOM_ACCESS_KEY", "").strip()
if not ACCESS_KEY:
    raise SystemExit(f"접근 키 없음: 환경변수 KIWOOM_ACCESS_KEY — {KEY_PAGE} 에서 발급해 설정")

# id만으로는 무엇인지 알 수 없으므로 목차의 이름을 상수 이름에 남긴다.
Q_기준일_비교일자 = 1
Q_당사_ETF_순자산 = 5
Q_내부코드명 = 10


def fetch(query_id: int, args: dict[str, str | list[str]]) -> list[dict]:
    r = httpx.post(f"{GATEWAY_URL}/winus/query/{query_id}", json={"args": args},
                   headers={"Authorization": f"Bearer {ACCESS_KEY}"}, timeout=30)
    if r.status_code == 401:
        raise PermissionError(f"DBGateway 신원 거절(401): {r.json()['detail']} — {KEY_PAGE} 에서 재발급해 설정")
    if r.status_code == 400:
        raise ValueError(f"쿼리 {query_id} 거절: {r.json()['detail']}")
    if r.status_code == 422:
        names = sorted({e["loc"][2] for e in r.json()["detail"] if len(e["loc"]) > 2})
        raise ValueError(f"쿼리 {query_id} 형식 오류: 인자 {names}의 값이 문자열이나 문자열 배열이 아님")
    r.raise_for_status()
    return r.json()["rows"]


날짜 = fetch(Q_기준일_비교일자, {"오늘": "20260915"})[0]
당사_etf = fetch(Q_당사_ETF_순자산, {
    "d0": 날짜["기준일"], "d1": 날짜["전일"],
    "d2": 날짜["당사전월말"], "d3": 날짜["당사전년말"],
    "cls": "44",
})
카테고리명 = fetch(Q_내부코드명, {"cls": "GT002", "codes": ["001", "002"]})  # 코드는 분류에 맞게: GT002는 카테고리
```

- `async def` 안에서는 `httpx.AsyncClient`를 쓰고 앱 종료 시 닫는다. 동기 호출은 이벤트 루프를 차단한다.
- 결과 열 이름은 등록된 SQL의 열 별칭과 대조해 쓴다.
