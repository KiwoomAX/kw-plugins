# submitting-ax-inquiry

AX 지원 문의 서비스(`http://192.7.9.45/ax/`)에 문의를 접수한다. 클로드가 초안 파일을 쓰고 그 내용을 그대로 보여 준 뒤, 사용자가 다음 메시지에서 보내라고 하면 스크립트가 그 파일 그대로 보낸다. 접수한 문의는 사용자가 화면에서 직접 쓴 문의와 같은 신청자로 남는다.

```
[클로드 코드] --내 접근 키 + 초안 파일 내용--> [AX 지원 문의 서비스] --> 내 문의 목록에 접수
```

> 이 문서에 적힌 것과 스크립트 출력이 다르면 맞춰 넘기지 말고 사용자에게 알린다.

## 다루는 문의

| 문의 | 이 스킬에서 | 초안 파일 |
|---|---|---|
| 1:1 문의 | 접수한다. 유형은 사내 지침의 문의 유형 목록에서 고른다(「튜토리얼 신청」·「Claude 계정」·「제공 인프라」·「기능 검토 문의」·「기타 문의」). 첨부 파일은 보내지 못한다 | `{"type": "<유형>", "title": "<제목>", "body": "<내용>"}` |
| 환경변수(env) 등록 | 접수한다. `.env` 에서 고른 키의 줄만 보낸다 | `{"repo_name": "<GitHub 저장소 이름>", "body": "<내용>", "keys": {"<키 이름>": "<용도>"}}` |
| 데이터 조회 요청 | 접수하지 않는다. `http://192.7.9.45/ax/` 주소만 안내한다 | 없음 |

첨부 파일이 꼭 필요한 1:1 문의도 주소만 안내한다.

## 흐름

1. 무엇을 왜 문의하는지 정리하고 초안 파일을 Write 도구로 `$env:TEMP` 아래에 쓴다(예: `$env:TEMP\ax-inquiry-draft.json`). Write 도구에는 `$env:TEMP` 를 실제 경로로 바꿔 넘긴다. 내용은 문제 상황에 맞게 쓰고, 비밀 값(접근 키, 비밀번호, 토큰, `.env` 의 값)은 넣지 않는다. 1:1 문의 유형이 둘 이상 맞으면 더 가까운 쪽을 고르고, 고른 까닭을 초안과 함께 한 줄로 알린다.
2. 환경변수 등록이면 초안을 쓰기 전에 `env-keys` 로 키 이름을 받는다. 등록할 키를 고르고 키마다 용도를 적는다. 용도를 키 이름으로 추정했으면 추정이라고 적는다.
3. `env-keys` 출력에 `고칠 수 있음` 줄이 있고 그 키를 등록하면, 고칠 내용(줄 번호, 키, 문제 종류)을 초안과 함께 보여 주고 「`.env` 의 <줄 번호>번째 줄 <키> 를 고친 뒤 이렇게 보낼까요?」라고 묻는다. 값을 읽지 않으므로 여러 줄 값인지는 키 이름으로 판단한다. 인증서·개인 키처럼 여러 줄일 수 있는 이름(`PEM`·`CERT`·`PRIVATE_KEY` 가 든 이름 등)이거나 판단이 서지 않으면, 줄 끝에서 따옴표를 닫으면 값이 망가질 수 있다고 함께 적는다. 고르지 않은 키의 문제는 접수를 막지 않으므로 묻지 않는다.
4. 고칠 수 없는 문제(`<줄 번호>번째 줄: <이유>` 로 나온 쓸 수 없는 키 이름, 1MB 를 넘는 내용)가 등록할 키에 걸리면 개발자에게 설명하고, 개발자가 고친 뒤 `env-keys` 부터 다시 한다.
5. 초안 파일 내용을 요약하지 말고 파일에 쓴 그대로 대화창에 보여 준 뒤 「이렇게 보낼까요?」라고 묻는다. 그 답은 거기서 끝낸다.
6. 사용자가 다음 메시지에서 보내라고 하면 전송 명령을 실행한다. 3번에서 고칠 내용을 함께 보여 줬으면 `fix-env` 를 먼저 실행하고 그다음 `send-env` 를 실행한다. 고쳐 달라고 하면 초안 파일을 고치고 5번부터 다시 한다.
7. 직접 쓰겠다고 하면 `http://192.7.9.45/ax/` 만 안내한다. 초안 내용을 옮겨 쓰라고 함께 알려도 된다.

## 명령

명령 안에 JSON 을 적지 않는다. PowerShell 은 명령 인자의 큰따옴표를 지우고 파이프로 넘긴 한글을 깨뜨리므로 내용은 초안 파일로만 넘긴다.

```
python "${CLAUDE_SKILL_DIR}/scripts/ax_inquiry.py" env-keys "<.env 경로>"
python "${CLAUDE_SKILL_DIR}/scripts/ax_inquiry.py" fix-env --draft "<초안 파일>" --env "<.env 경로>"
python "${CLAUDE_SKILL_DIR}/scripts/ax_inquiry.py" send-inquiry --draft "<초안 파일>"
python "${CLAUDE_SKILL_DIR}/scripts/ax_inquiry.py" send-env --draft "<초안 파일>" --env "<.env 경로>"
```

`env-keys` 는 키 이름, 규칙에 맞지 않는 줄의 이유, 고칠 수 있는 줄만 출력하고 값은 출력하지 않는다. 따옴표가 닫히지 않은 줄 뒤의 키도 함께 나온다. `fix-env` 는 초안의 `keys` 에 적은 키만 고친다. 닫히지 않은 따옴표는 그 줄 끝에서 닫고, 같은 키가 여러 번 있으면 마지막 줄만 남긴다. 백업 사본은 만들지 않는다.

## 출력 읽기

출력 첫 줄로 다음 행동을 정한다.

| 첫 줄 | 뜻 | 다음 행동 |
|---|---|---|
| `접수 완료: #<번호> <주소>` | 접수됨 | 접수 번호와 그 주소를 알린다 |
| `입력 오류: <이유>` | 보내지 않음 | 이유대로 초안이나 `.env` 를 고친다. 고친 초안은 5번부터 다시 보여 준다 |
| `키 없음` | 보내지 않음 | 둘째 줄이 「이 창에는 아직 반영되지 않음」이면 그 줄대로 창을 모두 닫고 다시 열라고 안내한다. 아니면 `http://192.7.9.45/ax/` 에서 직접 쓰라고 안내한다 |
| `키 거절` | 보내지 않음 | 키를 다시 발급하라고 먼저 말하지 않는다. 둘째 줄에 「새 키가 설정됨」이 있으면 창을 모두 닫고 다시 열라고 안내한다. 그다음 `http://192.7.9.45/ax/` 에서 직접 쓸 수 있다고 안내한다. 재발급은 기존 키를 대체해 같은 키를 쓰는 다른 도구가 멈춘다. 사용자가 재발급을 물으면 이 영향을 알리고 정하게 하며, 재발급하겠다고 할 때만 searching-winus 스킬의 「접근 키」 안내를 따른다 |
| `접수 경로 없음` | 접수 경로가 열리지 않음 | 다시 보내지 않는다. 다시 보내도 같은 결과가 나오므로 `http://192.7.9.45/ax/mine` 에서 접수되지 않았는지 확인한 뒤 `http://192.7.9.45/ax/` 에서 직접 쓰라고 안내한다 |
| `접수 확인 필요` | 저장됐는지 모름 | 다시 보내지 않는다. 저장이 끝난 뒤에도 이렇게 끝날 수 있고 신청자는 문의를 취소할 수 없다. `http://192.7.9.45/ax/mine` 에서 확인하라고 안내한다 |
| `접수 거절(<코드>): <이유>` | 서비스가 받지 않음 | 이유대로 초안을 고치고 5번부터 다시 한다 |

`접수 확인 필요` 뒤에 사용자가 다시 보내 달라고 하면, 먼저 내 문의 목록에 그 문의가 없는지 사용자에게 확인받는다. 없다고 하면 초안을 다시 보여 주고 「이렇게 보낼까요?」부터 다시 묻는다. `.env` 를 이미 고쳤으면 이번에는 `send-env` 만 실행한다.

## 지키는 규칙

- `.env` 를 고치는 일은 fix-env 로만 하고, 초안과 함께 승인받은 뒤 한다.
- 초안 파일 내용을 그대로 보여 주고 「이렇게 보낼까요?」라고 묻는다.
- 초안을 보여 준 답에서 전송 명령을 실행하지 않는다.
- 접수 경로 없음이나 접수 확인 필요로 끝나면 다시 보내지 않는다. 접수 확인 필요 뒤의 재전송은 위 「출력 읽기」의 확인과 새 승인을 거친 뒤에만 한다.
- 전송 명령은 자동 허용 목록에 넣지 않는다.
- .env 의 값을 읽지 않는다. 키 이름은 env-keys 출력으로만 본다.
- 직접 작성하겠다고 하면 http://192.7.9.45/ax/ 만 안내하고 브라우저를 열지 않는다. 다른 안내에서도 브라우저를 열지 않는다.
