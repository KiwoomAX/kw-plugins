# building-dashboard-from-excel

업무 엑셀 하나를 DB 표와 계산 코드와 결과표 조회 화면으로 옮긴다. 엑셀 분석기(`explaining-excel-cell`)의 결과 파일을 읽어서 진행한다.

화면에서 칸을 직접 고치는 기능은 없다. 담당자는 입력 양식을 내려받아 고친 뒤 올린다. 업무용 모니터링 화면은 이 스킬의 범위 밖이고, 다른 개발자가 결과표를 표 이름과 열 이름으로 불러와 만든다. 그래서 표 이름과 열 이름은 바꾸기 어려운 약속이다.

## 묻는 원칙

스스로 알 수 없거나 판단이 애매한 정보는 짐작으로 채우지 않고 모두 스킬을 실행하는 사람에게 묻는다. 화면 제목의 본부 · 팀, 기능을 넣을 대시보드 저장소, 결과를 확인할 환경, 표를 둘 스키마가 여기에 든다. 질문은 한 번에 하나씩 대화 본문으로 한다.

코드를 쓰기 전에 아래를 알린다.

- 화면으로 들어온 요청은 모두 개발자의 접근 키 권한으로 처리되고, 작업 기록에도 개발자로 남는다.
- 키를 재발급하거나 다른 본부로 옮기거나 퇴사하면 서비스가 멈춘다. 키는 서버 환경 변수 `KIWOOM_ACCESS_KEY` 로 넣는다.
- 업로드 코드를 넣기 전에 그 화면의 접근 제한이 설정됐는지 확인한다. 접근 제한이 없으면 업로드와 「WINUS 다시 받기」를 빼고 조회만 만든다.

## 작업 폴더

엑셀 옆에 `dashboard-work` 폴더를 만들고 아래 파일을 둔다.

| 파일 | 내용 |
|---|---|
| `source_notes.md` | 0단계 출처 설명과 4단계에서 확정한 표별 출처 |
| `explain_results.json` | 엑셀 분석기의 결과 파일 |
| `table_plan.json` | 만들 표의 설계 |
| `query_requests.md` | AX 팀에 넘길 쿼리 등록 요청 |

## 절차

### 0. 출처 설명 받기

엑셀과 함께 아래 문구로 설명을 받아 `source_notes.md` 에 적는다.

> 엑셀 파일과 함께 데이터를 어디서 가져오는지 간단히 적어 주세요. 시트 이름이나 표 위치를 함께 적어 주시면 더 정확하게 분석합니다.
>
> 1. 매크로나 데이터 연결로 자동으로 들어오는 데이터
> 2. WINUS · 우리펀드서비스 화면에서 내려받아 붙여 넣는 데이터(화면 이름이나 번호, 그 화면에서 넣은 조회 조건)
> 3. 펀드닥터처럼 외부 서비스나 다른 파일에서 가져오는 데이터
> 4. 손으로 입력하거나 사이트를 직접 검색해 찾는 데이터

2번의 우리펀드서비스 데이터와 3번은 외부 데이터 표, 4번은 수기 입력 표로 분류한다.

### 1~3. 엑셀 분석과 표 정의 확인

사용자에게 슬래시 명령 `/explaining-excel-cell` 의 전체 모드로 엑셀을 분석해 달라고 안내한다. 결과표는 시트가 아니라 시트 안의 표로 고른다. 결과에 쓰이는 표의 정의를 모두 확인받고, 결과 파일을 작업 폴더에 둔다. 확인되지 않은 정의가 있으면 다음 단계로 가지 않는다.

### 4. 원천 출처 확정

결과 파일의 표 역할과 연결을 0단계 설명과 대조하고, 둘이 다른 표만 묻는다. 예를 들어 설명에는 수기 입력인데 연결이 있는 표, 설명에 없는 원천 표를 묻는다. 확정한 표별 출처(`winus` · `external` · `manual`)를 `source_notes.md` 에 적는다.

수기 입력 표와 외부 데이터 표가 모두 없는 엑셀은 이 스킬의 대상이 아니다. 저장해 둘 사람 입력이 없기 때문이다. 5단계까지만 진행하고, 저장 구조와 조회 화면 없이 등록 쿼리로 응용화면을 바로 만들라고 안내한 뒤 끝낸다.

### 5. 쿼리 구하기와 등록 요청

WINUS 원천 표마다 아래 순서로 쿼리를 찾는다.

1. 설명의 화면 번호와 탭을 확인한다. 화면 번호만으로 고르지 않고 탭까지 맞춘다.
2. `searching-winus` 스킬의 등록 쿼리 목차에서 찾는다. 있으면 그 쿼리를 쓰고 조회 조건은 쿼리 매개변수로 둔다.
3. 없으면 `query_requests.md` 에 항목을 적는다. 사용자가 이 파일을 AX 팀에 넘긴다. 등록 쿼리는 AX 팀이 승인하므로 값 대조는 하지 않는다.

| 등록 요청 항목 | 내용 |
|---|---|
| 원천 표 | 표 정의의 `id` 와 만들 표 이름 |
| SQL | 엑셀에서 찾은 SQL 또는 화면 · 탭 정보 |
| 매개변수 | 이름과 값의 형식, 값이 든 셀 |

등록 번호를 기다리지 않는다. 그 표는 엑셀 저장값으로 채워 「쿼리 연결 대기」로 두고 6~8단계를 진행한다. 대기 표가 남아 있으면 화면의 업로드와 「WINUS 다시 받기」는 꺼진다. 한 결과 안에 두 시점의 데이터가 섞이지 않게 하기 위해서다.

### 6. 저장 구조 만들기

`scripts/table_plan.py` 로 `table_plan.json` 을 만든다. 쓸 수 있는 스키마를 조회해 개발자에게 고르게 한다. 고르는 기준은 그 엑셀을 쓰는 본부다. 표 목록을 보이고 승인을 받은 뒤 샌드박스 스킬(`managing-sandbox`)로 표를 만든다. 이미 있는 표는 이름과 열을 대조해, 같으면 다시 만들지 않고 다르면 묻는다.

WINUS 원천 표의 primary key 는 서로 다른 기준일 세 개의 응답으로 유일한지 확인한 뒤 정한다. 표를 만든 뒤에는 primary key 를 바꿀 수 없다.

### 7. 계산 이전과 엑셀 대조

[calc-guide.md](calc-guide.md) 대로 엑셀 수식을 표 · 열 이름 기준의 Python 코드 `calc.py` 로 옮긴다. `scripts/verify_calc.py` 로 엑셀 저장값과 셀 단위로 대조하고, 합격해야 다음으로 간다.

### 8. 조회 화면

[templates/README.md](templates/README.md) 대로 템플릿을 대시보드 저장소에 복사한다. 엑셀마다 달라지는 값은 `table_plan.json` 과 `calc.py` 뿐이고, 화면 코드는 고치지 않는다. `scripts/initial_load.py` 로 적재 파일을 만들고, 적재는 개발자가 터미널에서 실행한다. 대화 중에 기준일 범위를 지우는 적재를 실행하지 않는다.

### 9. 쿼리 연결

등록 번호가 오면 `scripts/query_link.py` 로 응답 열과 표의 열을 값으로 대조한다. 열이 맞으면 「쿼리 연결 대기」를 풀고 업로드를 시험한다. 열 구성이 달라 표를 다시 만들어야 하면 개발자에게 알린다.

## 개발 뒤의 구조 변경

변경 절차는 따로 없고 개발자가 직접 고친다. 아래 원칙을 지킨다.

- 열 추가는 기존 표에 열을 더하고, 과거 기준일의 새 열은 빈 값으로 둔다.
- 표 이름과 열 이름은 응용화면이 쓰는 약속이므로, 바꾸기 전에 응용화면 개발자에게 확인한다.
- 계산 코드를 고치면 엑셀 대조를 다시 실행하고, 과거 기준일 결과는 다시 계산하지 않는다.

## 실행 명령

스크립트는 PowerShell 에서 아래 형식으로 실행한다.

```powershell
uv run --system-certs --no-project --with-requirements "<스킬>\scripts\requirements.txt" python "<스킬>\scripts\table_plan.py" <인자>
```
