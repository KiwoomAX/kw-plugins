# 이미 만든 대시보드를 템플릿으로 옮기기

SKILL.md 의 「이미 만든 대시보드를 옮길 때」에서 연다.

옮기는 방향은 하나다. 템플릿으로 새 저장소를 만들고, 옛 대시보드의 화면과 데이터 호출을 그 저장소로 가져온다. 옛
코드를 템플릿에 덧대지 않는다.

**순서.** 옮기기 전에 옛 대시보드의 화면 · 링크 · 단추 · 데이터 호출을 목록으로 만든다. 그 목록으로 아래
「옮기기 전 승인받기」대로 목업을 보여 주고 승인을 받은 뒤 옮긴다. 옮긴 뒤 목록을 하나씩 새 대시보드에서 눌러
보고 아래 「끊기는 연결」 표로 잇는다. 목록 없이 옮기면 무엇이 끊겼는지 모른 채 끝난다.

옛 대시보드에서 처음 여는 화면은 메뉴 줄의 `path` 를 `/` 로 두어 옮긴다. 그래야 새 대시보드 주소로 들어온
사람이 빈 첫 화면이 아니라 그 화면을 본다.

## 옮길 때 지키는 것

옮기기는 옛 대시보드를 그대로 가져오는 일이다. 더 나은 이름과 배치가 보여도 옮기는 동안에는 고치지 않는다.

1. **사이드바는 옛 사이드바 그대로 옮긴다.** 기능 이름과 카테고리 이름과 그 안의 차례를 옛 코드에 적힌 글자
   그대로 쓴다. 옮기는 사람이 이름을 새로 정하지 않는다.
2. **화면 안은 고치지 않는다.** 카드 배치 · 색 · 글자 크기 · 부품 모양을 옛 화면이 보여 주던 대로 옮긴다.
   SKILL.md 의 「권장 — 내용 구획」은 새로 만드는 화면에 적용하고, 옮겨 온 화면에는 적용하지 않는다. 공용
   디자인으로 바꿀지는 옮기기가 끝난 뒤 아래 「공용 디자인 적용」에서 실제 화면을 보고 정한다.
   **옛 화면의 결함도 고치지 않는다.** 글자가 잘리거나 겹치거나 값이 틀린 것을 발견해도 그대로 옮기고
   보고에만 적는다. 옮기면서 함께 고치면 화면이 달라졌을 때 이전 때문인지 그 수정 때문인지 구분할 수 없다.
3. **파일 이름을 바꾸지 않고, 옛 파일 하나를 여러 파일로 분할하지 않는다.** 언어가 바뀌어 확장자만 바뀌는 것은
   괜찮다(`lib/notice/collect.ts` → `src/backend/notices/collect.py`).
4. **옛 코드 어디서도 호출하지 않는 화면은 기능으로 등록하지 않는다.** 옛 사이드바에 없고 화면을 여는 코드도
   없는 파일은 죽은 코드다. 메뉴에 넣지 말고 그런 파일이 있다고 사람에게 알린다.
5. **이 스킬의 규칙과 옛 것이 상충하면 고치지 말고 묻는다.** 아래 표대로 지금 값과 제안을 함께 알리고, 답을
   받은 뒤 고친다. 묻지 않고 고치면 쓰던 사람이 이름으로 찾던 화면을 찾지 못한다.

| 상충하는 것 | 무엇을 알리고 묻나 |
|---|---|
| 옛 기능 이름이 한글 13자를 넘는다 | 이름이 두 줄로 접혀 그 줄만 키가 커진다고 알리고, 줄인 이름을 제안한다 |
| 옛 사이드바가 카테고리 사이에 낱개 기능을 끼워 두었다 | 차례를 옛 코드 그대로 두면 콘솔에 `[shell]` 경고가 난다고 알리고, 그 기능을 카테고리 앞이나 뒤로 옮길지 묻는다 |
| 옛 API 주소가 `/api/<기능 이름>` 규칙과 다르다 | 주소를 바꾸면 그 주소를 쓰던 다른 프로그램이 끊긴다고 알리고, 바꿀지 묻는다 |
| 옛 구조가 너무 복잡하거나 코드가 낭비이거나 이상하다 | 그대로 옮기는 것을 기본으로 둔다. 고치자고 제안할 때는 무엇이 어떻게 바뀌는지와 지금 구조의 문제를 함께 적고, 「그래도 그대로 둘까요?」로 묻는다. 답을 받기 전에는 옛 구조 그대로 옮긴다 |
| 옛 요소를 놓을 곳이 템플릿에 없다 | 그 요소를 빼지 말고, 무엇이 왜 놓을 곳이 없는지와 살리는 선택지를 함께 알리고 묻는다. 모든 화면 위에 늘 붙어 있던 요약 띠, 헤더에만 있던 표시, 화면끼리 함께 쓰던 상태가 여기에 해당한다 |

## 옮기기 전 승인받기

옮기기 시작하기 전에 주요 변경점을 목업 한 장으로 보여 주고 승인을 받는다. 옮긴 뒤에 보여 주면 이미 고친 화면을
되돌리는 일이 된다.

목업은 HTML 파일 한 장으로 만들어 브라우저로 직접 열어 준다. 파일 경로만 알려 주고 열어 보라고 하지 않는다.
옛 화면 하나를 골라 왼쪽에 지금 모양, 오른쪽에 옮긴 뒤 모양을 나란히 두고 낮과 밤을 함께 보여 준다.

**알리는 것과 정할 것을 나누어 적는다.** 아래 알리는 것은 옮기면 반드시 그렇게 되므로 목업에 적되 묻지 않는다.

| 알리는 것 | 무엇을 적나 |
|---|---|
| 셸이 대신 그리는 것 | 옛 사이드바 · 헤더 · 탭 막대가 셸로 바뀐다. 옛 헤더의 시계 · 로고 · 사람 이름처럼 셸에 없는 것은 사라진다 |
| 밤 모드 | 옛 색을 그대로 두면 밤에 글자가 바탕에 묻히므로 토큰으로 바꾼다. 어느 화면의 어느 색이 바뀌는지 적는다 |
| 메뉴 | 옛 사이드바 이름을 그대로 옮긴 목록. 화면이 없어 빠지는 기능과 그 이유 |
| 이번에 옮기지 않는 기능 | 기능 이름과, 그 기능에 기대는 화면 · 카드 · 링크 |

정할 것은 위 「상충하는 것」 표에 걸린 항목뿐이다. 걸린 것이 없으면 묻지 않고 승인만 받는다.

**목업 위의 글은 할 일로 적는다.** 표시 방식을 설명하지 않는다. 「주황 점선 칸은 정해야 할 항목이고」처럼
적으면 사람이 무엇을 하면 되는지 알 수 없다. 무엇을 골라 달라는 말로 쓴다.

| 이렇게 적지 않는다 | 이렇게 적는다 |
|---|---|
| 왼쪽은 before, 오른쪽은 after 입니다 | 왼쪽이 지금 대시보드이고 오른쪽이 옮긴 뒤입니다 |
| 주황 점선 칸은 정해야 할 항목입니다 | 기능 이름 「파생상품운용현황표」를 「파생상품 현황」으로 줄일까요? 왼쪽 사이드바 셋째 줄입니다 |
| 그 밖의 변경은 옮기면 그대로 적용됩니다 | 나머지는 옮기면 그대로 바뀌므로 고르실 것이 없습니다 |

**물을 때는 질문을 그대로 적는다.** 「질문 N개를 어떻게 할까요」처럼 개수로 묻지 않는다. 사람은 목업 안의
주황 칸을 세어 가며 답하지 않는다. 물을 때마다 그 질문의 대상과 지금 값과 제안을 글로 함께 적고, 브라우저에
열어 둔 화면에서 어디를 보면 되는지 가리킨다. 정할 것이 여럿이면 한 번에 하나씩 묻는다.

승인받은 것만 고친다. 승인 전에는 옛 이름과 옛 모양을 그대로 둔다. 배치와 모서리와 여백은 제안하지 않는다.

이 승인은 옮기기까지다. 승인을 받은 뒤에는 옮기기를 끝까지 진행하고 중간에 다시 묻지 않는다. 공용 디자인을
적용할지는 옮기기가 끝난 뒤 실제 화면을 띄워 따로 정한다(아래 「공용 디자인 적용」).

**옮기다 드러난 상충은 모아 두었다가 끝에 한 번에 묻는다.** 그때까지는 옛 동작을 그대로 두고 옮기기를
이어 간다. 항목마다 멈춰 물으면 사람이 옮기기 내내 붙잡혀 있게 된다. 옮기기가 끝나면 모아 둔 것을 「옮기면서
이런 것이 걸렸습니다」로 한 묶음으로 보이고, 항목마다 옛 동작과 새 구조에서 달라지는 점과 제안을 적는다.
옛 동작을 그대로 둘 수 없어 더 나아갈 수 없는 것만 그 자리에서 묻는다.

## 공용 디자인 적용

옮기기가 끝나고 화면이 전부 열리고 검사가 통과한 다음에 적용 여부를 정한다. 기능 이전과 디자인 변경을
한 번에 섞으면 화면이 틀어졌을 때 무엇 때문인지 알기 어려우므로 순서를 지킨다.

**두 벌을 열어 승인받는다.** 기능 하나를 골라 공용 디자인을 먼저 적용하고, 옮기기를 끝낸 화면과 함께
브라우저로 직접 열어 사람이 오가며 대조하게 한다. 그림으로 그린 목업에는 표의 행 높이와 긴 이름이 줄바꿈되는 모양이
드러나지 않는다.

**적용해도 되는지 미리 묻지 않는다.** 고른 기능 하나에는 묻지 않고 적용한다. 「진행할까요」로 한 번 묻고
답을 받은 뒤에 적용하면 사람이 두 번 답해야 하고, 첫 번째 답은 볼 것이 없는 상태에서 하게 된다. 승인은 두
벌을 띄운 뒤에 한 번만 받는다. 거절하면 고른 기능을 되돌리므로 미리 묻지 않아도 잃는 것이 없다.

| 정할 것 | 어떻게 하나 |
|---|---|
| 고르는 기능 | 표와 지표와 상태 표시가 함께 있는 화면을 고른다. 셋 중 하나만 있는 화면은 달라지는 곳이 적어 대조가 되지 않는다 |
| 왼쪽(지금) | 옮기기를 끝낸 화면 그대로다. 옛 색을 살린 채 밤에 읽히게만 고친 상태다 |
| 오른쪽(공용 디자인) | 같은 화면에 색 토큰을 전부 바꾸고 글자 크기와 아이콘과 여백까지 공용 디자인으로 맞춘 상태다. 색은 템플릿 기본 팔레트라 차트 1순위가 남색, 2순위가 청록이고 상승이 빨강이다 |
| 여는 방법 | 두 화면은 코드 상태가 달라 한 폴더에서 함께 열 수 없다. 한 폴더에서 dev 서버를 둘 실행하면 3000번과 3001번이 같은 파일을 읽어 둘 다 적용한 화면을 보여 준다. 옮기기를 끝낸 상태를 커밋한 뒤 `git worktree add ..\<폴더 이름>-before HEAD` 로 폴더를 하나 더 만들고, 그 폴더에서 `npm install; npm run dev` 를 실행해 두 주소를 브라우저로 직접 연다. 백엔드는 8000번 하나를 같이 쓴다. 낮과 밤을 각각 대조할 수 있어야 한다 |
| 묻는 말 | 「열어 둔 두 화면을 보고 골라 주십시오」라고 묻는다. 공용 디자인을 적용할지만 묻고 팔레트는 묻지 않는다 |
| 적용하기로 한 때 | 나머지 화면에 같은 기준으로 적용한다. `index.html` 은 손대지 않는다 |
| 적용하지 않기로 한 때 | 옮기기를 끝낸 화면 그대로 둔다. 고른 기능도 되돌린다 |
| 키움 색을 쓰고 싶다고 할 때 | `index.html` 의 `<html>` 에 `data-palette="kiwoom"` 한 줄을 적는다. 차트 1·2순위와 상승색 다섯만 옛 대시보드의 남색과 핑크로 바뀐다 |

바뀌는 것은 아래 다섯이다. SKILL.md 의 「권장 — 내용 구획」을 적용하는 일이다.

| 바뀌는 것 | 지금 | 공용 디자인 |
|---|---|---|
| 색 | 옛 대시보드가 코드에 적어 둔 고정값 | 셸 토큰(`bg-surface` · `text-on-surface` · `accent` · `status-*` · `rise` · `fall`). 토큰은 낮 값과 밤 값을 함께 보유하므로, 화면이 색을 다시 적지 않아도 사람이 고른 테마의 값으로 그려진다 |
| 글자 크기 | 옛 스케일 | 17 · 14 · 13 · 12 · 11 · 10 |
| 모서리 | 옛 값 | `rounded-sm`(6px)과 `rounded-md`(10px) |
| 아이콘 | 옛 아이콘 | lucide-react 아이콘, 획 두께 `strokeWidth={1.7}` |
| 여백과 폭 | 고정 px | 그리드 비율과 `minmax` |

끝난 뒤에는 옮기기 때와 같은 검사를 다시 실행하고, 화면마다 달라진 곳을 보고에 적는다.

이 단계에서 손대는 것은 위 표의 다섯 가지뿐이다. 화면의 동작과 계산과 데이터 호출은 건드리지 않고, 옛
화면의 결함도 그대로 둔다. 디자인을 바꾸다 동작이 함께 바뀌면 무엇 때문에 달라졌는지 알 수 없다.

밤 모드에서 읽히지 않는 색을 바꾸는 작업은 이 단계와 별개다. 그 색은 옮기는 동안 묻지 않고 토큰으로 바꾸고,
어느 화면의 어느 색이 바뀌었는지만 목업과 보고에 적는다.

## 옛 HTML 킷(dash-kit) 화면

옛 화면은 `DASH.page({ … })` 선언 하나와 `.content` 안의 HTML 로 되어 있다. 선언의 값은 아래 표대로 옮기고,
`.content` 안은 페이지 컴포넌트로 다시 쓴다. 옛 화면 파일 하나가 새 페이지 하나다.

| 옛 값 | 템플릿에서 |
|---|---|
| `org` | `dashboard.config.ts` 의 `org` |
| `title` · `asof` · `cycle` | `DashboardLayout` props 로 그대로 넘긴다 |
| `actions` | `DashboardLayout` 의 `actions`. 아이콘은 스프라이트 이름 대신 lucide-react 컴포넌트를 넘기고 `onClick` 을 함께 준다 |
| `refresh: true` | 하루 안에 값이 바뀌는 화면이면 `refresh` 에 새로고침 함수를 넘기고, 아니면 옮기지 않는다 |
| `nav` | `routes.tsx` 의 `menu`. `cat` · `items` 는 그대로 쓰고 `href` 는 `path` 와 `page` 로 바꾼다 |
| `locked: true` 항목 | `{ name, locked: true }` 로 옮긴다. 옛 킷은 잠긴 항목에 `href` 를 두지 않았으므로 `href` 가 없어도 옮긴다 |
| `on: true` | 옮기지 않는다. 셸이 지금 주소를 보고 켠다 |
| `locked` 도 `href` 도 없는 항목 | 화면이 없는 기능이라 옮기지 않는다. 화면이 생길 때 추가한다 |
| `drawer` 와 `<aside class="side">` 안의 내용 | `alerts.tsx` 한 곳으로 옮긴다. 건수는 `useAlertCount` 로 알린다 |
| `MY_ORGS` | `dashboard.config.ts` 의 `others`. 실제로 화면이 있는 대시보드만 옮기고, 옛 킷에 예시로 들어 있던 항목은 옮기지 않는다 |
| `ME`(사람 이름) | 옮기지 않는다. 셸이 로그인 사용자로 그린다 |
| `unit` | 없다. 무리 이름은 조직 이름 끝에서 읽는다 |
| `live` · `notify` · `mine` · `doc` · `logo` | 없어진 값이라 옮기지 않는다 |

`.content` 안을 옮길 때:

- 킷 부품 클래스(`.card` · `.strip` · `.cols` · `table.tbl` · `.chip` · `.seg` · `.prog` · `.tag`)는 템플릿에 없다.
  Tailwind 클래스와 색 토큰으로 다시 만들고, 여러 화면이 쓰면 한 곳에 둔다.
- `dash-kit.css` 와 화면 파일의 `<style>` 을 통째로 가져오지 않는다. 셸과 같은 클래스 이름(`.side` · `.content` ·
  `.nav-item`)과 태그 이름 규칙이 들어 있어 사이드바와 상태바 모양이 바뀐다.
- 글자 크기는 SKILL.md 크기 표 안의 값이면 그대로 둔다. 옛 킷도 내용 구획을 1.12배로 확대했으므로 보이는 크기가
  같다. 표에 없는 값만 표 안의 가까운 값으로 고친다.
- 동작하지 않던 단추와 목업 안내문은 옮기지 않는다.

## 다른 방식으로 만든 대시보드

React · Next.js · 파이썬 같은 다른 방식으로 만든 대시보드도 같은 표로 옮긴다. 저장소마다 구조가 달라도 옮길 곳은
템플릿이 정해 두었다.

| 옛 것 | 템플릿에서 |
|---|---|
| 화면(페이지 · 라우트) | 화면 하나를 페이지 컴포넌트 하나로 옮기고 `routes.tsx` 에 메뉴 줄을 추가한다. 메뉴 이름과 카테고리는 위 「옮길 때 지키는 것」대로 옛 사이드바에 적힌 글자 그대로 쓴다 |
| 직접 만든 사이드바 · 헤더 · 레이아웃 | 옮기지 않는다. 셸이 그린다. 조직 이름은 `dashboard.config.ts` 에, 제목과 기준 시각은 `DashboardLayout` props 로 넘긴다. 다만 그 안에 그 대시보드만의 지표나 기능이 함께 들어 있으면 그것은 옮긴다. 놓을 곳이 없으면 위 표대로 묻는다 |
| 직접 만든 알림 · 공지 화면 | `alerts.tsx` 한 곳으로 옮긴다 |
| 서버 코드(API 라우트 · 백엔드 엔드포인트) | `src/backend` 의 FastAPI 라우터로 옮긴다. 주소는 옛 주소를 그대로 쓴다. 템플릿의 백엔드는 서버 하나이므로 다른 언어로 된 서버 코드는 파이썬으로 다시 쓴다 |
| 서버 코드의 테스트 | 함께 옮긴다. 서버 코드를 다른 언어로 다시 쓰면 그 테스트도 파이썬으로 옮겨 같은 값을 확인한다. 옮길지 사람에게 묻지 않는다 |
| 예약 실행(수집기 · cron · 배치) | 템플릿은 상시 도는 서버 둘만 실행한다. 예약 실행은 `deploying-kiwoom-service` 스킬의 스케줄 등록 요청으로 옮긴다 |
| 환경변수 · 키 | 백엔드 환경변수로 둔다. 서버 등록은 `deploying-kiwoom-service` 스킬이 한다 |
| 전역 CSS · 테마 | 옮기지 않는다. 색은 토큰으로, 글자는 SKILL.md 의 크기 표로 다시 준다 |
| 이미 돌고 있는 배포(젠킨스 잡 · 컨테이너) | `deploying-kiwoom-service` 스킬의 「이미 도는 서비스를 넘겨받을 때」를 따른다 |

## 끊기는 연결

| 끊기는 것 | 왜 끊기나 | 잇는 법 |
|---|---|---|
| 화면 사이 링크(`href="stock.html"` · 옛 라우터의 주소) | 화면 주소가 메뉴 줄의 `path` 로 바뀐다 | 메뉴 줄의 `path` 로 바꾸고, 화면 안의 링크는 react-router 의 `Link to="/stock"` 으로 쓴다 |
| 옛 주소로 저장한 즐겨찾기 | 새 대시보드에는 그 주소가 없어 「없는 주소」 페이지가 뜬다 | 옛 대시보드를 내리기 전에 새 주소를 사용자에게 알린다 |
| 브라우저에서 다른 서버 API 를 직접 호출하던 코드 | 새 대시보드는 주소가 다르고, 사내 다른 서버가 다른 주소에서 온 브라우저 호출을 막을 수 있다(CORS). 키를 브라우저 코드에 두면 누구나 볼 수 있다 | 백엔드에 `/api/<기능 이름>` 라우터를 만들어 백엔드가 대신 호출하게 한다. 키는 백엔드 환경변수로 두고, 서버 등록은 `deploying-kiwoom-service` 스킬이 한다 |
| 상대 경로 그림 · 파일(`assets/logo.png`) | 빌드하면 파일 위치가 바뀐다 | 페이지 코드에서 `import` 하거나 `src/frontend/public/` 에 두고 `/logo.png` 로 쓴다 |
| DOM 을 직접 고치던 코드(`innerHTML` · `getElementById`) | React 가 다시 그릴 때 직접 고친 내용이 사라진다 | 데이터는 `useState` 로 들고 그리기는 JSX 로 옮긴다 |
| 테마가 바뀔 때 차트를 다시 그리던 코드 | 템플릿에는 테마 변경 이벤트가 없다 | 선 색을 토큰 클래스(`stroke-chart-1` 등)로 주면 낮 · 밤에 따라 저절로 바뀐다 |
| 킷 부품 모양 | 템플릿에 부품 클래스가 없어 모양이 사라진다 | 위 「`.content` 안을 옮길 때」대로 다시 만든다 |

**끊긴 곳을 찾는 법.** 새 대시보드를 실행하고 브라우저 개발자 도구를 연다. 옮기기 전에 만든 목록을 하나씩 눌러
보며 Console 탭의 오류와 `[shell]` 경고, Network 탭의 404 · CORS 오류를 확인한다. 찾은 것은 위 표로 잇는다. 표에
없는 것이 나오면 옮긴 사람이 정하지 말고 AX 팀에 알린다.
