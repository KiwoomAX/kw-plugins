# 알아 둘 점 지침

이 지침은 분석 서브에이전트가 장면마다 「알아 둘 점」을 코드에서 찾는 방법을 정한다. 「알아 둘 점」은 안내 화면의 오른쪽 남색 상자에 표시된다. 화면만 봐서는 알 수 없는데, 모르면 입력이 실패하거나 결과를 잘못 읽는 규칙을 사용자에게 알린다.

## 등급

서브에이전트는 찾은 규칙마다 아래 등급 중 하나를 정한다.

| 등급 | 판정 | 예 |
|---|---|---|
| 핵심(`core`) | 화면에 보이지 않고, 모르면 입력이 실패하거나 결과를 잘못 읽는 규칙 | 펀드코드 칸에 쉼표나 띄어쓰기로 여러 개를 넣으면 묶음 산정으로 바뀝니다. |
| 참고(`ref`) | 알면 좋지만 몰라도 틀리지 않는 규칙 | 진행 표시 (n/7)은 4단계를 반복합니다. |
| 싣지 않음 | 화면에 이미 글자로 보이는 안내를 다시 말하는 규칙, 눈에 보이는 상태(테두리, 바탕색, 흐려짐)를 묘사하는 규칙 | 입력 창 아래 「예상 소요시간 3–5분」은 화면에 고정해 둔 안내 문구입니다. |

핵심은 아래 종류에서 나온다. 조사한 레포 여섯 곳에서 핵심은 이 종류에 몰렸다.

- 입력 형식: 구분자, 자릿수 제한, 필수인데 표시가 없는 칸, 받는 파일 형식과 시트 이름
- 단위 · 기준 시점: 라벨 없는 단위, 미래 날짜 보정, 기준일이 데이터 시각이 아닌 업로드 시각인 조건
- 선행 조건: 다른 동작을 먼저 해야 결과가 나오는 조건, 켜 두어야 하는 프로그램
- 결과 해석: 값의 출처(재계산, 고정 샘플, 다른 테이블), 알림 없이 끝나는 실패, 필터와 무관한 집계, 같은 이름인데 기준이 다른 숫자
- 되돌림 불가: 확인 창 없는 삭제 · 발송, 기존 값을 덮어쓰는 저장, 닫으면 사라지는 편집
- 저장 대상: 임시저장과 실제 저장의 차이, 다른 사용자와 공유되는 저장소

## 판정 순서

서브에이전트는 아래 순서로 판정한다.

- 장면의 화면 문구(placeholder, 안내, 라벨, 버튼 이름, 빈 상태와 오류 문구, 확인 대화상자)를 먼저 모은다.
- 찾은 규칙을 사실 단위로 나눠, 화면 문구로 이미 보이는 사실은 뺀다. 판정 단위는 문장이 아니라 사실이다. 펀드코드 칸 안내가 「예: 5001, 5002」로 쉼표 예시만 보이면, 「띄어쓰기도 구분자다」와 「여러 개면 묶음 산정으로 바뀐다」는 화면에 없는 사실이므로 핵심이다.
- 화면 문구가 실제 동작과 다르면 핵심으로 싣는다. 예: 줄바꿈이 되지 않는 입력창에 적힌 「Shift + Enter로 줄바꿈」, WINUS 에 쓰지 않는데 「자동으로 임시저장됩니다」라고만 적힌 확인 대화상자.
- 마우스를 올려야 보이는 툴팁(`title`)에만 있는 규칙은 화면에 보이지 않는 사실로 보고 판정한다. 안내 화면의 캡처에는 툴팁이 찍히지 않는다.
- 화면 코드와 함께 백엔드의 저장 · 조회 코드를 읽는다. 조사에서 핵심의 대부분(ESG3 25개 중 18개, excel 업로드 9개 중 7개)이 백엔드에서만 확인되었다. 특히 알림 없는 실패 분기(`catch` 뒤에 화면 표시가 없는 분기)와 저장 대상 테이블을 찾는다.
- 같은 규칙은 그 기능에서 처음 나오는 장면에만 싣는다.

개수는 정하지 않는다. 핵심이 없는 장면은 핵심을 내지 않는다. 장면을 채우려고 참고나 화면 문구 재진술을 핵심으로 올리지 않는다.

## 항목 표시

항목에 아래 표시를 붙인다. 템플릿이 표시마다 모양을 바꾼다.

| 표시 | 붙이는 조건 | 안내 화면의 모양 |
|---|---|---|
| `irreversible: true` | 동작을 실행하면 되돌릴 수 없는 핵심(확인 창 없는 삭제 · 발송, 덮어쓰는 저장, WINUS 같은 외부 시스템 기록) | 문장 아래 작은 주황 글씨 「실행 후 되돌아가기 불가」 |
| `defect: true` | 사용자에게 가르칠 규칙이라기보다 고쳐야 할 결함(화면 문구와 다른 동작, 알림 없는 실패, 잘못된 표시) | 빨간 테두리의 「결함」 상자 |

`defect` 를 붙인 항목은 `analysis-prompt.md` 의 `mismatches` 에도 같은 근거로 적는다. 주 세션이 스킬 실행 끝의 보고에 결함 목록으로 옮긴다.

## 근거

항목마다 근거 `파일:줄` 을 적고, 근거를 찾지 못한 항목은 내지 않는다. 주석과 코드가 다르면 코드를 따르고, 그 차이는 `mismatches` 에 적는다.

## 문장 규칙

`analysis-prompt.md` 의 「문장 규칙」 표를 그대로 따른다. 항목은 한 문장으로 짧게 쓰고 「~합니다」체로 끝낸다. 화면에 보이는 문구를 인용해 그 뜻을 설명하는 문장은 쓰지 않는다.

조사에서 나온 예시는 아래와 같다.

| 알아 둘 점 | 등급과 표시 | 근거 |
|---|---|---|
| 쉼표나 띄어쓰기로 펀드코드를 여러 개 넣으면 묶음 산정으로 바뀝니다. | `core` | Kiwoom-Rag `useRiskManagement.ts:152-154` (안내 문구 `InputForm.tsx:246` 은 쉼표 예시만 보임) |
| 임시저장은 AX팀 DB 에만 남고 WINUS 에는 기록되지 않습니다. | `core` | Kiwoom-RM `previews.py:142-145` |
| 처음부터 모든 항목이 선택되어 있어 「선택 항목 저장」은 다른 페이지의 항목까지 WINUS 에 저장합니다. | `core`, `irreversible` | Kiwoom-Rag `PreviewModal.tsx:79-84` |
| 이 화면의 「위험등급 산정」 단추는 편집한 코멘트를 임시저장만 하고 산정하므로 편집본이 등급에 반영되지 않습니다. | `core`, `defect` | Kiwoom-Rag `PreviewModal.tsx:240-259`, Kiwoom-RM `previews.py:142-145` |
| 진행 표시 (n/7)은 4단계를 반복합니다. | `ref` | 진행 표시 코드 |

## 출력

`analysis-prompt.md` 의 출력 JSON 에서 장면의 `tips` 목록에 항목 객체를 넣고, 근거는 같은 JSON 의 `tipsEvidence` 에 둔다.

```json
"tips": [
  {"text": "쉼표나 띄어쓰기로 펀드코드를 여러 개 넣으면 묶음 산정으로 바뀝니다.", "level": "core"},
  {"text": "저장하면 입력 칸이 잠기고, 초기화해도 WINUS 기록은 남습니다.", "level": "core", "irreversible": true},
  {"text": "진행 표시 (n/7)은 4단계를 반복합니다.", "level": "ref"}
],
"tipsEvidence": {"0.0": ["src/hooks/useRiskManagement.ts:152-154"], "0.1": ["src/components/CommentRecordCard.tsx:89"]}
```

`tipsEvidence` 의 키는 `"<장면 번호>.<항목 번호>"` 다. 주 세션은 결과를 받은 뒤 「알아 둘 점 검토」 단계에서 근거 줄을 열어 모든 항목을 대조한다. 그리고 화면 문구 재진술, 핵심으로 잘못 올린 참고, 빠진 핵심, 장면 사이 중복을 고친다.
