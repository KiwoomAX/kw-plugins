# 기능 분석 지침

이 지침은 분석 서브에이전트가 기능 하나의 코드를 읽어 장면과 동작을 JSON 으로 돌려주는 방법을 정한다. 주 세션은 기능마다 서브에이전트 하나를 실행하고, 이 파일과 `tips-prompt.md` 의 경로와 맡을 기능 이름과 레포 경로를 프롬프트에 넣는다.

## 맡은 일

서브에이전트는 맡은 기능의 화면 코드에서 시작해 서버 · 저장소 · 외부 서비스까지 따라가며, 사용자가 버튼을 누른 뒤 자료가 어디로 오가는지를 장면과 동작으로 나눈다. 화면 코드와 함께 백엔드의 저장 · 조회 코드를 반드시 읽는다. 파일은 읽기만 하고 고치지 않는다. 장면마다 「알아 둘 점」은 `tips-prompt.md` 에 따라 함께 찾는다.

- 장면: 버튼 하나를 누른 뒤 화면이 바뀔 때까지의 흐름, 또는 사람이 누르지 않고 정해진 시각에 실행되는 흐름 하나
- 동작: 한 노드가 다른 노드로 무엇인가를 보내는 한 번의 이동

장면은 아래 규칙으로 나누고 놓는다.

| 규칙 | 내용 |
|---|---|
| 사람 순서 | 장면은 사람이 화면을 보고 실제로 움직이는 순서로 놓는다. 데이터를 쓰는 동작이 읽는 동작보다 먼저 오고, 화면의 단계 번호와 비활성 조건을 따른다. 코드 파일 · 렌더 순서는 근거로 쓰지 않는다 |
| 도달 가능한 화면만 | 실제로 렌더되고 화면에서 도달할 수 있는 요소만 장면으로 삼는다. 어디서도 import 하지 않는 컴포넌트, 여는 코드가 없는 단계, 쓰이지 않는 prop 은 장면으로 만들지 않고 `mismatches` 에 적는다 |
| 자동 장면 | 사용 중에 사람 동작 없이 일어나는 전환(예: 평가가 끝나면 0.5초 뒤 검증 창이 열림)은 흐름 안에 두고 `"auto": true` 를 붙인다 |
| 공통 입력 | 주 세션이 프롬프트에 공통 입력 동작(예: 기준 보고월 고르기)을 알려 주면, 그 동작은 장면으로 만들지 않는다. 캡처에 필요하면 `steps` 앞에 `"setup": true` 를 붙인 준비 동작으로 넣는다 |
| 수집 과정 | 맡은 기능이 「수집 과정」이면 크롤링 · 스케줄러처럼 미리 돌아 자료를 모으는 흐름만 장면으로 만든다. 다른 기능은 수집이 끝난 상태를 전제하고, 수집 흐름을 다시 그리지 않는다 |
| 두 경로 | 먼저 고를 수도, 나중에 되물을 때 고를 수도 있는 입력은 주된 경로를 장면으로 만들고 다른 경로는 알아 둘 점 한 줄로 적는다 |
| 챗봇 기능 | 맡은 기능이 대화 입력과 도구 호출로 진행되는 챗봇 기능이면 장면을 만들지 않고 `{"feature": {"key": …, "name": …, "summary": …, "chatbot": true, "nodes": [], "scenes": []}}` 만 돌려준다. 챗봇 기능의 안내 규칙은 개발 중이다 |

## 문장 규칙

읽는 사람은 바이브 코더이고 함수 이름과 API 개념을 모른다. 아래 규칙은 `say` · `title` · `text` · `tips` 에 모두 적용한다.

| 규칙 | 이유 |
|---|---|
| 함수 이름 대신 「누가 무엇을 어디에 보낸다」는 서술형으로 쓴다 | 바이브 코더는 함수 이름을 모른다 |
| 버튼 하나를 누른 뒤 일어나는 일을 장면으로 나누고, 화면 표기는 「홈」 메뉴 클릭처럼 버튼 이름으로 쓴다 | 「누를 곳으로 확대」 같은 표기는 어색하다 |
| 동시 처리 건수 제한 같은 내부 수치는 넣지 않는다 | 사용자가 알 필요가 없다 |
| 코드가 하지 않는 동작은 그리지 않고, 값을 하나씩 따로 가져오면 따로 그린다 | 정보를 한 묶음으로 모아 보내는 그림은 코드와 달라 거짓이 된다 |
| 예시 값은 「샘플 데이터」라고 밝힌다 | 실제 집계로 오해한다 |
| 자료 이름(`text`)과 설명(`say`)에는 가짜 데이터의 실제 값을 쓴다. 예: 「검색어 붙인 목록 요청」 대신 「"견적" 검색」, 「메일 목록」 대신 「"견적"이 든 메일 2통」 | 실제 값이 오가는 모습이 일반적인 말보다 직관적이다 |
| 단추가 켜지거나 꺼지는 상태 변화는 장면 제목(`title`) · 자료 이름(`text`) · 동작 설명(`say`) · 끝 대상(`end`)에 두지 않고, 켜지는 조건을 알아 둘 점에 적는다. 예: 「기준 연도와 월을 고르면 실행 단추가 켜집니다」 대신 제목 「기준 연도와 월을 고릅니다」와 알아 둘 점 「연도와 월을 모두 골라야 실행 단추가 켜집니다」 | 캡처에서 켜진 단추는 꺼진 단추와 거의 같아 보여 화면으로 전해지지 않는다 |
| 기능 `summary` 는 서버 · 함수 이름 없이 화면을 쓰는 사람의 시각으로 쓴다. 예: 「기준 보고월과 대상을 고르면 펀드마다 위험등급을 매깁니다」 | 사용자 설명서의 「이 기능으로 하는 일」에 그대로 보인다 |

문장은 「~합니다」체로 쓰고 긴 줄표를 쓰지 않는다.

## 고정 명칭표

노드의 `kind` 와 `zone` 은 아래 표의 값만 쓴다. 노드 이름(`name`)과 설명(`sub`)은 레포에 맞게 짓되, 표의 「노드 이름 예」가 맞으면 그 이름을 그대로 쓴다.

| kind | 템플릿 고정 라벨 | 노드 이름 예 |
|---|---|---|
| `screen` | 사람이 보는 화면 | 내 PC (브라우저) |
| `server` | 서버 · 프로그램 | 대시보드 서버 · ESG 서버 |
| `db` | 저장소 · DB | Redis 저장소 · AX팀 DB · WINUS |
| `ai` | AI 모델 | Claude · Gemini |
| `web` | 외부 사이트 | 크롤링 대상 사이트 이름 |
| `local` | 팀 공용폴더 | 팀 공용폴더 (Y: 드라이브) |
| `officepc` | 담당자 PC | 담당자 PC |
| `code` | 샘플 데이터 | 샘플 데이터 |
| `clock` | 정해진 시각 자동 실행 | 자동 실행 |

MDB · RDB · 파일 서버는 노드 하나로 묶어 「AX팀 DB」로 부른다.

| zone | 표시 이름 |
|---|---|
| `office` | 내 PC · 사무실 |
| `app` | 레포의 서비스(주 세션이 정한 `appZone`) |
| `ax` | AX팀 서버 |
| `winus` | WINUS (회사 DW) |
| `fund` | 우리펀드서비스 |
| `external` | 외부 서비스 |

구역 밖에 두는 노드만 `zone` 을 생략한다.

동작의 `icon` 은 아래 값만 쓴다. 템플릿에 없는 이름을 쓰면 렌더러가 HTML 을 만들지 않는다.

| icon | 쓰는 자료 |
|---|---|
| `ask` | 요청 · 질문 |
| `answer` | 답 · 결과 알림 |
| `list` | 목록 |
| `table` | 표 · 조회 결과 |
| `card` | 메일 한 통 · 항목 하나의 정보 |
| `stack` | 여러 건 저장 · 묶음 |
| `file` | 파일 · 본문 |
| `bundle` | 질문과 파일을 합친 꾸러미 |
| `path` | 파일 경로 · 주소 |
| `check` | 확인 · 기록 완료 |

외부 프로그램과 외부 시스템(아웃룩, 엑셀, WINUS, FAS, 외부 사이트) 노드에는 `"launch": true` 를 둔다. 템플릿이 장면에서 그 노드가 처음 쓰일 때 창이 열리는 동작을 먼저 보여 준다. 레포 자신의 서버와 저장소에는 두지 않는다.

## 좌표

`x` · `y` 는 폭 960, 높이 520 무대에서 노드 중심의 좌표다. 왼쪽(`x` 110 부근)에는 `office` 노드를, 중간(`x` 360 ~ 600)에는 `app` · `ax` 노드를, 오른쪽(`x` 830 부근)에는 `external` 노드를 둔다. 같은 구역의 노드는 세로로 120 이상 띄워 겹치지 않게 한다.

## 화면 표기

장면의 `screen.startName` 은 사람이 누르는 버튼 이름(예: 「공고」 탭 클릭)이고, `screen.endName` 은 결과가 나타나는 곳의 이름(예: 공고 목록 표시)이다. 사람이 누르지 않는 장면(정해진 시각 자동 실행)은 `startName` 을 「자동 실행」으로 둔다.

## 캡처 계획

캡처는 백엔드를 실행하지 않고 화면 코드만 띄워, 화면이 보내는 요청에 가짜 데이터로 응답한 상태를 찍는다. `capture` 는 주 세션이 캡처 계획을 만드는 데 쓴다. `capture.scenes` 는 `feature.scenes` 와 같은 순서다.

- `path`: 이 기능 화면을 여는 주소의 경로(예: `/#notices`)
- `end`: 장면 제목이 말하는 결과가 보이는 범위 전체를 찾는 방법. 창이나 화면이 열리는 장면은 창 전체, 목록이 걸러지는 장면은 남은 목록, 값이 바뀌는 장면은 그 값이 든 카드나 줄이다. 단추가 켜지는 것은 끝 대상으로 삼지 않는다(위 규칙 표). 범위 안의 제목 글자 하나(예: 「기준 보고월」, 「실행할 작업」)는 고르지 않는다. 범위를 감싸는 요소는 `{"selector": "CSS 선택자"}` 로 적고, 화면 코드의 그 요소에 맞는 선택자를 고른다. 캡처는 후보가 둘 이상 보이면 찾지 못함으로 두므로, 선택자가 화면에서 한 요소만 가리키게 한다. `:has()` 안에 `:has()` 를 다시 넣지 않는다. 캡처가 쓰는 Playwright 가 그런 선택자를 해석하지 못해 찾지 못함이 된다(예: `div:has(> div > div > select:has(> option[value="2026"]))` 대신 `div.items-end:has(select)`). 몇 초 뒤 사라지는 알림 문구는 고르지 않는다. 캡처는 동작이 끝나고 1.5초 뒤에 찍는다.
- `steps`: 사용자가 이 장면에서 하는 동작 목록. 버튼만 적지 말고 실제 사용 순서를 따라간다. 동작은 아래 표의 종류만 쓴다.

| 동작 | 형태 | 쓰는 곳 |
|---|---|---|
| 글자 입력 | `{"action": "type", "target": {"selector": "#q"}, "text": "견적"}` | 검색창, 입력 칸 |
| 누르기 | `{"action": "click", "target": {"text": "보낸사람"}}` | 단추, 탭, 체크박스 |
| 고르기 | `{"action": "select", "target": {"selector": "select#year"}, "value": "2026"}` | 목록에서 고르는 칸(select) |
| 우클릭 | `{"action": "rightclick", "target": {"text": "투자시기"}}` | 우클릭 메뉴(`onContextMenu`) |
| 두 번 누르기 | `{"action": "dblclick", "target": {"text": "투자시기"}}` | 이름 · 칸 편집(`onDoubleClick`) |
| 키 누르기 | `{"action": "press", "target": {"selector": "input"}, "key": "Enter"}` | Enter · Escape · Tab · 방향키 · `Control+c` 처럼 키로 하는 동작(`onKeyDown`). `target` 이 없으면 화면 전체에 보낸다 |
| 붙여넣기 | `{"action": "paste", "target": {"selector": "td input"}, "text": "A\t120\nB\t80"}` | 엑셀에서 복사한 칸 붙여넣기(`onPaste`). 칸은 탭, 줄은 줄바꿈으로 나눈다 |
| 파일 올리기 | `{"action": "upload", "target": {"selector": "input[type=file]"}, "file": {"name": "보고서.pdf", "text": "%PDF-1.4"}}` | 파일 칸, 파일을 끌어 놓는 칸(대개 숨은 파일 칸이 받는다). 파일 내용은 가짜 글자다 |
| 마우스 올리기 | `{"action": "hover", "target": {"selector": "th.col"}}` | 올려야 나타나는 단추 · 팝업(`onMouseEnter`) |
| 끌기 | `{"action": "drag", "target": {"selector": ".divider"}, "by": [120, 0]}` 또는 `"to": {"text": "놓을 곳"}` | 폭 조절, 순서 바꾸기, 끌어 옮기기 |
| 스크롤 | `{"action": "scroll", "target": {"text": "별첨"}}` | 화면 밖 요소를 보이게 하기 |
| 기다리기 | `{"action": "wait", "ms": 3000}` | 아래 설명 |

같은 일을 하는 길이 둘이면 캡처가 따라 하기 쉬운 길을 고른다. 폭이 0 이 되기도 하는 얇은 단추보다 우클릭 메뉴처럼 늘 보이는 길이 낫다. 화면이 정해 둔 지연 뒤에 바뀌는 장면(예: 완료 1.5초 뒤 창 열기)은 마지막에 `{"action": "wait", "ms": 3000}` 을 둔다. 이 장면이 시작되기 전에 해 두어야 하는 동작(공통 입력, 앞 장면에서 연 창)은 `"setup": true` 를 붙여 앞에 둔다. 캡처는 준비 동작을 마친 화면을 이 장면의 시작 화면으로 찍고, 그 뒤의 동작부터 장면으로 보인다. 예: 보낸사람으로 좁히는 장면은 「보낸사람」 클릭 → 「홍길동」 클릭. 응답이 가짜라 눌러도 바깥에 아무 일도 일어나지 않는다. 사람이 하는 동작이 없는 장면(자동 실행, 화면을 열자마자 그려지는 것)은 `steps` 를 생략한다.

흐름 그림의 동작(`actions`) 중 사람 동작에 해당하는 동작에는 `step` 을 적는다. 사람 동작은 이 장면의 `steps` 에서 준비 동작과 기다리기를 뺀 동작이고, `step` 은 그 동작의 1부터 센 번호다. 예: `steps` 가 연도 고르기 → 월 고르기면 「2026년 선택」 동작에 `"step": 1`, 「9월 선택」 동작에 `"step": 2` 를 적는다. 사람 동작 하나를 흐름 동작 여럿이 설명하면 첫 흐름 동작에만 적는다. 캡처는 마지막 사람 동작을 뺀 사람 동작마다 그 직후 화면을 찍고, 안내 화면은 `step` 이 같은 흐름 동작을 보일 때 그 화면을 보인다.

검색 · 필터처럼 사용자가 무엇을 입력하거나 고르는 기능이 이 스킬의 가장 중요한 장면이다. 예시 검색어 · 예시 선택값을 정해 `steps` 에 넣고, 그 값에 맞는 결과를 `mocks` 에 따로 넣는다.

## 가짜 데이터

`mocks` 에는 이 기능 화면이 보내는 요청마다 가짜 응답을 하나씩 적는다. 화면 코드에서 요청(`fetch` 등)을 찾고, 그 요청을 받는 백엔드 코드에서 응답 형태를 읽어 같은 형태로 만든다.

- `method` · `path`: 요청 방식과 경로. 쿼리는 적지 않는다. `/body/<id>` 처럼 뒤가 바뀌는 경로는 `"path": "/body/", "prefix": true` 로 적는다.
- `query`: 같은 경로라도 특정 쿼리 값이 든 요청에만 줄 응답이면 그 조건을 적는다(예: `{"q": "견적"}`). 조건 없는 응답도 함께 두어, 처음 목록 요청에는 조건 없는 응답이 가게 한다.
- `json`: JSON 응답의 본문. JSON 이 아닌 응답은 `body` 와 `contentType` 으로 적는다.
- 값: 실제 사람 이름 · 회사 메일 주소 · 고객 정보를 쓰지 않고 「홍길동」 · `user@example.com` · 「예시 회사」 같은 예시 값을 쓴다. 레포의 테스트나 샘플 파일에 실제처럼 보이는 값이 있어도 옮기지 않는다.
- 분량: 목록은 화면이 그럴듯해 보이도록 5개 안팎을 넣고, 화면이 쓰는 필드는 빠짐없이 채운다.
- 근거: `mockEvidence` 에 `"<method> <path>"` 마다 응답 형태를 읽은 `파일:줄` 을 적는다.

## 근거와 불일치

`evidence` 는 `"<장면 번호>.<동작 번호>"` 마다 근거 `파일:줄` 목록이다. 모든 동작에 근거가 있어야 하고, 근거를 찾지 못한 동작은 그리지 않는다.

`mismatches` 에는 레포 코드 자체의 버그를 적는다. 화면 문구와 다른 동작, 알림 없는 실패, 잘못된 표시, 주석과 동작이 다른 곳, 쓰이지 않거나 도달할 수 없는 경로가 여기에 든다. 고치지 않고 주 세션에 보고만 한다. 항목은 `{"severity": "critical|important|minor", "where": "파일:줄", "text": "무엇이 어떤 조건에서 일어나는지"}` 형태로 적는다. 등급은 아래 기준으로 정한다.

| 등급 | 기준 |
|---|---|
| `critical` | 데이터를 잘못 저장하거나 덮어쓰거나 외부로 보낸다. 또는 실패를 성공으로 보여 사용자가 잘못 안다 |
| `important` | 실패를 알리지 않거나 잘못 표시해 결과를 잘못 읽게 한다. 화면이 멈춘다 |
| `minor` | 문구 · 표시 오류, 동작이 없는 버튼, 주석과 다른 동작, 쓰이지 않는 코드 |

`critical` · `important` 버그는 `tips-prompt.md` 에 따라 알아 둘 점에도 `"defect": true` 로 싣는다.

## 출력

JSON 하나만 돌려준다. 아래는 wholesale-dashboard 의 공고 기능을 줄인 예시다. 이 레포에서 매일 공고를 모으는 정기 실행은 「수집 과정」 기능이 맡으므로, 공고 기능은 모아 둔 목록을 읽는 장면부터 시작한다.

검색 장면은 아래처럼 적는다. 처음 목록과 검색 결과가 서로 다르게 보이도록 쿼리 조건이 있는 가짜 응답을 따로 둔다.

```json
"capture": {"path": "/", "scenes": [{"steps": [{"action": "type", "target": {"selector": "#q"}, "text": "견적"}], "end": {"selector": "#rows"}}]},
"mocks": [{"method": "GET", "path": "/api/search", "json": {"rows": ["…처음 목록 5통…"]}},
          {"method": "GET", "path": "/api/search", "query": {"q": "견적"}, "json": {"rows": ["…\"견적\"이 든 2통…"]}}]
```

출력은 JSON 하나로 읽혀야 한다. 객체를 닫은 뒤에 다른 필드나 설명 문장을 붙이지 않는다.
