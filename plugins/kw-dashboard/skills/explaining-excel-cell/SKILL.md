# explaining-excel-cell

엑셀 셀 하나의 값이 어떤 원천 값에서 어떤 수식을 거쳐 나왔는지 재생하는 HTML 화면을 만든다. 엑셀 파일만 읽고, DB 와 네트워크는 쓰지 않는다. 값은 엑셀에 저장된 계산 결과다.

## 실행 순서

1. 사용자에게 엑셀 경로와 시트 이름과 셀 주소를 받는다. 셋 중 빠진 것만 묻는다. 결과 셀의 이름(예: 연도별 · 월별 수익률)을 알면 `--title` 로 넘긴다.
2. 출력 경로를 영문으로 정한다. 현재 폴더의 `explain_<시트 순번>_<셀 주소>.html` 형태로 쓰고, 같은 이름이 있으면 뒤에 번호를 붙인다. 스크립트는 이미 있는 파일을 덮어쓰지 않고 실패한다.
3. PowerShell 에서 열 이름 재료를 만든다. `<스킬>` 은 이 SKILL.md 가 있는 폴더다.

   ```powershell
   uv run --system-certs --no-project --with-requirements "<스킬>\scripts\requirements.txt" python "<스킬>\scripts\explain_cell.py" "<엑셀 경로>" "<시트>" D26 --hints explain_hints.json
   ```

4. `explain_hints.json` 을 읽고 열마다 이름을 정한다. `rule` 은 같은 열 위쪽의 첫 글자 셀로 정한 이름이라, 그 열에 머리가 없으면 다른 블록의 머리를 가져와 틀린다. `rule` 이 맞으면 그대로 두고, 틀리거나 「<시트> <열>열」처럼 비어 있으면 `left_label`(왼쪽 열의 블록 제목 후보)과 `above`(위쪽 셀)와 `formula` 를 보고 무슨 값인지 이름을 짓는다. 바꿀 열만 `explain_names.json` 에 `{"시트!열": "이름"}` 으로 쓴다.
5. 화면을 만든다.

   ```powershell
   uv run --system-certs --no-project --with-requirements "<스킬>\scripts\requirements.txt" python "<스킬>\scripts\explain_cell.py" "<엑셀 경로>" "<시트>" D26 --title "<결과 이름>" --names explain_names.json --out explain_2_D26.html
   ```

6. 만든 파일을 `Start-Process explain_2_D26.html` 로 브라우저에서 연다.
7. 사용자에게 단계 수와, 화면에서 확인할 점(왼쪽 단계 목록, 오른쪽 엑셀 캡처, 마지막 출처 확인 단계)을 알린다. 규칙 이름에서 바꾼 열은 근거와 함께 알린다. 예: 「3004자료 M열은 블록 제목 「월별성과」와 수식 (이번 달 - 지난달) / 지난달을 보고 「월별수익률」로 정했습니다」. 마지막에 「틀린 내용이 있으면 이 대화에서 알려 주십시오. 출처 확인 단계의 출처가 맞는지도 알려 주십시오.」를 덧붙인다. 화면은 서버 없이 열리는 HTML 한 장이라 확인 결과를 저장할 곳이 없으므로 이 대화에서 받는다.

## 전체 모드

사용자가 셀을 고르지 않고 엑셀 전체의 흐름을 보고 싶어 하면 `--all` 로 실행한다. 분석기는 2번 실행한다. 1번째 실행은 결과표 후보만 찾고, 2번째 실행이 결과표마다 페이지를 만든다. 페이지는 원천 데이터 → 계산된 표 → 결과표 3단계와 「원천 데이터 출처」 · 「확인 필요한 사항」 화면으로 이루어진다.

1. 1번째 실행으로 후보 파일을 만든다. 출력 이름은 영문으로 정한다.

   ```powershell
   uv run --system-certs --no-project --with-requirements "<스킬>\scripts\requirements.txt" python "<스킬>\scripts\explain_cell.py" "<엑셀 경로>" --all --out explain_all.html
   ```

   출력은 `결과표 후보 시트 N개: <경로>` 이고, `--out` 폴더에 `explain_candidates.json` 이 생긴다.
2. 후보 파일을 읽고 결과표를 묻는다. 묻는 문장은 「이 엑셀로 최종적으로 확인하거나 활용하는 표를 정해 주세요. 모니터링이 목적이면 모니터링하고 싶은 표를 정해 주세요.」다. 후보 시트는 표 하나로 보인다. 행마다 시트 이름, 후보 표의 위치(`tables[].id`), 엑셀 표 이름(`tables[].excel_table`, 있을 때), 클로드가 유추한 표 이름을 적는다. `shown` 이 false 인 시트는 표에 넣지 않고 이름만 한 줄로 모두 적는다. 사용자는 목록에 없는 시트나 엑셀 표도 직접 지정할 수 있다.
3. 같은 질문에서 날짜 시트 군을 확인한다(`date_groups` 가 있을 때). 「「<pattern>」 이름의 시트 <count>개를 같은 구조로 보고, 그중 「<base>」 시트로 분석합니다. 맞습니까?」 사용자가 다른 기준 시트를 고르면 `--base "<pattern>=<시트>"` 를, 날짜 시트가 아니라고 하면(「TDF2030」·「TDF2040」 같은 빈티지 시트) `--base "<pattern>=없음"` 을 1번 명령에 더해 1번째 실행부터 다시 하고, 새 후보 파일로 다시 묻는다. 분석하는 시트가 바뀌면 후보와 묶음 번호가 바뀌기 때문이다. `--base` 는 군마다 1번씩 여러 번 줄 수 있다.
4. 같은 질문에서 행 순서를 확인한다. 결과표의 `row_order` 가 「순위 순」이면 묻지 않는다. 그 밖의 결과표와 사용자가 직접 지정한 표는 두 안을 묻는다.
   - 기본 안: 엑셀의 지금 순서를 순번 열(`row_seq`)로 저장하고, 앞으로 추가분은 뒷행에 붙인다.
   - 다른 안: 가나다 순이나 펀드코드 순 같은 정렬 기준을 정한다.
5. 답을 `--out` 폴더의 `explain_results.json` 에 Write 도구로 쓴다(UTF-8). `base_sheets` 는 후보 파일의 `base_sheets` 를 그대로 옮긴다. 엑셀 표를 결과표로 골랐으면 `excel_table` 에 그 이름을 적는다. 표 묶음 이름은 후보 파일의 `groups`(머리글 행 글자, 표 위 제목 글자, 첫 행 값)를 보고 클로드가 유추해 묶음 번호로 적는다. 이 파일은 대시보드 스킬이 행 순서 답을 읽는 기록이기도 하다.

   ```json
   {"excel": "<엑셀 파일 이름>", "base_sheets": {"<pattern>": "<시트>"},
    "results": [{"sheet": "<시트>", "excel_table": null, "row_order": "순위 순"}],
    "names": {"g1": "분류 대응표"}}
   ```

6. 2번째 실행으로 페이지를 만든다. 결과표마다 `explain_all_r<번호>.html` 과 단계 화면 폴더 `explain_all_r<번호>_steps/` 가 생긴다.

   ```powershell
   uv run --system-certs --no-project --with-requirements "<스킬>\scripts\requirements.txt" python "<스킬>\scripts\explain_cell.py" "<엑셀 경로>" --all --results explain_results.json --out explain_all.html
   ```

7. 만든 페이지를 `Start-Process` 로 브라우저에서 연다. 날짜 시트 군이 있으면 대화에서 1번 알린다. 「마지막 시트(<시트>)의 계산 기준으로 분석했습니다. 더 과거의 계산 이력까지 모두 검토가 필요하면 말씀해 주세요.」 틀린 내용이 있으면 이 대화에서 알려 달라고 덧붙인다.
8. 실패로 중단되면 아무 파일도 쓰이지 않는다. 원인을 고친 뒤 `--out` 이름을 바꿔 다시 실행한다.

수식이 하나도 없는 엑셀은 `계산 규칙 없음` 한 줄로 끝난다. `--hints` 와 `--names` 는 셀 모드에서만 쓴다.

## 주의사항

전체 모드 화면의 문장은 분석기가 만든다. 클로드가 대화에서 결과를 설명하거나 묶음 이름을 지을 때도 같은 규칙을 지킨다.

- 대상을 흐리는 말(「옆 표」, 「다른 곳」)을 쓰지 않는다. 시트 이름, 표 이름, 위치, 찾는 열 제목, 가져오는 열 제목을 모두 적는다.
- 찾기와 가져오기는 2문장으로 나눈다. 예: 「「펀드명」 셀은 이 행의 「순위」 값을 「수익률현황」 시트의 계산용 순위표(N1:Z3)에서 찾습니다. 찾는 열은 「순위정리」 열입니다. 찾은 행의 「펀드명」 값을 가져옵니다.」
- 찾는 범위가 표 여러 개에 걸치면 범위 이름을 이렇게 적는다. 「「2026년 7월5주」 시트의 R4:AB249 범위입니다. 이 범위는 주간 성과 표 12개를 이어 붙인 범위입니다.」
- 수식에 없는 동작을 지어내지 않는다. `IF(VLOOKUP(..)<>0, VLOOKUP(..), "")` 형식만 「가져온 값이 0이면 빈 셀로 둡니다」로 쓴다. 조건이 다른 IF 는 이 문장을 쓰지 않는다.
- VLOOKUP 은 4번째 인자가 `FALSE` 나 `0` 일 때만 「같은 값을 찾는다」로 쓴다.
- 순위는 방향을 수식에서 읽는다. `RANK(..., 1)` 은 작은 값부터 1위다. `IFERROR` 로 감싸면 「순위를 매길 수 없으면 빈 셀로 둡니다」를, `+MAX(..)` 가 붙으면 「아래 묶음의 가장 큰 순위 다음 번호부터 이어서 매깁니다」를 덧붙인다.
- 역할(찾아 채우기, 계산, 기준 비교, 순위, 옮기기)은 수식을 부분 문자열로 읽지 않고 함수와 연산자 단위로 정한다. 시트 이름 속 「-」는 계산으로 보지 않는다.
- 기준값(threshold)의 이유는 설명하거나 유추하지 않는다.
- 문장으로 풀지 못한 수식은 「「<열>」 셀은 수식으로 계산됩니다」로 적고 수식 원문을 「자세히 보기」에 둔다.

## 화면이 보이는 것

| 화면 구성 | 뜻 |
|---|---|
| 왼쪽 단계 목록 | 값이 만들어지는 순서다. 번호를 누르면 그 단계로 간다. 맨 끝에 「출처 확인」 단계가 있다 |
| 오른쪽 엑셀 캡처 | 단계가 가리키는 칸이 든 덩어리(엑셀 표 또는 빈 행 · 열로 나뉜 범위)를 왼쪽 위부터 보인다. 먼 행 · 열은 〰 로 줄여 잇는다 |
| 깜빡이는 칸 | 이 단계가 가리키는 칸 |
| 점선 칸과 점선 화살표 | 이 계산에 쓴 같은 덩어리의 입력 칸 |
| 가는 점선 칸 | 앞 단계에서 본 칸 |
| 점선 글자 단추(칩) | 다른 덩어리에 있는 입력. 누르면 그 값이 나오는 단계로 간다 |
| 출처 확인 단계 | 출처 종류(WINUS · WFS · DB 쿼리 연결 · 외부 연결 · 외부 파일 · 수기 입력)마다 값의 이름을 적는다. 이름을 누르면 그 값이 나오는 단계로 가고, 이름 아래 「예」 값은 이 칸을 계산할 때 쓴 값 하나다 |

| 출처 표시 | 뜻 |
|---|---|
| WINUS | 엑셀 쿼리 · 매크로 연결이 WINUS 에서 가져온 값 |
| WFS(우리펀드 서비스) | 엑셀 쿼리 · 매크로 연결이 우리펀드 서비스 표에서 가져온 값. WINUS 표를 함께 읽어도 WFS 로 표시한다 |
| DB 쿼리 연결 | DB 를 읽는 엑셀 쿼리 · 매크로 연결이지만 WINUS · WFS 인지 판정하지 못한 값. 사내 공용 폴더의 출처 대응표를 읽지 못했을 때(사내망 밖 등)도 이렇게 보인다 |
| 외부 연결 | DB 가 아닌 외부 연결(DDE 링크, 웹 호출, 외부 프로그램 등)에서 가져온 값 |
| 외부 파일(<파일 이름>) | 수식이 다른 엑셀 파일을 참조해 읽어 온 값. 다시 계산하려면 그 파일을 함께 첨부해야 한다 |
| 수기 입력 | 연결 흔적이 없는 값(손으로 넣거나 복사해 붙인 값) |
| 계산 | 엑셀 수식이 만든 값 |
| 피벗 | 엑셀 피벗 테이블이 묶어 만든 값 |
| 표 열 제목 | 엑셀 표의 열 제목 칸. 데이터가 아니라, 수식이 그 글자를 값처럼 읽는 칸 |

범위 참조(`SUM(A1:A10)` 등)는 범위 안 수식 칸 중 가장 많은 칸이 쓰는 수식의 대표 한 칸을 따라가고, 모양이 다른 수식은 가짓수마다 한 칸씩(최대 4가지) 더 따라간다. 단계 설명에 나머지 칸 수를 적는다. 열 맨 위의 날짜 머리나 매개변수 수식은 가장 많은 모양의 대표로 고르지 않는다. 범위가 값 칸 위주이면 칸마다 따라가지 않고 「범위 E21:E30 의 값 칸 8개는 손으로 넣은 값입니다」처럼 단계 하나로 보이며, 캡처에서 그 범위 전체가 칠해진다. 그 값이 쿼리 연결 표의 값이면 대표 한 칸을 따라가 출처를 보인다. 피벗 값 칸은 그 칸이 묶은 원본 행을 따라가고, 여러 행을 묶었으면 대표 한 행과 묶은 행 수를 적는다. 같은 열이 위 행을 이어 받는 긴 사슬(잔액 · 누적 열)은 앞 몇 단계만 보이고 나머지는 한 항목으로 접는다. 같은 열 · 같은 출처의 값이 6개 이상 이어지면 앞 3개만 보이고 나머지를 한 항목(「<열 이름> 값 N개를 <출처>에서 가져옵니다」)으로 접는다. 접힌 항목을 누르면 구간의 처음 칸(점선)과 끝 칸(깜빡임)을 점선 화살표로 잇는다. 연결 문자열은 계정 정보가 있을 수 있어 화면에 넣지 않는다.

## 실패했을 때

| 출력 | 할 일 |
|---|---|
| `엑셀 파일 없음` | 엑셀 경로를 사용자에게 다시 확인한다 |
| `엑셀 열기 오류` | `.xls` 이거나 엑셀이 아닌 파일이다. 엑셀에서 `.xlsx` 로 다시 저장해 달라고 요청한다 |
| `시트 없음` | 시트 이름을 사용자에게 다시 확인한다 |
| `빈 셀` | 셀 주소를 다시 확인한다 |
| `셀 주소 오류` | 셀 주소를 `A1` 형식으로 다시 확인한다 |
| `출력 파일 중복` | `--out` 이름을 바꿔 다시 실행한다 |
| `결과표 파일의 엑셀 이름 다름` | 결과 파일의 `excel` 을 엑셀 파일 이름으로 고친다 |
| `결과표 시트 없음` | 결과 파일의 시트 이름이나 엑셀 표 이름을 엑셀과 대조해 고친다 |
| `인자 오류: --hints 는 셀 모드 전용` | `--all` 에서는 `--hints` 를 빼고 실행한다 |
| `인자 오류: --base` | `--base` 의 군 이름은 후보 파일 `date_groups[].pattern`, 시트는 그 군의 시트 이름으로 다시 적는다 |
| `결과표 엑셀 표 없음` | 결과 파일의 `excel_table` 을 후보 파일의 `tables[].excel_table` 과 대조해 고친다 |
| `결과표 시트가 기준 시트가 아닌 날짜 시트` | 그 시트를 기준 시트로 `--base` 에 넣어 1번째 실행부터 다시 한다 |
| `기준 시트가 후보 파일과 다름` | 결과 파일의 `base_sheets` 를 후보 파일 값으로 고치거나, 바꾼 기준 시트로 1번째 실행부터 다시 한다 |
| `계산 규칙 없음` | 수식이 든 칸이 없는 엑셀이다. 다른 엑셀인지 사용자에게 확인한다 |
| `인자 누락: 시트와 셀 필요` | `--all` 이 아니면 시트와 셀 주소를 함께 준다 |
