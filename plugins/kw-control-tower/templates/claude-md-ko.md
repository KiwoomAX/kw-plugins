사용자는 금융업 종사자이다. 보고서와 제안서를 읽고 쓰는 일이 많아 근거·검증·절차·편향·표준·기준선 같은 말에 익숙하다.

금융투자협회 홈페이지(`kofia.or.kr` 와 그 아래 주소 전체)에는 접속하지 않는다. 클로드가 직접 접속하는 일, 반복 접속 코드를 써서 사용자가 실행하게 하는 일, 그런 코드를 파일로 써서 클로드가 직접 실행하는 일이 모두 해당한다. 접속이 반복되면 사내 접속이 차단되어 임직원의 실제 업무에 지장이 생긴다. 필요한 자료는 홈페이지에서 직접 내려받거나 사내에 이미 있는 데이터 경로가 있는지 사용자에게 확인한다.

git 의 `user.name`·`user.email` 이 비어 있어도 대화 맥락에 있는 이름이나 메일로 채우지 않는다. 클로드 계정이 사용자 본인의 것이 아닐 수 있다. 채울 값은 사용자에게 확인받는다.

사내 웹 화면(본부 · 팀 대시보드와 사내 웹 기능)을 만들 때는 화면 초안을 그리기 전에 kw-design:designing-kiwoom-frontend 스킬을 읽고 그 디자인을 기본값으로 쓴다. 사용자가 다른 디자인을 원하면 따른다. brainstorming 에서 설계 승인 전이어도 이 스킬은 읽어도 된다. 화면 코드를 쓰기 전에 그 스킬이 안내하는 방법으로 목업을 만들어 사용자에게 먼저 보인다.

회사 기능·앱·화면·스크립트 코드를 새로 만들거나 고치는 작업에는 kw-github 플러그인의 스킬을 쓴다. 새 작업은 코드를 쓰기 전에 `kw-github:starting-feature-repo` 로 작업 폴더를 준비하고, 기능 단위가 끝나면 `kw-github:saving-work` 로 commit 한다. GitHub 업로드는 사용자가 승인한 것만 한다.

이미 다른 코드 저장소(플러그인·대시보드 등)에서 작업 중이면 작업 폴더를 새로 준비하지 않는다. 다만 여러 개발자가 함께 쓰는 대시보드에서 새 기능을 시작하면 `kw-github:saving-work` 의 안내대로 개발자에게 먼저 묻는다.
