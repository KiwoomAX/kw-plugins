# 데이터 보안 점검표

저장 검사는 파일 이름과 정규식으로만 판정하므로, 형태를 모르는 키나 md 안에 든 데이터를 놓친다. 이 점검표는 Claude 가 코드를 읽고 그런 것을 찾는 기준이다. 해당하는 것을 찾으면 파일 경로와 줄과 항목 이름을 적는다.

| 항목 | 찾는 것 |
|---|---|
| 비밀값 | 형태와 상관없이 코드에 직접 적힌 키, 토큰, 비밀번호, 비밀번호가 든 접속 문자열 |
| 업무 데이터 | 코드, md, txt, JSON 에 직접 적힌 고객·펀드·거래 데이터와 ipynb 출력 셀에 남은 데이터 |
| 개인정보 | 실명, 계좌번호, 주민등록번호, 연락처 |
| 브라우저 노출 | 화면 코드가 키나 토큰을 브라우저로 보내거나, 다른 서버의 키가 필요한 호출을 브라우저에서 하는 코드 |
| 로그 노출 | 비밀값이나 개인정보를 로그나 화면 오류 메시지에 출력하는 코드 |
| 배포할 수 없는 코드 | 오피스 프로그램을 조작하는 코드(`win32com`, `Dispatch`, `xlwings`, Outlook 호출, 매크로 실행)와 메일을 직접 보내는 코드(`smtplib`, 메일 API 호출) |

예시로 쓴 가짜 값(`example`, `xxxx`, `<토큰>`)과 `.env.example` 의 빈 칸은 해당하지 않는다. 배포할 수 없는 코드는 `feature_code_rules.md` 의 「오피스 프로그램」 절과 「메일」 절에 적힌 방식으로 고친다.
