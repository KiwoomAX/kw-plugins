# 기능 코드 규칙

이 기능은 나중에 회사 대시보드에 붙을 수 있다. 붙일 때 코드를 최대한 덜 고치도록 아래 최소 구조를 지킨다. 폴더 구조는 자유롭게 둔다. 대시보드에 붙인 뒤에는 대시보드 쪽 코드를 고치고, 이 레포는 지운다.

## 진입점

폴더 구조는 자유롭게 두되, 최상위의 두 폴더와 두 파일만은 고정한다. 대시보드는 이 두 파일만 보고 기능을 붙인다.

- 화면은 `frontend/` 아래에 두고, `frontend/index.tsx` 가 기능 화면 컴포넌트를 `export default` 로 내보낸다.
- 서버 로직은 `backend/` 아래에 두고, `backend/router.py` 가 FastAPI `APIRouter` 를 `router` 라는 이름으로 내보낸다. 라우터 안의 주소는 상대 경로로 쓴다. 대시보드가 이 라우터를 `/api/<레포 이름>` 아래에 붙인다.
- 화면이 없는 기능은 `frontend/` 를 두지 않는다.

## 기술 구성

- 화면은 React 18 과 TypeScript 컴포넌트로 만들고 export 한다. 대시보드는 이 컴포넌트를 자기 페이지 안에 넣는다.
- 서버 로직은 파이썬 FastAPI 의 `APIRouter` 로 만든다. 화면이 없는 기능도 실행 입구를 라우터로 둔다. 대시보드는 이 라우터를 `/api/<레포 이름>` 아래에 등록한다. 화면 코드는 API 를 `/api/<레포 이름>/...` 상대 주소로 부른다.
- 스타일은 Tailwind 클래스로 준다. 전역 CSS 에 `h1`·`table`·`body` 같은 태그 이름 규칙을 쓰지 않는다. `.shell`, `.rail`, `.topbar`, `.side`, `.nav-item`, `.content` 클래스를 정의하지 않는다. 대시보드의 사이드바와 상태바 모양까지 바뀌기 때문이다.
- 크기는 부모 영역을 기준으로 준다(`w-full`, `h-full`, 비율). `w-screen`, `h-screen`, `100vw`, `100vh` 와 `position: fixed` 를 쓰지 않는다. 대시보드에서는 사이드바(펼침 264px, 접힘 64px), 알림 서랍(열림 340px), 상태바(높이 68px)를 뺀 공간에 그려지고, 그 너비는 사용 중에도 바뀐다.

## PC에서 띄워 확인하기

- 파이썬 환경은 기능 레포 안에 `python -m venv .venv` 로 만든다. 의존성은 `requirements.txt` 에 `==` 로 버전을 고정해 적고 `.venv\Scripts\pip install -r requirements.txt` 로 설치한다. 전역 파이썬에 패키지를 설치하지 않는다.
- 백엔드는 `.venv\Scripts\uvicorn <모듈>:app --host 127.0.0.1 --port 8000 --reload` 로 PC 안에만 띄운다. 라우터를 등록하는 작은 FastAPI 앱 파일을 기능 레포에 함께 둔다. 이 파일은 대시보드에 붙일 때 쓰지 않는다.
- 화면은 Vite 개발 서버를 `--host 0.0.0.0` 으로 띄워 다른 PC 에서도 IP 로 접속할 수 있게 한다. Vite 설정의 `server.proxy` 로 `/api` 요청을 `http://127.0.0.1:8000` 에 넘긴다. 포트가 이미 쓰이고 있으면 비어 있는 포트를 쓴다.
- 띄운 뒤 개발자에게 `http://<이 PC의 IP>:<Vite 포트>` 주소를 알린다. 처음 띄울 때 Windows 방화벽 허용 창이 나오면 허용하라고 안내한다. 회사 정책으로 막혀 있으면 PC 안에서만 확인하고 AX팀에 문의하라고 알린다.
- 띄운 화면은 사내망에 인증 없이 열린다. 확인이 끝나면 서버를 끄라고 알린다.

## 오피스 프로그램

이 폴더의 기능은 AX팀이 공용 서버에 배포한다. 그래서 오피스 프로그램을 사람처럼 조작하는 코드(COM 호출, 화면 조작, 매크로 실행)를 쓰지 않는다. 공용 서버에서 이런 코드를 실행하면 보안 문제가 생긴다.

오피스 작업은 반드시 아래 방식의 파이썬 코드로 바꾼 뒤에 올린다.

- 엑셀 작업은 openpyxl 같은 라이브러리로 파일을 직접 읽고 쓰는 코드로 바꾼다. 엑셀 수식이 하던 계산도 파이썬 코드로 옮긴다.
- 매크로나 엑셀 쿼리가 DB 에서 데이터를 가져오던 작업은 그 쿼리나 엑셀 파일 자체를 AX팀에 보내 쿼리 등록을 요청한다. 승인을 받으면 등록된 쿼리를 DBGateway 로 호출하는 코드로 바꾼다.

## 메일

이 폴더의 코드는 메일을 직접 보내지 않는다. 공용 서버에서 메일을 보내면 보안 문제가 생기고, 누가 무엇을 보냈는지 기록이 제대로 남지 않기 때문이다.

메일로 보낼 내용은 DBGateway 샌드박스 테이블에 저장하는 데까지만 한다(`kw-devops:managing-sandbox`). 그 테이블을 읽어 Outlook 으로 보내는 자동화는 발송자 본인 PC 에 두고, 이 폴더에는 두지 않는다. 그러면 메일이 발송자 계정에서 나가고, 보낸편지함과 테이블에 발송 기록이 남는다.

## 규칙 밖의 방식

개발자가 Streamlit 이나 다른 화면 도구처럼 위 규칙 밖의 방식을 원하면 그 방식으로 만들지 않는다. 개발자에게 이렇게 알린다. "이 방식으로 만들면 대시보드에 붙일 때 작업이 복잡해집니다. 꼭 필요하면 AX팀에 문의해 주세요."
